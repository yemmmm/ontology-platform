# 模型访问与额度管理：业务说明 v2

本系统是为 OntoWeave 建模测试构造的可运行业务，不代表任何开源网关的真实规则。

## 切片一：模型目录与可用性

管理员登记模型标识、显示名称及启用状态。模型标识唯一，登记后不变。
每个模型还有新成功调用的扣额单位 `quota_cost`，必须是正整数，默认 1。
管理员可单独修改扣额单位，包括模型停用期间；修改不改变模型启用状态、授权或凭证余额。
修改仅影响之后的新调用，历史成功记录保留调用时的实际扣额单位，不重新计价。
启用表示平台允许接受该模型的新调用，不代表任何调用方自动获得访问权。
停用保留模型、历史授权和调用记录；重新启用后，原授权仍在。

## 切片二：调用凭证、模型访问与次数额度

调用方使用系统签发的测试凭证。每个凭证有独立的名称、启用状态、允许访问的模型集合和剩余次数额度。
多个凭证的额度独立；同一凭证访问多个模型时共享自己的额度。
授权的模型必须已经登记，可以在模型停用期间签发授权。拥有授权不代表模型现在可调用。
首次创建凭证时必须给出非空模型集合及非负整数额度，可以创建零额度凭证。
凭证原文只在签发时返回，管理查询显示凭证身份和状态。

## 调用与拒绝

调用提交模型标识、请求标识与提示文本，使用 Bearer 测试凭证认证。提示文本按提交内容保留，空格也是内容的一部分。按以下顺序处理：

1. 请求格式有效，凭证存在且启用，否则拒绝。
2. 若该凭证已经成功处理过同一请求标识：相同模型和提示文本返回原结果，本次扣额为零；不同内容返回冲突。该回放仍要求凭证启用，不重新检查模型当前状态或剩余额度。
3. 对新请求，检查模型存在、属于该凭证允许访问的模型集合且已启用。
4. 剩余额度至少达到该模型当前扣额单位时，执行本地确定性调用、扣除相应单位并写入一条成功调用记录；否则拒绝（即使余额大于零）。成功响应和记录的 `charged_units` 为这次实际扣额。

本地调用返回“模型标识: 提示文本”。它不调用外部模型，不衡量生成质量。
拒绝不扣额度，也不产生成功调用记录。一次新成功调用、一次扣额和一条记录原子完成。
并行请求不能使额度为负，也不能让同一凭证、同一请求标识重复扣额。
请求标识的去重范围是单个凭证；两个凭证使用相同请求标识各自处理。
同一凭证跨模型共享余额，不同模型可以有不同扣额单位。例如余额 4，先调用扣 3 的模型后余 1，
再调用默认扣 1 的模型后余 0；余额 2 不能调用扣 3 的模型。
历史相同请求回放不按当前扣额单位重新收费；回放响应的 `charged_units` 为本次扣额 0，
`remaining_quota` 为凭证当前余额，成功记录的历史 `charged_units` 不改写。

停用模型不抹除历史成功记录；已成功的相同请求可以回放，但新的请求被拒绝。
停用凭证后，该凭证的新调用和历史回放均被拒绝；重新启用不补充额度。
服务重启后，模型、授权、剩余额度和成功记录继续保留。
旧版 SQLite 启动升级时，已有模型补上扣额单位 1，原模型身份、授权、余额和调用记录保留。

## 边界

额度是本系统的整数调用单位，不再等同于可调用次数；不是 token 数量、人民币余额或上游模型费用。
当前没有充值、退款、自动重置或过期规则。
用户组织、付费订阅、上游渠道、真实供应商故障和计费均不在本版本范围。
本机管理 API 对试验操作者开放；调用凭证的模型权限不等于管理 API 的权限，也不等于 OntoWeave 的语义读取权限。
业务行保存在 SQLite。建模应表达概念、关系、条件和映射，不能用复制这些业务行代替语义模型。
