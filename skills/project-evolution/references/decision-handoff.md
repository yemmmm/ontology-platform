# 决策输入与上下文交接

在初次接续、组织事件输入、委派详细工作或切换主上下文时读取。复用既有事件、状态和
记录；以下是输入／返回的组织方式，不要求新增数据库、固定 JSON schema 或监控平台。

## 信息先筛选，再进入模型

程序观察实际状态，把原件写入现有记录，只有需要推理的变化才产生主 Agent 输入。
不先将原始 status／board／完整日志送给模型再压缩，不通过定时“仍在运行”对话维持
监督。实际环境缺少事件等待或再唤醒能力时如实说明；有界观察能力不等于无人值守。

同一对象／事件的重复可归并次数和最新状态，未决问题仍保留。影响扩大、严重性变化、
已约定期限到达或状态反转须重新呈现；不能只凭相同错误字符串合并不同对象。用户
输入、授权变化、未知写入、监控失效和未预期的重要异常不能被过滤。无变化不唤醒
不等于停止程序观察，也不免除必要的存活检查。

消息已发送、已投递、已读取、已消费、依赖满足和业务完成分开；不能用事件归并
或摘要生成作为确认。busy 时按当前合同在完整原生回合结束后处理，不按工具结束
随意打断。普通机械动作可连续执行，异常与授权变化沿原通道处理。

## 决策包

按本次判断裁剪以下字段，提供当前投影，不反复附上全部历史快照：

```text
阶段及截止点：阶段身份、状态时点、代码／提示／模型修订。
目标与边界：本阶段条件、仍有效的用户约束、授权／预算引用及状态。
本次变化：发生对象、实际结果、首阻塞、影响范围；区分事实和原因假设。
当前未决：下一依赖、待答请求、在途操作、未知写入、尚未验证的部分。
待决定：需要主 Agent 选择的动作、候选方案及已有依据。
证据：可按权限读取的原件位置与范围、是否完整、必要的补读入口。
```

不能只返回“成功”或文件哈希。比如决定恢复时，应知道原失败复测结果、修复是否进入
实际进程、是否有未知副作用和未满足条件。原件引用提供定位，必要变化正文支持当前
判断；缺少决定性证据时补读相关范围，不能推断为 PASS。

投影由已有真实字段生成，语义解释与根因由获准 Agent 提供并标明依据。安全关键
约束、业务未知和不完整性优先于长度目标；必要时按当前依赖分页，不静默截断。
输入量可以随真正的未决事项增加，但不应随无关历史事件数量持续增加。

## 专项任务交接与返回

需要独立工作上下文时，交接目标、已知事实、原失败证据、当前版本、允许修改的文件／
资源、完成条件与返回位置。执行者不是独占工作区，不得回退其他人的修改。生产和
修复任务只提供获准公开资料；不继承宿主全部聊天、隐藏题／答案或私有评分。

执行者将详细调查、日志和大段差分保存在现有任务记录，向主 Agent 返回：

```text
结果：完成、需修订、待外部条件或未验证，并注明范围。
原因与把握：具体证据、已排除解释、仍未知的部分。
变更：实际提交／文件／资源及版本，是否进入运行进程。
验证：执行了什么、实际结果、对应原失败是否解除、尚未覆盖什么。
下一步：可继续动作、依赖或需要裁决的取舍。
证据与消耗：原件引用、适用版本、已有时间／token；缺失写 unknown。
```

主 Agent 依据相关差分与原件核对，不盲信摘要，也不重复每一步排查。创建诊断任务
不代表已解决；工程通过不替代实际采用或独立语义验收。最终验收者不能参与生产／
修复；其私有题和答案不得通过返回摘要进入生产。

模型或来源变化后，由独立侧沿原标准核对影响并绑定当前目标，选择受影响范围复验。
未变化结果只有在原合同允许且版本／适用性仍有证据时才能复用；影响无法界定就补充
取证或保留 `PARTIAL`，不自动沿用旧 PASS，也不默认每次重跑全部题目。明确已不符合
才记 `REVISE`。额度可用不等于新增调用已授权；先核对本阶段是否已包含该项复验，
已包含就直接执行，仅在实际超出授权时提出具体决定，不能重复请求已有许可。

## 更换主上下文

只发送增量仍会累积。一个问题已形成决定或到达清晰阶段边界时，保存以下短交接：

- 原阶段目标／授权及其真实来源，预算、用户暂停和有效期。
- 当前代码、输入、模型／验收身份；尚未完成的条件与未解决问题。
- 仍有效决定及理由、已排除的方案和证据位置，避免重复走旧失败。
- 实际执行者、run／进程／工作身份、在途操作与未知副作用；不得重新派发。
- 下一动作、等待条件、谁负责观察及实际接手方式，关键证据的精确引用。

新上下文先从原记录核对当前事实与版本，再按需读取历史。交接摘要只作导航，不覆盖
平台实际状态、原预算或独立报告。原执行未完成或回执不明时接回原执行／沿原身份
对账，不能在交接中标成未开始。切换宿主上下文不改变生产 run、额度或验收资格。

切换必须有实际可用的上下文接续机制或接手者，不以结束对话冒充交接。没有接手且
仍有授权内待办时继续当前工作；确需外部决定时留下具体请求和恢复点。不要为了限制
上下文按固定次数永久关闭任务，也不为每个普通事件都创建新线程。平台压缩作为
补充；交接、重新加载和补读同样计入成本。

对照 [R4.3-030](../../../docs/requirements/requirements-v4.3.md#r4-3-030) 验证效果：
无变化不重复调用、关键事件不丢失、换上下文不重复写入、质量保持；统计输入／唤醒／
补读与其他角色成本转移，外部 Host 按既有规则单列。摘要字数或缓存率不等于净收益。
