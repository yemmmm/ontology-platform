# 阶段约定

仅在建立新阶段或需要补齐关键决定时读取。阶段约定是用户目标和已有授权的索引，
不是新的预算账本、运行状态库或必须全部填满的审批表。

优先使用用户指定的阶段文件、现有运行记录或权威需求中的对应段落。首次需要文件时，
可在既有 gitignored 运行目录保存一份 `stage.md`；不为每个恢复／新线程复制一份。
来源、冻结验收和预算保持各自原件，通过稳定引用关联。先补安全开始所必需的信息，
无需等所有未来阶段设计完成；示例中的字段不构成新授权。

## 可裁剪模板

```markdown
# 阶段：填写稳定阶段身份与业务目标

- 目标：写用户可观察的结果。
- 权威依据：需求版本／条目、用户决定、来源版本与范围引用。
- 当前范围：实际业务、代码／配置、Project／Ontology、任务／run；明确未决项。
- 完成条件：本阶段 L0／L1／L2／L3，必需结果与独立证据、冻结标准引用。
- 自主操作：已授权的建模／修模、技术修复、测试、部署及资源操作范围。
- 保留决定：业务含义／范围、重大兼容性、验收含义、预算、权限和控制边界。
- 资源授权：真实指令依据、模式、稳定 budget_ref 或计次记录、获准模型配置。
- 有效期与停止约定：依真实授权填写；未指定则注明未指定，不擅自声称不限期。
- 责任与入口：当前宿主／执行者、运行目录、状态／控制入口、实际等待或再唤醒方式。
- 证据与进度：引用唯一运行记录、相关需求／优化项与当前版本；不复制完整历史。
```

## 使用边界

- 已有明确阶段执行授权就继续，不能把生成模板变成再次请求批准的理由。用户仅要求
  评估、编写技能或设计时，只完成该范围，不启动真实建模或收费试验。
- 目标表达为结果，不能使用“持续优化到最好”、Agent 忙碌率、资源数量或测试总数
  代替完成条件。完整范围、真实质量和必要独立验收不可被效率总分抵消。
- 模型、额度和期限采用当次指令与适用仓库默认；只有真实授权允许时才采用不限额
  模式。金额模式不套默认三轮；跨 run 不清零，也不为每次重启自动创建新 3 元预算。
  同一任务计次／semantic-start 和金额规则沿原入口，不在本模板再实现一套。
- 缺少影响费用或写入的授权时，提出具体需要决定的范围，同时完成安全分析和方案；
  不把未知授权填成许可，也不对用户已授权的动作重复请示。
- 跨多个任务的阶段总额及子任务额度分配须有明确授权；简单试点优先维持一个业务
  任务与原预算。正常自然回合可能有在途尾差，保留原计量，不承诺逐请求精确截断。
- 约定停滞检查时区分缺口减少、失败消失、覆盖增加、关键解释被排除与纯日志／提交
  增长。未指定次数阈值时不编造硬上限；发现无新证据的重复才做有界原因复核。
  已约定的复现／随机性对照按计划执行，不把“同条件”本身当作禁止验证的理由。
- 目标或授权变更记录真实主体、来源和适用范围，保留旧版本。通常只是技术实现
  选择时记录理由即可；不能借更新阶段文件静默改变主验收标准。
- 本阶段达标即停止。示例 Demo、建议后续阶段和剩余预算均不构成继续执行的授权。
