# 阶段自主演进

让技术宿主围绕固定结果连续推进，用户只处理必要的业务和授权决定。主 Agent 按关键事件
决策，程序承担观察与等待。任务状态和证据保存在外部，避免长期聊天承载全部运行历史。
本技能不挂载给生产建模角色，不代替业务建模或独立验收，也不自行启动后台程序。

## 绑定阶段与执行责任

1. 确认仓库根目录，按当前 `AGENTS.md` 定位本阶段所属需求；只读相关条目和实际状态。
   复用已确认目标、决定、验收标准和原运行记录，不重新解释范围或前置全面审计。
2. 将阶段目标、完成条件、允许修改／写入范围、授权与预算引用、有效期／停止约定、
   原 run 和下一责任方绑定到一份现有记录。首次建立或有关键缺项时才读
   [阶段约定](references/stage-contract.md)，不重复制作已有文档。
3. 沿当次真实授权执行；常规可逆选择自行决定，不重复请示。创建／安装技能本身不授权
   建模启动、预算追加或恢复暂停任务。只询问会实质改变业务含义、范围、兼容性或授权
   的缺失决定，继续不依赖该决定的工作；不得自行填写授权金额、期限或试验阈值。
4. 绑定唯一运行控制责任方。新建模沿 `scripts/modeling`，旧 run 保留原合同；准备、
   计量和安全接续复用下列入口。真实建模已获准时遵守仓库首次 semantic start 时限。

| 当前工作 | 按需加载的入口 |
| --- | --- |
| 启动、监督、暂停／接续、组织独立验收 | [modeling-dev-loop](../modeling-dev-loop/SKILL.md)，当前 v5 操作读其 [runbook](../modeling-dev-loop/references/v5-runbook.md) |
| 旧优化效果核对、真实失败归因与改进建议 | [modeling-retrospective](../modeling-retrospective/SKILL.md)，仅核对本阶段关联项 |
| 工程修改与验证 | 宿主可用的 `requirement-delivery`；沿仓库交付规则选择相应范围，不自动增加正式审批流程 |

按实际需要选择入口，不每轮整包读取所有技能与 references，不建立第二条建模监督链。

## 只接收当前决定需要的信息

主上下文保留：**阶段目标及约束、当前相关状态、本次变化、未决决定、证据引用与限制**。
首次接续、组装决策输入或交接专项任务时，按需读
[决策与交接](references/decision-handoff.md)。完整日志、源码、测试输出及调查过程留在外部。

- 程序在调用模型前筛选状态变化。普通心跳、日志增长、同状态进度不触发主 Agent；
  已授权且参数确定的机械动作沿现有程序执行，遇到新判断再交回。
- 新阻塞、影响范围变化、工作／验证结果、依赖满足、用户输入、授权／预算变化、未知
  写入、监控失效及实际约定的期限事件进入相关决策。不能只关注预先列出的等待对象。
- 当前 `status`／`board` 可能包含历史集合；程序读取后形成有界投影，不能原样反复注入。
  摘要保留必要变化正文、适用版本、不完整性和补读入口；关键未知不能因长度目标被删。
- 专项诊断或工程工作确需隔离上下文时委派有界任务，明确目标、材料、权限、文件／资源
  归属和完成条件；告知执行者保留其他人的修改。只返回结论、依据、验证、未解决项和
  下一步，完整过程存原件。不为汇总普通心跳增加常驻监控 LLM。

## 围绕实际缺口推进

1. 从当前结果选择影响本阶段目标的真实缺口，关联已有问题／优化项。新发现不相关能力
   进入待办；不能因为 Agent 空闲或余额充足扩大产品范围。
2. 保留原失败，核对来源、请求／回执与实际采用版本，定位首层：`modeling-quality`、
   `platform-contract`、`collaboration/routing`、`runtime/infrastructure`。证据不足保持
   未定位；工程失败不能推导模型质量差。已有有效结果复用，不重复调查已排除原因。
3. 记录简短的“证据 → 原因假设 → 最小改变 → 预期实际结果 → 验证方式”。模型问题交原
   建模责任方，提示歧义修权威提示，代码偏差修对应实现。守卫阻断先做 `AGENTS.md` T0
   复核；不因不通过就删除保护，也不顺带增加治理或编排机制。
4. 在授权范围内实施、按影响验证并核对实际进程采用。工程修改保留其他工作树改动，
   按仓库规则测试、必要重启及提交；共享运行只有一个明确部署责任方。能安全接续就
   继续原 run；未知写入先按原操作身份对账，不能换 run 重放或以 Git 回退代替数据恢复。
5. 复测原失败和受影响结果，按本阶段标准组织独立验证，记录质量、时间和完整成本。
   将结果关联原需求与运行记录；无新证据不重复同条件昂贵试验。prompt-contract 缺陷
   在下一 semantic start 前持久修正，临时指导不能冒称默认路径已可靠。

执行方不得自行放宽阶段目标、主验收标准、业务范围、预算／权限或本技能中的控制边界。
技术澄清和授权内实现选择无需逐次批准；需要改变保留决定时先完成具体方案与影响分析。
阶段内已授权的常规修复无需再要求用户逐条确认；优化台账只登记符合其确认规则的条目。

独立验收者不得生产、继续或修复被验收 run；修复方只获得获准公开反馈，不读隐藏题／答案。
验收依据实际应用和受治理读取，生产自查、开发测试、过程分数、报告格式正确均不能替代。
发现裁判实现缺陷时保留原报告，在同标准下核对已确认正反例；改变标准须另作决定。
分别记录 `L0`／`L1`／`L2`／`L3`，不将后阶段变成当前阶段的新完成门。

## 短上下文接续与结束

完成一个问题或到达清晰阶段边界时保存当前决定、理由、待办与精确证据，必要时用新上下文
接续。新上下文先核对真实目标／授权、版本、未决请求与在途操作；不仅相信生成摘要。
切换主上下文不重启生产、不清零预算、不重复派发、不继承不适用的 PASS。详细接续合同
沿[决策与交接](references/decision-handoff.md)，不为每个小事件强制换线程。

| 当前情况 | 行动 |
| --- | --- |
| 授权内有安全下一步 | 继续；普通可恢复错误不要求用户再次说“继续” |
| 局部输入／外部依赖未决 | 等待该部分，推进不依赖它的工作；保留原请求与恢复责任 |
| 预算关闭、到期或用户暂停／取消 | 停止受影响的新动作，沿自然回合停稳及对账；不自行续额，用户停止优先 |
| 未知写入 | 先查原操作实际结果，只阻断受影响的写入和依赖 |
| 重复无改善且无新因果证据 | 有界复核原因；无可验证的安全下一步时报告阻塞，不用固定尝试数永久关闭 run |
| 阶段全部条件有适用证据 | 收口停止；下一阶段只有已明确获准时才继续 |

使用实际可用的等待、观察与再唤醒入口。没有后台执行者时，明确当前只能由活跃宿主
推进；不能声称安装技能后已在后台运行。结束宿主回合前必须达标、有明确暂停／终止或
不可独立解除的阻塞，或已有实际承接的执行者；不能借切换上下文留下无人推进的任务。

用户简报只讲实际成果、剩余缺口、下一步、耗时／用量和是否需要决定。无须用户操作时
明确说明；确需决定时给推荐方案、业务影响与代价，不只转发堆栈。结束时报告对应范围
的结论、证据、提交与资源状态，打印墙钟和已知 token，缺测写 unknown；失败与恢复计入
原任务，研发／复盘和外部 Host 单列，Host 不计任务金额或预算。不以主上下文变短冒称
全任务净降耗。本阶段证据不齐记 `PARTIAL`，明确不符合记 `REVISE`，存在不可独立解除
的阻塞才记 `BLOCKED`；只有约定条件全部满足才报告对应范围完成。
