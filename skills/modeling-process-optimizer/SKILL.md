# 建模流程优化

目标是在保持源忠实、业务覆盖和独立验收标准的前提下，缩短获得合格模型的总时间。
质量是约束，时间是优化目标；值得增加的澄清、建模或验证工作，应说明它能解决的质量缺口
及可能减少的返工。不要用一个加权总分让提速抵消质量退步。

这是技术宿主侧的复盘技能，不挂载给生产建模角色。默认读取保留证据、输出建议及验证计划；
用户已要求实施时，在已有授权内更新归属需求、实现或权威提示，并按仓库要求验证。
本技能不另授 semantic start、平台写入或验收权限，不解除已有暂停。
实时推进与安全接续交给 [modeling-dev-loop](../modeling-dev-loop/SKILL.md)，不建立第二条监督链。

## 选择范围与证据

1. 确认仓库根目录，读当前 [AGENTS.md](../../AGENTS.md) 和本次适用的
   [版本化需求](../../docs/requirements/)。当前效率口径入口为 R4.3-001 与 R4.0-021，
   具体时间目标、题目范围、角色和工具以所分析轮次及当前权威合同为准，不硬编码为所有场景规则。
2. 用户指定 run、时段或问题时遵循其范围；否则从最近几轮相关任务开始，包含失败、中止
   和未完成样本。已有证据足以支持决定时停止扩展，不全量扫描历史，也不为了凑样本启动运行。
3. 从摘要定位原始证据，按需使用 [证据导航](references/evidence-map.md)。将同一业务任务的
   fresh starts、恢复、修模与重验串成完整时间线，另列各 run 的状态；不要只取最后成功片段。
4. 记录输入资料、范围、题集及评分版本、模型与 effort、Task/Profile、代码和提示身份；
   区分从零建模、生产恢复与只读验收。不可比样本可以解释失败机制，不能直接计算优化增益。
5. 先复核上次建议和当前交付：未采用、待实现、已实现待实测、有效、无收益或退步、证据不足。
   核对实际 run 加载的版本；文件已更新、开发测试通过都不代表旧进程已生效。
   历史问题已经修复时，优先验证效果；仍有旧现象时查生效或残余原因，不重复立项。

## 同时看质量与时间

| 维度 | 需要回答的问题 |
| --- | --- |
| 模型质量 | 业务定义、条件、计算口径、关系和共享身份是否正确？范围是否完整，未知是否忠实？实际写入与读回是否一致？ |
| 消费质量 | 冻结完整题集实际通过多少？必答点缺在模型、检索还是答案综合？证据及分页是否完整？ |
| 时间 | 从输入就绪且获准开始，到完整独立 PASS 和必要收尾用了多久？首条可消费业务链、返工和等待在哪里？ |
| 辅助计数 | 哪些角色往返、重复读取、dry-run、输入体积或唤醒能解释瓶颈？不要将计数当质量或语义 start 数。 |

复用 [同轮效率记录](../../modeling_team/references/efficiency-round-record.md) 和已有事件。
尚无完整 PASS 时报告已观察时间、真实结果和未完成项，不能称作成功性能基线。
仅有摘要或情境材料中的通过数时，写“报告记载通过，独立资格未核验”；原始报告、冻结
身份与读取证据未核对前，不把该记载称为已证实的独立 PASS。
修模、重验及同一任务的重启不重置总起点；并行区间按墙钟并集，累计 Agent 时间另列。
正常推理、读取、调度、输入纠错、质量返工及人工等待保留在总时间内。
有证据阻断关键路径的故障可另报去重后的扣除估算，不能冒充无故障实测。

跨度、进程存活时间和意图到回执间隔均不等于有效语义工时、数据库 CPU 或单次 HTTP 时间。
未被分类的余时不能全部视为可删除；并行等待减少也不必然等额缩短总时间。
缺失数据写 unknown，估算注明依据，不补造 token、费用或精确节省时间。
有效语义时间比例仅在分子、分母及活动证据充分时计算，按 AGENTS.md 处理；不以分类不明
为由新建监控平台或强制逐工具打点，也不让本复盘成为每轮启动的前置门。

## 从现象定位最窄原因

每项发现形成：**现象 → 原始证据 → 对时间或质量的影响 → 原因及把握 → 最小改动**。
明确区分观察事实、因果推断和待验证假设；出现频率高不等于根因已确定。

- 第一失败层沿用 `modeling-quality`、`platform-contract`、`collaboration/routing`、
  `runtime/infrastructure`。证据不足写尚未定位；同时记录修改对象为实现、prompt-contract
  或流程设计，不增加另一套失败分类。“平台故障”等笼统描述不能区分平台合同与基础设施，
  在缺具体失败证据时保留首层未确定，不为了填写类别猜测。
- 语义消费不足进一步检查：获准材料是否支持该事实、模型是否表达、平台实际返回什么、
  Consumer 是否使用、Judge 依据是否有效。粗粒度失败标签不能独立证明模型缺失。
  已返回但未使用时检查消费表达；尚未返回时区分检索与模型证据，保留未确定项。
- 优先检查重复转录、重复批准、无效唤醒、晚发现缺边、交接停等和可恢复错误。
  也检查过早结束读取、遗漏限定条件、未知丢失等质量问题；需要增加有效语义工作时明确建议。
- 守卫导致阻断时按 AGENTS.md 的 T0 复核必要不变量和上层覆盖，考虑删除或降级重复防御；
  不以跳过授权、dry-run/application、原子性或实际读回来换速度。
- 改动落到当前责任面：实现不符合同则修实现；输入或角色说明有歧义则修权威提示；
  各方遵守合同仍反复停等则调整流程。只改证据指向的环节，不附加通用编排或治理机制。

## 输出和验证优化建议

使用 [报告模板](references/report-template.md) 按任务大小裁剪。默认优先给最有价值的几项，
不要凑满条数。每项包含证据引用、当前状态、原因及把握、最小改动与责任面、时间收益假设、
质量影响、验证方式和退步处置。节省分钟数或百分比须有可核对计算，否则只说明方向与待测项。

优先选择同时改善质量和时间的项，其次是保持质量的提速项；增加时间以补必要质量的项说明
代价。结合影响、证据把握、实现成本和影响范围排序，不追求虚假的精确评分。
允许结论为“保持现状”“先验证已实现改进”或“补一项决定性证据”。

验证先选最小可比较切口：确定性数据搬运看合同及完整性，提示与协作看实际生效及行为，
语义质量看获准的独立消费和裁决。前后保持范围、评分及关键配置可比；同时改变多个因素时
披露混杂，必要时分项验证，不自动扩大为全面基准或强制多轮 A/B。
局部工程通过、真实语义效果、端到端达标和重复性分别结论；单次改善只支持本次范围。
不缩小分母、不删难题、不改变未知口径、不降低评分来达标，不拼接不同尝试的通过题。

沿既有台账保留建议身份、采用版本、验证证据及有效／退步／待证状态。下一次复盘先核对
这些项目；质量退步时提出撤回或修正受影响改动，已写入模型按现有恢复合同处置，不盲目回滚。
获准实施时将通用纠正落到真正被加载的权威提示或实现，不能只留在复盘报告或临时提醒中。

## 证据与完成边界

运行原件、冻结题池和历史裁决只读保留；报告写入既有宿主工作目录或用户指定位置，
分清可交付通用建议与含隐藏信息的私有分析。默认先读元数据和公开证据，只有定位必要且
在获准范围内才读隐藏材料；不能将隐藏题、答案、评分细节或其变相提示带回生产。
已暴露材料按当前合同标记，不追称严格盲测；复盘者不自任被其生产或修复过的 run 的最终验收者。

当关键瓶颈、证据限制、建议顺序及验证计划已明确时完成本次复盘，不为填满报表继续取数。
资料缺口只阻止依赖它的判断，先交付已有证据支持的结论。无授权的真实验证列为待证，
按现有授权继续可做工作，不把“提出优化建议”自动扩大为启动建模。
