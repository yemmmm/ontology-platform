## 真实发现：治理读取身份误用于原生关系端点

初始版本 revision 3 的三条关系都有正确语义定义文字，但实际 source／target 是 `.../class/http%3A%2F%2F...`，并非其引用的已存在 Class IRI。原件为 `v1-stage.json` 的 relation-type-list 响应、原 `apply-00004/intent.json`／compiled.json／回执和 host/verified-reads；独立九题报告未识别端点错误，保留原报告，九题文字语义结论不扩大为结构正确性或完整 L1 通过。

根因沿 `PlatformWorker.read_binding` → `compile_model_changes` → source_class_id／target_class_id → 平台关系编译定位：semantic-read-v2 的 `id` 与 `iri` 均为 RDF IRI，而 Host 将前者填入 resource_id。原测试使用 id=native-42，未覆盖真实投影形状。平台再按原生 Class ID 编码生成 IRI，造成双重编码。错误归属 platform-contract，独立侧另有 prompt-contract 漏查拓扑，不能归咎为源材料或建模业务规则错误。

T0 复核：真实执行身份与引用完整性是必要边界；删除检查或把 IRI 字串当原生 ID 会继续写坏端点。现有应用原子性只保证整批执行，不能证明传入的两种身份相同。最小修复为保留精确获准治理读取，只在缺原生身份时匹配同本体、同资源种类、同 IRI 的既有真实应用回执；没有身份则沿现有编译器返回 binding_identity_missing，允许 Agent 使用实际回执或只需 IRI 的合法更新继续，不增加永久死亡或业务语义门。绝不从 IRI 拆字符串猜原生 ID。

两项真实投影形状用例先失败，随后该模块 13 项通过；同时补独立评价的关系端点实际解析提示，原隔离／来源反馈四个参数用例先失败后修订。完整 v5 回归及真实修后证据另记验证记录。修改只涉及 v5 Host 与评价提示，不改平台服务。

GitNexus 对 read_binding 返回 Target not found／UNKNOWN；直接检索仅有 v5 Host apply 的解析闭包及相应测试调用，既有 applied-bindings 路径不变。未声称图谱影响覆盖，不为此次窄身份修复重建索引。
