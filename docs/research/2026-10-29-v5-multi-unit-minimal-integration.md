# v5 多工作单元最小接入

日期：2026-10-29。基线 `f9a5b78`。用户同意继续验证：一个单元等待 HITL 时另一单元
继续推进，再由父单元整合。归属 [R5.0-001 F3／F9](../requirements/requirements-v5.0.md#r5-0-001)、
[R5.0-003 F1／F4／F5](../requirements/requirements-v5.0.md#r5-0-003)及 P2 的必要子集。

## 最小设计

- 显式任务增加 work_units 和 unit_concurrency；第一版是一个父级及直接子级，不建设
  动态递归规划、任意 DAG、跨机器调度或完整大型业务验收。
- 每个子级沿原 WorkUnitFlow 执行，具有独立业务身份、LangGraph thread、执行目录、
  任务卡和输入目标。共享当前 task 的记忆、通信、授权、模型与材料边界。
- 子级形成候选后停止在 proposal_ready，由程序发布版本化交接材料并发送引用给父级。
  子级不写模型；父级按需读取实际子级材料、原文及匹配的人工答复，承担整体语义判断与
  最终应用／治理自查。程序不合并业务语义或把子级 ready 当成全局正确。
- 各子图独立连接 PostgreSQL checkpointer。程序按完成事件和新输入调度，在仍有其他
  单元忙碌时也能恢复已获答复的单元；不使用整体 LangGraph superstep 等待所有业务。
  单元结束且没有新输入时静止，不重复启动模型。
- 复用 HumanInput 请求身份，问题显示单元归属，CLI reply 按请求自动路由；主动 input
  可指定 --unit-id。父级继承实际人工答复的主体与适用范围，不将子级解释升级为确认。
- 快照扩展保存各子级独立 checkpoint，仍只是组件观察快照；金额沿同一 Host 账本累计。

## 验证与当前边界

工程测试覆盖局部等待、兄弟单元继续、在兄弟回合尚未结束时消费答复、换调度器后
复用候选、父级按引用读取、单次应用和子级 checkpoint 快照。

真实任务采用公开的[多单元材料](../../modeling_team/v5/tests/fixtures/multi-unit-source.md)：
安装名称需要人工输入；核验定义可以独立形成；父级需要表达“只有核验通过安装才可视为完成”。
工程材料及单题公开判据在启动前固定，不作为新的隐藏业务测试。
本轮研发继续使用既有不限消耗授权，1 元只是触发／观察金额路径的工程阈值。

实际暴露两处窄缺口：结构化 HITL 问题已有 reason，却被重复要求 issues；Codex 默认
通用资源工具误导 Agent 反复读取未注册的文件 URI。前者删除重复校验并重解析原回执，
后者只在 v5 上游工具投影中移除未使用资源门面，保留配置的 MCP 工具。
卡住的只读原生执行有一次明确的宿主技术中止，证据保留；不记为自然暂停成功。
