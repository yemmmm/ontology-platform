#### 目标与范围

用户、Delivery 和宿主无需反复翻阅完整对话，即可了解当前谁在做什么、近期准备推进什么、
正在等待谁，以及哪项请求尚待处理。例如 A 正在分析设备业务，依赖 B 校验关系：A 发出一次
请求后，自己的卡片显示“等待 B 校验”，B 的卡片显示“来自 A：期待完成设备关系校验”。
B 反馈缺少资料时，双方同时看到缺口；提供结果后，A 判断原工作是否能继续。
此例只说明协作行为，不引入新的业务事实或角色分工。

首版覆盖当前 run 的工作卡、协作请求、历史版本、与既有消耗统计关联的复盘查询及留存，
提供按权限读取的结构化及人类可读汇总。Delivery 的
已有等待记录、宿主的已有交接待办作为宿主视图的补充来源。图形界面后续接入，不作为
首版完成条件；本条不新增管理页面、任务调度器、自动派单／恢复或语义裁判。

#### 功能要求

- **F1 — Agent 自维护当前工作。** 每个生产 Team Agent 按真实 run／Agent 身份维护自己的
  当前工作、范围、短期待办、必要等待说明及最近成果引用。短期待办允许阶段目标、分析活动
  和具体操作；建议保留少量近期事项，不能把固定条数、操作粒度或填写完整度变成运行硬门。
  领取工作、目标切换、关键成果、阻塞变化和交接时更新；不要求逐工具或定时重填。
- **F2 — 一条协作请求，双方关联展示。** A 在既有获准通信范围内向 B 提出可跟踪请求，记录
  发起者、接收者、简述、受影响工作、是否为实际阻塞及消息引用。同一记录出现在 A 的发出／
  等待区和 B 的收到请求区，保留 A 署名。B 的本人计划仍由 B 维护；请求不自动改变其任务
  优先级、角色职责或授权。多个请求者的独立请求不能互相覆盖。
- **F3 — 请求、反馈与依赖满足分别表达。** 区分消息登记／实际送达、B 的进度／补充资料请求／
  结果／无法处理，以及 A 判断已满足或撤回。无需先接单再反馈，可直接提供结果；
  “已回复”“无法处理”“提供结果”均不能由程序推导为依赖满足。A 可在继续原工作时顺便
  关闭已满足请求，不要求单独确认消息。未关闭请求不自动阻止 Agent 终态或整轮交接。
- **F4 — 消息与展台一次提交。** 沿现有 Team Transport 为需要持续跟踪的消息附加最少机械
  关联；同一次请求／反馈调用完成原消息提交和工作展台登记，返回各自真实结果。普通消息
  继续自由交流，不要求全部转任务。稳定请求／更新身份防止重试生成重复请求或重复消息；
  部分成功、送达不明、对方已终态及记录异常准确可见，可核对、修正或沿原通道继续，不能
  声称登记即送达，也不能因展台异常永久终止 run。
- **F5 — 自述与运行事实并列。** 展示 Agent 最后更新时间、报告内容及可验证的运行活动／
  消息回执，保留各自来源。无卡显示“尚未报告”，旧卡显示报告时间；安静期不推断卡死，
  活跃进程不推断有效进展，自报完成不推断应用成功或独立语义 PASS。只读汇总不刷新原报告
  时间，不编造历史卡片。卡片只是协作摘要，模型成果与业务范围继续引用原产物／场景地图。
- **F6 — 复用原权限与隔离。** 写卡身份由运行端点绑定；A 可追加署名请求，不能冒充 B 修改
  本人计划或反馈。生产 Agent 只读本人与原 Profile 可通信对象的获准卡片、本人参与的请求；
  引用仍按原材料权限读取。Delivery 默认只读流程所需摘要和引用，不获取私有 CQ、隐藏
  Consumer／Judge 正文。独立验收运行与生产展台隔离，既有审核和 Host 私有待办不发布到
  生产共享展台；用户／宿主沿既有获准入口查看。
- **F7 — 有界读取与低维护成本。** 复用 run-local 证据目录、Host 读取及既有 Delivery 输入
  通道。支持按 Agent／请求选择、有界分页及完整性说明，未返回不表示不存在。日常卡片
  变化供查看，不反复注入完整展台或自动唤醒 Delivery；确需动作的阻塞、错误、用户控制
  等沿原请求／升级通道处理。相同卡片不重复记更新，不因读取看板启动模型推理。
- **F8 — 持续记录与验收边界。** 同 run 保留请求和反馈身份及原结果；晚到反馈不覆盖 A 的
  撤回／满足判断，新 run 不自动继承旧请求或重发消息。记录坏页、旧版缺记录与运行结束时
  保持准确限制，不为展台创建新 start 或新增恢复框架。工程、实际采用、维护成本和完整
  业务效果分别判断，不以卡片数量、消息数量或展示字节减少证明效率提升。
- **F9 — 卡片历史与变化查询。** 每次实际更新保存完整本人卡片内容、真实身份、时间及序号，
  当前展示改变不删除旧版本。原读取工具和CLI增加历史／指定版本模式，按run、Agent、
  请求、带时区时间区间及记录序号定位，支持查看前后内容与变化字段；查询保持只读、按原
  权限过滤及有界分页。续页绑定相同来源前缀，新增事件不改变已读历史；缺记录、坏行或
  无法核对前版准确披露，不用当前卡片填补过去。
- **F10 — 与用量统计共同留存及复盘。** 在同一run证据目录保留展台历史与019／036既有
  数值报告，通过Host私有复盘索引关联冻结的历史前缀、统计版本、真实成员身份、各自窗口
  和覆盖。关闭后保留可查询原件；卡片正文不混入只含数值的统计报告或生产共享统计输入。
  复盘入口可并列读取各Agent的历史与token／调用／活动时间／生命周期，不另算一套token
  主账、不把同一成员总量重复放进每次更新后再相加。时间筛选默认只筛选历史，统计仍明确
  显示原报告范围；缺成员绑定或细分usage保持unknown／partial，不能用时间邻近推断每个
  宏观任务的准确消耗。归档／关联失败只影响复盘可用性，不阻塞原关闭、清理或统计发布。

#### 目标、例子与当前基线

用户可以授权“在这个已确认业务目标内，使用指定模型完成建模和独立验收，预算 ¥10”，

失败请求、技术重试、恢复和阶段换线程共享该预算；新建 run 不获得一份新额度。
金额预算只约束资源消耗，不保证模型在预算内完成，也不改变完整业务范围或验收标准。

例如单价单位统一为元／百万 token，缓存输入 100 万、未缓存输入 10 万、输出 1 万，
三项单价分别为 0.2、2、8 时，估算消耗为 `1×0.2 + 0.1×2 + 0.01×8 = ¥0.48`。
这里是用于说明和验收的虚构单价，不代表任何供应商当前价格或实际扣费。

#### 功能要求

- **F1 — 以任务金额授权替代次数额度。** 对实施后明确采用本条的新授权，记录原业务目标、
  获准来源／模型和操作范围、预算金额及币种。预算须为有限非负金额，零额度即耗尽。
  该任务不再以初建、修模轮次或 fresh-start
  数作为第二道资源额度门；这些计数继续保留作运行分析。余额内可按原流程推进同一目标
  的初建、修模和独立验收，不为每轮重复申请次数。金额余额不授权扩大业务、切换未获准
  模型、额外平台开发或新目标；源忠实度、应用完整性、写入对账及独立验收约束保持。
  新增运行、同目标接续和实际成员必须绑定同一任务预算，不能靠换 session／run 清零。
- **F2 — 明确主预算覆盖与缺测成本。** 首版主预算覆盖平台托管且可明确绑定的 Delivery、
  生产 Team／CQ、公开反馈、正式公开／隐藏 Consumer 与 Judge，以及上述角色实际发生
  的失败、重试、修模、压缩、恢复和必要收尾模型调用。接入主预算的辅助模型调用按同样
  规则计费。外层 Host、尚未接通统一计量的检索／排序等辅助调用，单列已知金额或缺测，
  明确未从主预算扣除；不得据托管链小计宣称完整任务总成本受控。首次使用前可见本任务
  覆盖范围，历史期间缺失的数据不得因后续接入而假称完整；本期不以全量 Host／辅助模型
  接线为托管链预算的前置，也不静默把它们当零成本。
- **F3 — 用户可配置三项模型单价。** 按供应商／接入路由与实际模型绑定设置缓存输入、
  未缓存输入和输出单价；统一使用每百万 token 单位，任务内采用单一币种，默认人民币，
  不自动换汇。单价须有限非负，允许显式为零，缺价不能默认为零；首次使用某绑定前，缺价或非法金额
  返回可修正反馈。任务开始消耗前保存所用价表快照，后续全局改价不追改该任务的已用量、
  费用或剩余额度。本期不要求自动查价、税费／折扣／套餐还原或供应商价格验证。
- **F4 — 三类 token 归一化后估价。** 对每次实际调用，按实际 provider／runtime 的字段
  含义区分缓存输入、未缓存输入和输出，计算
  `费用 = (缓存输入×缓存单价 + 未缓存输入×未缓存单价 + 输出×输出单价) / 1,000,000`。
  接口输入若已包含缓存，则未缓存为总输入减缓存；DSH 等互斥桶先统一含义，不能直接把
  原始同名字段当总输入。已知缓存写入按本期近似口径归入未缓存输入，不新增第四项单价；
  已包含在输出中的推理不重复收费，独立且已证未包含的推理归入输出。缓存／推理／压缩
  的子集不得再次加到总额。保留必要小数精度后累计，展示舍入不参与余额判断，不逐请求
  舍入到分后丢掉大量小额调用。估价与实际账单金额可以不同，字段缺失不能伪造为已知。
- **F5 — 程序近实时归集、去重与接续。** 可用 usage 到达后自动增量更新任务金额，不等
  run 结束、关闭报告或 Host 三分钟巡检；无需 Agent 自报数字、额外推理或主动轮询。
  设计采用程序每2秒增量观察，健康无积压时可用数值到达后5秒内发布投影及必要触发；
  具体有界处理、积压和监视失败见设计第4节。状态显示最新已计量截止点；正常在途请求列为在途，
  不声称其费用已结算，也不把正常等待 usage 误判为采集故障。复用019／034的真实身份、
  来源选择和去重：同一请求的流式累计／末次 usage、原生记录、代理记录和累计快照不能
  重复收费；实际再次发起的重试是独立消耗，失败不因未写模型而退款。保存累计进度与
  已处理身份，使宿主重启、恢复、线程／进程切换后继续原账；晚到用量补入原任务，不覆盖
  原调用结果、不将历史重新累计。冲突或不完整记录给出定位与已知小计，不猜任务归属。
- **F6 — 可解释的估算与计量异常。** 总输入、输出已知但缓存量缺失时，允许按全部输入
  未命中保守估价，并标明估算依据，不能伪造真实缓存率。请求已结束而关键 usage 缺失时
  列为待结算，已知项仍保留；有现成可信依据可保守暂估时，标明暂估并在真实用量到达后
  对账替换，不能把暂估与真实值相加。无法形成可信估算或持续无法计量时，预算状态明确
  为计量异常，触发同一暂停请求路径等待核对，不能以缺数为零持续放行。补齐记录／配置后
  可恢复，不因采集缺口永久杀死 run；只读对账、保护已写资源及必要收口不被异常阻断。
  自定义缓存价高于未缓存价时，缺缓存量采用两项输入价中较高者暂估，不把全未命中
  误称保守上界。已结束请求最多10秒usage到达宽限，之后仍无法可信涵盖则异常暂停；
  正常在途无固定10秒截止，明确采集失败／冲突不等待宽限，见设计第3—4节。
- **F7 — 金额与覆盖可见且低开销。** 通过现有获准状态入口和可读汇总展示授权总额、
  已计估算、保守暂估／待结算、剩余估算、超出金额、逐角色／模型分项、在途调用数、
  统计截止点、价表快照及覆盖限制。余额可为负，不能只截断为零隐藏尾差；缺测时注明余额
  不是全部费用结清后的保证值。范围外已知成本与主预算分别展示，不能混成已扣额度。
  费用变化由程序记录；普通每次 token 增长不反复唤醒 Delivery 或注入完整历史，仅预算
  耗尽、计量异常、用户追加／撤回等需要动作的状态变化沿原通道送达。同一未变状态不重复
  广播。统计和状态读取不启动模型，数值及身份不包含业务正文、隐藏题或凭据。
- **F8 — 耗尽、暂停与追加边界。** 已计估算与有效保守暂估合计达到或超过授权金额时，
  标记预算耗尽并触发当前任务全部绑定执行方的暂停请求，暂缓安排新的消耗动作；“全局”
  仅指该预算所属任务，不影响其他任务。触发、实际送达、执行方确认和在途调用分别记录，
  发出消息不代表所有执行已暂停。允许在途请求、usage 延迟及必要安全收口产生尾部消耗，
  全部继续记回原任务，不承诺实际扣费绝不超过预算；设计须按实际并发、单次请求
  限制与控制延迟说明可验证的超额量级。保留已应用模型、未知写入及独立验收报告；未完成
  时如实报告 PARTIAL／缺口，不以预算耗尽代替语义失败，不跳过验收或自行缩减业务。
  追加额度必须来自明确用户授权，记录追加金额及新总额，历史消耗不清零；追加不足则
  仍耗尽。补足后按用户的继续授权沿原任务接续，余额变化本身不撤销用户主动暂停／停止。
  分runtime控制、逐成员确认及安全接续见设计第5节。普通新消耗关闭，有限的暂停控制
  turn与必要收口仍计费；预算原因与用户暂停／撤回／到期分开，清除一个不清除其他原因。
