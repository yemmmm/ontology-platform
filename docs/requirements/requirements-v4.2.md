- 2026-10-10 新增页面登记见 R4.2-008；本条五 Tab 为已交付基线，新对话页面单独细化、
  实施与验收，不能由本条历史 PASS 推导已接入 Delivery。
- 2026-10-08 用户调整：项目切换入口仅保留在主页面（概览）；模型浏览、召回测试、
  成员权限和设置页不提供右上角项目选择器，切换项目必须先返回概览，切换后仍停留在概览。

  也不把旧功能搬进抽屉、设置或隐藏入口。旧链接及本地保存的旧 Tab 应安全回到概览。
- 不因前端退役清除历史模型、CQ、验收记录或权限数据，不扩大后端退役范围。

**验收方向**：新项目与已有项目均只有五个 Tab；直接打开旧链接或恢复旧浏览器状态不会
进入退役功能；前端代码中不再保留仅服务于退役页面的运行分支。

### R4.2-002 精简概览页面

- 页面只围绕四项内容组织：项目介绍、一句话项目进度、CQ 能力问题、验收进度。
- 项目介绍说明项目目标与业务范围；本版本不恢复完整 Brief 编辑和访谈工作区。
- 项目进度用一句可读的话概括当前阶段及主要进展或阻塞；有依据才显示，不按节点数、
  Brief 完整度、进程存活或页面完成情况生成虚假的完成率。
- 2026-10-08 用户要求精简 CQ 与验收展示：全景题、切片题合并为一个列表，前端不按
  覆盖类型分组，完整展示所选当前题集；移除历史 CQ 列表、版本选择器及逐题技术版本号。
  优先匹配当前冻结绑定；无绑定时选择唯一最新且摘要完整的冻结题集，尚无冻结题集时
  只展示唯一最新公开记录并注明冻结未核实。存在歧义或冻结损坏时不任意挑选旧题集。
  不增加审核、冻结、编辑或建模启动操作。
- 隐藏题题干仅通过项目／组织管理员专用 CQ 读取接口提供，在题干后追加“(隐藏题)”文字标记；
  不提供参考答案、答案点、私有回答或诊断。普通 read／model Key 不可读取此接口，
  原公开建模投影与生产角色输入继续不包含隐藏题。此项为本轮前端管理视图的显式增量。
- 每题增加验收通过／未通过／待复核／未完成／尚未验收标记，仅使用绑定同批次、
  同快照且适用性为 verified_current 的正式报告，不使用旧报告或公开回归冒充当前验收。
- 2026-10-08 用户要求补齐验收结果关联：读取同项目、同冻结题集且与在线模型一致的
  正式验收报告，包括无生产状态文件的只读验收运行。按每题最新正式结果汇总，重复题
  不重复计数；新验收明确覆盖但尚未裁决的题目不得沿用旧通过结果。进度不区分公开／
  隐藏题，分母固定为当前完整冻结题集，部分报告不能把 8/8 显示成全 26 题完成。
- 验收进度展示在 CQ 能力问题标题正下方、题目列表上方，只显示一个进度条及必要状态文字，移除独立验收面板、
  报告选择器和诊断详情。进度为正式报告中已获得通过／模型或召回不满足裁决的题数占
  当前完整冻结题集题数；文字保留已验收、应验收和通过题数，每题只计一次。
  待复核、运行未完成及未执行不算完成；无当前有效报告或计数不完整时不显示虚假百分比。
  进度条 100% 表示该批题目完成裁决，不表示全部通过或全项目语义验收通过。
- 来源和更新时间保留在读取合同中，不恢复完整运行与验收诊断工作台。

**验收方向**：四项内容清晰可见；缺数据与有数据均能正确展示；项目进度与验收进度不混淆，
未执行、局部验收和历史结果不会变成当前整体 PASS。

### R4.2-003 以图谱画布为主体的模型浏览

- 图谱画布是主要内容区域，节点和边分别表示真实模型资源与关系；不再以旧列表页面为主、
  图谱作为附属入口。
- 2026-10-08 用户确认：属性／谓词定义不作为独立画布节点；依据读取结果的明确类型
  `owl:DatatypeProperty`／`owl:ObjectProperty` 排除，谓词继续作为真实关系边的标签。
  此约定只改变画布投影，不删除定义或关系，不按名称、IRI 路径或业务视角猜测资源类型。
- 2026-10-08 用户要求补齐结构引用展示：除真实 RDF 关系外，展示已有映射／语义定义
  结构字段中的明确引用。IRI 必须准确对应获准的已加载资源；`definition_ref` 只按同一
  GraphSet 获准窗口内唯一的 `semantic_id` 解析，不按名称或说明猜边。实线表示已断言
  关系，虚线表示结构引用并保留来源字段；只改变只读投影，不写入或补造模型关系。
  已有中性 `mapping_payload` 的 JSON／字典字面量采用不执行代码的解析方式兼容读取。
  受限、未加载或不能唯一解析的引用不画边，继续保留窗口完整性提示。
- 支持搜索模型节点，在画布中定位或突出匹配结果，并与视角过滤共同生效。
- 提供“全部”及既有七视角过滤：对象、行为、规则、角色、流程、数据映射、接口映射。
  视角依据既有语义合同，同一资源跨视角保持同一身份，不复制为多套模型。
- 2026-10-08 用户调整：视角过滤由单选下拉改为可点击的多选视角按钮，与既有色系图例
  合并展示；首次点击仅展示该视角，继续选择其他视角展示所选视角的并集，再次点击
  取消该视角。未选择视角或点击“全部”恢复全部已加载节点；“清除过滤”同时清除搜索
  和视角选择。共享资源按 IRI 去重，关系仅在两端节点均可见时展示，搜索与多选共同生效。
- 提供图谱阅读必需的缩放、拖动画布和节点基本信息查看；本版本不包含模型编辑或 CRUD。
- 2026-10-08 用户精简节点详情：移除“当前读取位置”选择器及 Ontology 信息；其余
  详情字段保留，默认读取该 IRI 的首个已加载位置。多位置仍参与节点去重、视角过滤和搜索。
- 2026-10-08 用户增加选中高亮：选中节点后，高亮该节点、当前可见图中的一跳相邻
  节点及该节点的全部入边／出边（含结构引用）；其他节点置灰，非关联边淡化。
  选中状态优先于搜索高亮；点击空白画布或关闭详情取消选择，恢复搜索高亮或默认展示。
  切换选择、视角过滤及关系刷新后按当前可见图更新，不改变节点的基础颜色和大小。
- 2026-10-08 用户要求恢复按连接边数量调整节点大小：统计当前画布中每个节点的入边与
  出边总数，包含实线关系和虚线结构引用；连接更多的节点更大，尺寸限定在 25～58。
  视角过滤和刷新后按可见图重新计算，搜索高亮不改变尺寸；连接数全部相同时统一为 25。
- 2026-10-08 用户调整节点配色：采用“视角固定色相＋连接数控制饱和度”，替代按 IRI
  分配的三档深浅。对象蓝、行为橙、规则红、角色金、流程紫、数据映射绿、接口映射青；
  色系仅依据已有视角声明。同一资源的已加载位置存在不同视角声明，或没有可识别的视角
  声明时使用中性灰，不自行指定主视角；保留同一资源身份和已有详情读取位置。
  饱和度与节点大小复用当前可见入边＋出边的均值／标准差及 tanh 归一化，包含实线与
  虚线；彩色节点保持色相和明度，饱和度限定为 35%～75%，连接越多越鲜明；中性灰
  保持无彩色，连接越多明度越低，明度限定为 44%～68%。连接数全部相同时统一使用
  最低强度（饱和度 35%，灰色明度 68%）。视角过滤和关系刷新后重算；同一图的返回
  顺序变化不影响颜色，搜索、选中与拖动不改变基础颜色。图例展示各色系低／中／高
  强度示例，并说明大小与颜色强度仅表示当前可见连接数，不表示业务重要性或模型质量；
  搜索命中使用外圈强调，选中使用深色描边。
- 用户在设计轮再次明确：不再单独展示 Class。不得设置 Class 专页、专属列表、导航或
  独立管理界面；已有模型资源和分类信息统一纳入模型浏览，不将其恢复为旧 Classes 功能。
- 搜索与过滤仅作用于当前项目获准范围；无匹配、无模型及部分加载状态须可辨别，
  不把当前画布未显示解释为整个模型不存在。
- 首版按项目各 Ontology 默认 GraphSet 有界加载，搜索明确标为“搜索已加载模型”。
  现有 entity-relations 只覆盖 NamedIndividual，登记必要的通用 resource-relations
  read-model 增量以连接包括 Class 在内的实际已加载资源，复用原有受治理合同，详见设计 D4／D5。

**验收方向**：进入即以图谱阅读模型；可搜索定位节点、切换视角并清除过滤；节点身份与
真实关系不因过滤改变，受限资源不会通过图谱或搜索泄露。

### R4.2-004 query 到相关节点的召回测试

- 核心交互为输入 query、提交查询、显示相关节点；不继承旧 Context Query 工作台全部控件。
- 沿用现有受治理召回接口及项目范围，结果显示可识别的节点名称和必要摘要；如展示分数，
  只能使用接口实际返回的数据。
- 说明空结果、查询失败和接口实际报告的降级／未取完等必要状态，不伪装完整结果。
- 本版本不新增问答生成、SQL／API 执行、自动验收或复杂检索参数配置工作台。
- 固定项目范围、hybrid、depth=0 和已断言节点类型；只显示节点主命中，提供既有主命中
  游标的“加载更多”，不继承关联上下文工作台。查询变化清空旧结果，详见设计 D6。

**验收方向**：输入 query 后得到真实接口返回的相关节点；切换 query 不混用旧结果；
空结果与失败可区分；前端只接收和展示获准节点。

### R4.2-005 已有角色与 Grant 展示

- 展示当前项目已有权限角色、角色说明及对应 Grant，保留真实名称和值。
  用户原述“grand”在本需求中按现有权限术语 `Grant`（授权项）登记。
- 本版本为展示范围，不自动继承旧页面的用户／成员管理、角色分配、角色 CRUD、
  Grant 编辑、保护集管理和 Key 管理功能。
- 权限角色与模型中的业务角色、Agent 角色保持区别；空 Grant 如实显示，
  不因成员身份或业务角色关联推断授权。

**验收方向**：已有角色与 Grant 对应准确；无角色与无 Grant 状态明确；页面没有超出本次
范围的管理操作，读取遵循原有服务端权限合同。

### R4.2-006 设置页面与范围约束

- 保留独立设置 Tab，沿用现有视觉规范。
- 用户于本轮设计明确选择最小清单：语言偏好、当前登录账号、退出登录；复用已有语言与
  会话能力，不新增设置项。设置与是否有项目或 Ontology 无关。
- 设置不得成为退役页面、技术诊断、运行控制或管理能力的收纳入口。

**验收方向**：语言切换、账号展示与退出可用，实际设置项仅为已确认清单，无退役功能回流。

### R4.2-007 页面重写与现有视觉风格延续

- 优先围绕新五 Tab 重新编写页面、导航及页面状态组织，不以旧页面裁剪、改名或套壳作为
  默认实现方式；不维护新旧两套页面并行运行。
- 可以复用与新需求直接吻合的底层能力，例如鉴权、请求封装、类型、基础 UI、图谱渲染
  原语和样式变量；复用应减少实际工作，不将旧页面结构与旧业务交互带回新版本。
- 视觉风格与现有页面保持一致：浅色背景、白色面板、紫色主强调色，以及既有字体、圆角、
  边框、间距与控件观感。功能和布局可重写，不重新设计品牌风格或引入无关 UI 体系。
- 以当前 [样式文件](../../frontend/src/styles.css) 为视觉基线，详细设计时选取实际页面

- 后端接口优先复用已有合同。若确有数据缺口，先登记具体缺口，再限定必要接口增量，

**验收方向**：代码结构服务于五 Tab，旧页面和专属依赖实际清理；浏览器视觉对照确认风格
一致；不存在为兼容旧前端而保留的额外功能。

### R4.2-008 Delivery 建模对话与统一历史

**状态与来源**：2026-10-10 用户要求增加与 Delivery 沟通的页面，展示网页或
modeling-dev-loop 的消息及 Delivery 对外回复，并确认首版接入已有 Delivery 会话。
后续用户授权逐个讨论待决策点，Q1—Q5 已全部关闭，功能范围及验收条款已细化；用户
随后要求继续完成详细设计，现已形成
[详细设计](../delivery/designs/2026-10-10-r4-2-008-delivery-conversation-design.md)。
独立设计审阅、实现与验收未开展，本轮不启动开发、服务变更或真实建模。

用户另要求登记 [R4.0-028](requirements-v4.0.md#r40-028-建模-team-原地待命与显式停止)：
建模及验收全部完成后整个 Team 原地待命，由显式 stop 触发销毁。该独立需求随后已完成
细化与设计，用户补充已运行 Consumer 保留、未验收不预建；尚未实施，设计不表示待命已经实现。

#### 1. 功能要求与首版范围

**F1 — 页面及会话范围**

- 项目下新增“建模对话”页面，按 Delivery 交付会话选择和展示。首版接入已有会话，
  不包含网页创建新建模任务、上传材料及完整启动配置。
- 一个交付会话可关联多次生产、验收及修复 run；单个 run 结束不等于交付会话结束。
  会话须可靠关联当前项目；无会话时明确展示空态，不猜测或自动创建。
- 页面沿用现有视觉风格，展示会话、在线情况、最新业务进展、对话时间线、输入及待答
  问题。运行状态带更新时间和依据，不用聊天表述替代真实写入或验收结果。

**F2 — 统一消息入口与完整输入**

- 网页、CLI 与 modeling-dev-loop 共用同一入口、已有 Delivery 执行主体及统一历史。
  用户与宿主 Agent 均可查询进展、回答业务问题、主动补充或纠正业务信息，以及发送
  暂停、继续、停止等控制消息；平台不按用户／Agent 来源划分能力。
- 普通消息与问题答复分别保留原文和实际问题关联。支持多个待答问题，不伪造问题 ID，
  不将普通补充强制转换成对某个问题的回答。
- Delivery 忙时输入仍能送达；控制沿既有即时通道处理。消息接收、实际投递与控制生效
  可区分；同一消息的超时重发不能变成重复执行，结果未知先核对实际记录。

**F3 — 暂停、继续与正常完成后的待命**

- 按 Q2 方案 B，暂停为临时停工，保留原授权及 Team；收到明确继续指令后，按原范围、
  剩余额度和有效期限恢复推进。暂停不自动撤回生产／验收／修复启动权限，也不重置额度
  或延长有效期限；取消、撤回预算分别处理，不由普通“继续”自动恢复。
- 按 R4.0-028，建模及全部验收完成后整个 Team 原地待命，仍可在线提问；由用户或
  modeling-dev-loop 宿主显式 stop 后才销毁。结果认可本身不自动等同于 stop。
- 页面呈现实际控制结果和在线／待命／离线状态；“消息已发送”不等于暂停或停止已生效。

**F4 — 真正离线后的只读行为**

- 按 Q1 方案 A，Delivery 真正离线时只读统一历史和最后可核实状态，提示通过现有入口
  接续后再提问；首版不提供网页唤醒或离线消息代发。
- 正常工作完成后的待命与离线分开呈现，不能仅凭结果报告或 run 终态显示已经离线。
  刷新、重连或关闭浏览器不启动另一个 Delivery，也不控制现有 Team 进程生命周期。

**F5 — 消息来源与不处理冲突**

- 区分真实用户、宿主 Agent、测试代答与 Delivery 的展示来源。宿主转交用户原话和
  Agent 自行提出的消息保留实际来源，不能都标为“你”或真实用户确认。
- 按 Q3，来源仅用于展示和记录，不决定消息优先级或能力范围。本期不设计冲突仲裁、
  用户优先规则或按发送者划分的操作限制；问题／回答关联不作为来源之间的能力分级。

**F6 — 统一历史的起点及内容边界**

- 按 Q4 方案 B，完整有序的历史从新入口启用时开始；首版只展示其后经统一入口接收的
  消息和 Delivery 明确对外回复。新消息保留 ID、顺序、时间、发送者、入口、原文和
  实际问题关联，刷新、重连与切换会话后保持一致。
- 页面明确历史起点，不导入、展示或还原更早旧输入／输出日志，旧记录保持原件。
- 只展示明确对外消息，不开放 native transcript、内部 Agent 协作、推理或私有工具
  日志，也不以这些内容补齐旧历史。隐藏验收材料及答案不进入用户对话的公开投影。

**F7 — 本期不细化权限治理**

- 按 Q5，本期暂不考虑权限问题，不采用“仅项目／组织管理员”或新增成员分级方案，
  不增加对话专用权限、角色／Grant 或权限管理入口，也不将权限治理完善作为交付前置。
  复用平台现有登录及项目工作空间；会话项目归属用于准确路由，不作为新权限方案。
- 不因复用管理员工作台接口就默认将建模对话限定为管理员。当前权限治理缺口留待后续
  单独需求，不在本条默认为已解决。会话原有运行授权、额度及写入完整性合同继续适用。
