## 目标与范围

将当前以 Class、Entity、旧可执行规则和技术诊断为中心的前端，调整为以项目和业务场景
为中心的建模工作台。用户能够理解已有模型、当前建模进展、需要确认的业务问题及有效验收
结果，并可下钻查看技术细节。重组导航、页面职责和语义展示，复用现有可用组件与接口。

本版本新增的是前端适配范围。例如 R4.0-006 首版只交付管理 API、R4.0-021 只要求宿主
摘要和计时记录；本版本将相应展示或管理入口纳入目标，不据此认定它们在 v4.0 中未按范围交付。
新增页面不扩大主体权限、真实建模额度、外部执行权限或 Agent 职责。

### 产品边界

1. 项目是主工作空间。业务切片、视角、Ontology 和 Agent 是不同维度，不建立一一对应。
   尚未确定 Ontology 拓扑时，仍可浏览场景、访谈和获准 CQ；不要求先创建空 Ontology 才能工作。
2. 七个视角是同一模型的阅读入口，不是七套资源副本或必须依次通过的七阶段。
   共享定义使用同一身份，不从同名、同类型或图形位置推断业务等价。
3. 平台继续表达语义，外部系统执行业务。页面不增加流程执行引擎、规则脚本运行器、
   API 调试台、业务行导入／浏览、数据库连接管理或自动 SQL 改写能力。
4. R4.0-012 的 Evidence／完整 lineage 停用范围保持；不恢复逐资源缺证提示、追溯覆盖率、
   补证入口或历史追溯页。必要写入回执、恢复记录和独立验收依据可以按原职责展示。
5. 展示状态取自现有权威产物，不在浏览器维护第二套业务确认、应用或验收结论。
   页面不自动改写场景地图、候选、冻结题集和历史报告。
6. 普通用户仍通过 Key 访问，管理员可登录网页；普通用户门户、自助注册和 SSO 不纳入。
   业务角色、权限角色、Agent 角色分开展示，不因业务职责关系自动授予权限。
7. 先交付只读展示与已明确的管理员操作。启动、恢复、修复等操作须接入已有获准合同，
   不因出现一个按钮就新增运行、调度或恢复机制；细化前不把这些操作列为已可用。
8. v4.1 的页面完成不作为 v4.0 真实建模或 L0／L1 验收的启动前置。

## 信息架构与流程

```text
项目
├─ 总览
│  场景目标、当前阶段、待确认事项、最近成果、验收缺口
├─ 建模工作
│  业务澄清、能力问题、场景地图、候选与变更、运行记录
├─ 语义模型
│  全部、对象、行为、规则、角色、流程、数据映射、接口映射
├─ 检索与验证
│  语义检索、早期公开问答、独立验收、校验与推理
└─ 项目管理
   成员与权限、Key、保护集、Ontology 与图管理、技术诊断
```

Ontology 是模型范围选择，GraphSet、Class、Entity、IRI 等作为筛选或详情保留。
默认使用可阅读的列表与详情，关系图用于探索选中定义的上下文；不要求用户先理解底层图结构。

页面承接现有流程：场景理解与访谈 → 全景 CQ 审核 → 切片分析与切片 CQ 审核／冻结 →
多视角候选与共享定义 → Ontology 拓扑决策 → 获准候选的物化计划 → dry-run 与可恢复修正 →
翻译审阅 → 同内容 apply／读回 → 生产交接与独立验收。
多视角允许交错推进；已有小业务链安全写入后，可开展早期公开反馈，不等待全部模型完成。
页面表达实际依赖，不增加固定 Agent 数、视角数、人工审批或机械阶段硬门。

## 需求列表

### R4.1-001 项目工作空间与任务总览

**目标**：进入项目即可知道当前在做什么、已经得到什么，以及是否需要用户决定。

**功能范围**：

- 导航按上述信息架构重组；项目级工作不依赖先选 Ontology。模型浏览保留明确的范围选择。
- 首页展示当前工作、最近核实时间、实际运行状态、待业务确认／授权事项、已表达范围、
  已应用成果、最新有效验收结果、剩余工作和下一动作。
- 业务确认、建模表达、平台应用、独立验收四种状态分别呈现，不由 Brief 完整度、
  节点数、角色完成或进程存活推导总体完成度。
- 显示结果的范围与限制。局部 CQ 通过不能替代全 v4、SQL／API、真实 DL 或 L2／L3 通过。
- 技术健康、原始记录、运行配置放入次级详情；未知状态保留未知，不以旧记录冒充当前事实。

**验收方向**：没有 Ontology 的项目仍能进入获准的项目工作区；局部通过但有待验范围时
不显示整体完成；阶段结束但尚有已授权待办时显示后续动作；每个摘要可定位其来源与时点。

### R4.1-002 业务澄清与能力问题工作区

**目标**：把 Brief 填写、业务语义确认与 CQ 范围审核组织成可理解的工作内容。

**功能范围**：

- 保留 Brief 与访谈内容，区分缺失信息、待确认含义、显式未知和冲突。
- CQ 展示题干、获准必答点／审核内容、题目版本、审核与冻结状态及相关业务范围。
  不把旧 Brief 完整度或旧 competency_questions 数量当作 Team 冻结题集。
- 全景／切片／跨切片等覆盖维度，与公开／隐藏可见性维度分开。
  建模工作区只接收获准公开投影；验收专属内容由原有权限与隔离合同决定。
- 如需页面提交业务回答或审核决定，应接入现有责任方和版本绑定合同；不直接修改冻结文件，
  不把参考答案传给 Consumer，不因前端交互新增审批层。

**验收方向**：业务问题与技术故障分别路由；页面、网络响应、缓存和导出均不向生产侧泄露
隐藏题／答案；题目修改后的版本与冻结绑定准确，历史裁决保持原义。

### R4.1-003 场景地图与共享定义协同展示

**目标**：可按切片与视角了解实际表达、共同定义、依赖和未完成事项。

**功能范围**：

- 使用“业务切片 × 七视角”矩阵，单元格展示原合同的状态、已表达范围、未知／不适用／冲突、
  当前候选修订与关键 item、待办和责任；不把未登记视角默认记为不适用。
- 提供共享定义、主维护切片、跨切片依赖、变更影响及引用重审详情。
- 四种状态分别读取：业务确认来自确认记录，表达来自地图及候选，应用来自 Batch／Attempt／
  回执，独立验收来自绑定当前范围与状态的报告。`modeled` 不自动提升其他状态。
- 地图保持 Coordinator 唯一写入职责。显示核实时间、产物关联和已披露差异，不自动回填
  或改写冻结地图；隐藏诊断不得进入生产地图。依赖未读全时不声称没有引用。

**验收方向**：同一候选已表达但未应用时可准确展示；验收失败不自动把所有视角退回 pending；
共享变更只展示实际重审范围；旧修订与最新产物不会混为同一完成依据。

### R4.1-004 统一语义模型浏览与七视角详情

**目标**：围绕业务含义浏览模型，在不同视角之间沿同一共享身份切换。

**功能范围**：

- 统一列表、范围／视角筛选、关系图和详情；先展示含义、范围、关联及未知，再展开 IRI、
  底层类型和图位置。按真实语义声明识别角色，不从名称或页面位置推断。
- 允许无 Class、多分类或普通业务分类的资源；不为展示便利强制建立正式 Class。
- 同一定义跨视角打开同一资源；局部调用、对象位置和映射上下文不覆盖共享定义。

| 视角 | 必须保留的阅读内容 |
| --- | --- |
| 对象 | 定义、属性、关系、可选分类、局部差异及未知项 |
| 行为 | Action 对象适用、参数、前置条件、成功效果、职责及零／一／多个外部能力关联 |
| 规则 | 分类、自然语言说明、脚本、输入输出、语言／版本、执行环境及空值／失败／副作用语义 |
| 角色 | 业务职责与参与关系；与管理权限角色和 Agent 角色的区别 |
| 流程 | Action 定义与调用点分离、同类对象的不同位置、参数来源、分支、循环及输出条件 |
| 数据映射 | 业务定义与表列对应、行粒度、技术键／业务键、Join 基数、编码、转换与指标口径 |
| 接口映射 | 系统／接口身份和版本、请求响应字段位置、映射方向、对象位置及精确 Operation／binding 关联 |

流程图仅表达已建模语义，不增加并行同步执行能力。参数未知、空值、明确无输出、不适用等
状态保持区别。映射不保存业务行或凭据，不默认选取 Operation 的首个 binding。
已分析但未物化的内容保持 `analyzed_not_materialized` 或现有对应状态。

**验收方向**：无 Class 资源可正常浏览；共享定义不重复；原工单／返修工单等同类型对象位置
可辨别；字段映射与业务参数身份不同；脚本可读但无执行入口。编辑能力只复用明确可用的
受治理写入路径，不为七个视角各建一套 CRUD。

### R4.1-005 跨视角语义检索工作台

**目标**：从对象、Action、流程、规则或映射入口取得可解释且范围明确的语义上下文。

**功能范围**：

- 使用既有 Context Query，提供项目／Ontology 范围、资源类型、语义角色等合同支持的筛选。
  `semantic_roles` 只筛选主命中，不能误用于剔除必要的关联上下文。
- 分开显示主命中与关联上下文，支持精确资源下钻、主命中分页、上下文分页和后续读取。
- 如实表达召回降级、展开预算／深度受限、投影省略、结果过期和版本变化。
  查询读完不等于业务知识完整；空结果或未取完不能证明模型不存在。
- 服务端先授权过滤，再计数、分页及遍历；浏览器不得获取全部内容后再隐藏。
  无权资源与不存在按原合同不可区分，不显示隐藏数量、占位节点或受限关系桥接。
- 保留参数、规则、映射的必要语义，不恢复 Evidence／lineage 字段和缺证提示。

**验收方向**：非首个命中页的上下文可正确续读；过滤条件或模型状态变化不会混用游标；
compact 投影省略与真实未知可区别；受限资源不通过列表、图、统计或导出泄露。

### R4.1-006 公开反馈与独立验收结果展示

**目标**：明确呈现问题是否得到正确回答、哪些范围已经验证，以及失败判断的依据和限制。

**功能范围**：

- 早期公开问答独立展示问题、真实语义读取后的回答、不足和生产侧反馈；不计作最终独立验收，
  不要求每个批次或视角都执行一次。
- 独立验收按实际获准范围显示完整分母、公开／隐藏分组、通过、失败、待复核、未完成、
  未执行及专项缺口，并绑定冻结、模型状态、报告版本和核实时间。
- 逐答案点呈现原裁决及诊断，区分模型表达、检索可发现性、Consumer 理解、题目范围问题和
  原因未确定。诊断维度不替代四类运行失败归因；同题多个诊断不重复增加失败题数。
- 保留旧回答与报告，不拼接不同状态的历史 PASS；公开或已用于修模的问题不再冒充隐藏盲测。
- 区分开发测试、独立功能验收与真实语义验收；L0 Runtime、L1 Modeling quality、
  L2 Repeatability、L3 Productization 分段展示。静态映射解释不代表真实 SQL／API 执行。

**验收方向**：有未执行项时不能显示完整 PASS；早期反馈与正式报告不混算；
`model-recall-insufficient` 不被展示为已证明模型缺失；生产侧不能读取隐藏私有诊断。
最终验收者不通过本页面创建、继续或修复被验收 run。

### R4.1-007 建模运行与交接状态展示

**目标**：把现有运行记录整理为当前事实、下一动作和可下钻的技术详情。

**功能范围**：

- 复用 Build Context、Session、Checkpoint、Batch、Attempt 及宿主摘要，区分平台 Session、
  Team run 和宿主任务，不能假定它们一一对应。
- 展示候选到 dry-run、翻译审阅、apply、读回的关联，以及第一阻塞、未知写入和恢复记录；
  不把重试次数、角色终态或进程存活作为质量结论。
- 分开呈现生产交接、写入排空、进程／锁释放、独立验收启动、阶段结束与最终收尾。
  已删除在线资源的历史检查点不能显示为可直接恢复。
- 显示最新适用用户配置及实际角色配置，区分请求值、生效值和未核实；不宣称存活线程已热切换。
- 授权余额取自真实台账，未知时显示未知；不从事件数量猜余额，不增加平台建模次数硬门。
- 时间区分生产语义建模、独立消费／评分、等待、修复测试、审核文档、启动清理；
  墙钟、累计 Agent 时间、重叠和估算分别说明，不用进程全存活时间代表有效建模。
- 未接入操作合同前只读展示；后续操作不得绕过原授权、写入对账、资源生命周期和独立验收边界。

**验收方向**：阶段完成仍可显示剩余获准工作；不同 run／报告不串联成错误当前态；
历史记录保留；未知进程状态、授权余额及计时缺口不伪装成精确事实。

### R4.1-008 管理员成员与语义权限管理

**目标**：让管理员通过现有管理 API 维护主体与语义可见范围。

**功能范围**：

- 在各自权限范围提供用户／成员、项目权限角色、角色 Grant、保护集、Key 的管理入口，
  以及业务角色与权限角色的显式关联；不提升现有组织／项目管理权限。
- 成员关系本身不授予保护集权限；Key scope、用户状态、成员关系、角色和撤销状态分别表达。
  有效 Grant 由服务端计算，客户端不得自报。
- 沿用密钥仅创建时返回明文及撤销规则；不在模型、报告或日志中复制凭据。
- 普通用户网页登录、角色继承、deny 策略、外部数据行列授权不纳入。
- 将现有浏览器本地编辑锁称为防误操作锁；不表示后端只读、Agent 已暂停或写入租约被撤销。

**验收方向**：未授权管理员操作被服务端拒绝；业务角色关联不会自动授予权限；
角色及主体状态变化按既有合同生效；本地锁不会向用户承诺后台停止。

### R4.1-009 旧规则入口退役与校验推理分离

**目标**：页面与 R4.0-022 的产品职责收敛一致，避免两套业务规则能力混淆。

**功能范围**：

- 新业务规则入口读取 R4.0-005 的普通语义实体、`rule_definition` 注解及说明／脚本，
  不继续包装旧 Rule Definition 维护接口。
- 联动移除旧规则 CRUD、Run rules、Generate 中旧规则调用、rule-result 专用结果、
  图层、统计、筛选与引导。真实退役归 R4.0-022，不能只隐藏按钮后宣称完成。
- 保留 SHACL 结构校验、OWL 一致性／分类／蕴含、必要结果及有效／过期状态。
  显示实际推理实现模式，stub 结果不能冒充真实 DL 推理通过。
- 保持 R4.0-012 已停用追溯入口撤下，不因复用旧组件重新出现补证卡片。
- 旧页面路由、说明和工具目录随实际退役同步；共享能力按依赖保留，不按名称批量删除。

**验收方向**：正常页面不请求已退役接口；完成退役时直接 REST／MCP 也不能运行旧规则；
业务规则语义读取、SHACL、OWL 和通用检索不回归。未完成后端退役时如实保留该依赖状态。

### R4.1-010 Team 与宿主产物的最小前端接入

**目标**：使新页面读取真实权威产物，避免用占位数据或第二套状态替代运行事实。

**功能范围**：

- 实施前逐页面核对现有 REST／读取模型、Team 产物与宿主记录；区分已可调用接口、
  尚未暴露的真实产物及尚未实现的能力。
- 优先复用语义查询、映射读取模型、构建上下文、批次和主体访问 API。
  对地图、候选审阅、CQ 冻结、反馈／验收报告和宿主摘要，只补选定页面必需的受授权只读接入。
- 保持原产物为事实来源，带适用范围、版本、观察时间及限制；协同状态不塞入 RDF，
  不新建通用产物平台、状态数据库、监控平台或后台调度框架。
- 只返回对应受众获准字段；隐藏材料和凭据不得通过任意文件读取、原始 JSON 或导出泄露。
  旧工作流记录接口的存在不代表已接通当前 Team 的全部产物。
- 内容未接入、加载失败、权限合同返回及确实无内容须按各自合同表达；不编造百分比或状态。
- 新增写操作先明确既有服务、责任方、授权与内容绑定；真实语义变更仍走相应受治理写入流程，
  不允许绕过适用的候选批准、dry-run／翻译审阅／apply 和未知写入对账。

**验收方向**：页面状态可追到实际产物；旧版本、失效绑定与缺少数据不会变成最新 PASS；
生产与验收投影隔离；前端刷新、排序或展示操作不会修改权威产物或触发建模。

### R4.1-011 持续改进与自主修复的展示预留

**目标**：为未完成的 R4.0-001／023 保留合理位置，不提前固化其流程与技术实现。

**功能范围**：

- 持续改进可在问题及模型详情中关联已存在的使用反馈；反馈采集、触发条件、评估和自动化
  方式等待 R4.0-001 细化，不预建自动本体演进流水线。
- 自主修复可在验收详情／运行记录中展示已确认缺陷、Agent 责任交接、修复目标与结果。
  具体承接角色、交接格式和通道等待 R4.0-023 细化，不新建平台修复任务系统。
- 业务用户只处理实质业务歧义、范围／兼容性决定与新增授权，不要求其分析平台响应或编写
  技术修复任务。技术诊断和交接由系统 Agent 承担，证据不足时保留原因未确定。
- 隐藏诊断不能换措辞转给生产；生产修订依据须能从获准业务资料独立核实。
  修复与最终验收职责分离，重验另留报告。

**验收方向**：未细化能力不呈现为可执行按钮或已完成服务；预留只影响导航和关联设计，
不增加空白占位页。依赖细化后再确定具体操作与验收条款，不阻塞已可交付页面。
