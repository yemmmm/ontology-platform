### R5.0-001 可控编排与有界 Agent 执行

**目标**：将流程控制变为可检查、可测试的程序行为；Agent 在有界目标和权限下作语义判断。

- **F1** 明确执行位置、正在处理的工作单元、下一项依赖、首阻塞与所需输入；程序负责已确定的路由、等待、结果归属和恢复，Agent 提供需要推理的判断及理由。
- **F2** 在 LangGraph 编排下使用有界自定义 Agent，执行基础暂定 Codex harness；优先验证官方 Python Codex SDK，必要控制使用 app-server 公开协议，不要求继承旧适配器。输入、工具与输出有明确合同，执行器内部会话与外层业务流程职责分开。实际 SDK／CLI、provider、模型、effort、工具行为及用量必须核对，不因默认值静默改变配置。最终采用以 F8 验证为据。
- **F3** 每个有长等待需求的工作单元可独立暂停与接续；无关工作继续。程序不因普通心跳、日志增长或计时到期无条件唤醒模型。
- **F4** 用户输入、暂停／停止、预算变化与关键事件即时登记，目标忙碌时排队，当前原生 turn/activity 自然结束后处理，沿 R4.4-002／003 的 2026-10-22 最新规则。下一原生回合开始前检查控制及预算；已开始回合内的工具后续、重试、压缩和获准应用允许自然完成并计量，尾差如实披露。queued、delivered、consumed 与 effective 分开；所有在途成员可核对停稳后才报告任务已暂停。正常控制不对 busy turn 使用 steer／interrupt；即时中断能力不成为当前默认暂停的前提。
- **F5** 执行控制与业务状态分离；错误、字段缺失、暂时等待和技术运行上限允许准确修正及继续，不因角色数量或固定尝试数永久终止目标。
- **F6** 不保留常驻 Delivery LLM 作为机械推进或转交用户的必需条件。Agent 的人工请求由程序 HITL 通道直接呈现给用户，答复直接关联原请求及工作单元；确需推理的语义协调可由有界助手承担，但不成为提问、答复或恢复的必经中转。该项是 v5 对旧职责合同的目标调整，实施时同步活跃提示与工具入口。
- **F7** 业务工作单元、一次执行尝试、LangGraph thread、Codex thread／turn、平台操作与原预算可明确关联。恢复先核对原执行、业务版本和实际副作用；不因节点重执行就重复启动仍在运行或状态未知的有副作用工作。完成本次 Agent 工作不自动证明业务收口、应用或独立验收通过。
- **F8** 全面改造前完成计划 P0 的 V1—V8：真实模型／工具循环、权限隔离、用量与金额、自然回合控制、压缩与补读、并行及 PostgreSQL 接续、真实平台故障对账、独立交接。已有机制证据按范围复用，未验证项不能用 schema、mock 或人工代做标通过。公开接口无法满足必需能力时，停止依赖该方案的开发并据实际缺口更新选型；可恢复错误先窄修，不扩大为永久运行拒绝。
- **F9** 动态 HITL 同时覆盖 Agent 按实际需要发起的业务澄清／决定请求，以及用户主动补充、纠正和任务控制。请求保留稳定身份、原工作单元／步骤、相关内容版本、问题、依据及影响范围；答复保留主体、来源与适用范围。人工等待采用持久工作流等待点，当前 Codex 原生回合自然结束后进入等待或消费新输入，不使用原生 steer／interrupt 实现日常人工介入。答复只恢复或重审匹配部分；未答复、部分答复、版本已变化均保持准确状态，不自动选默认含义。重启后可定位原请求、答复和待恢复点，不重复提问、消费或已确认应用；只挂起依赖该输入的部分。无需人工判断的正常步骤不增加固定审批。

- **F10** 2026-10-29 用户要求增加检查点快照，供后续流程优化使用。当前最小范围为按需
  命名保存工作空间内容及版本、LangGraph checkpoint 引用、输入／任务卡及实际模型
  版本引用，支持只读查看与对比；不要求先停稳 Agent，不增加审批或运行完成门。
  完整平台数据／分叉恢复继续复用既有能力并另按需要接入，不以引用快照冒充数据备份。
  该最小快照已实现并实际保存／对比，含忙碌观察和换进程接续；证据见
  [记忆与快照交付](../delivery/records/2026-10-29-v5-memory-snapshot-delivery.md)。

**验收**：局部等待不阻塞无关单元；进程恢复、用户控制及预算行为有真实状态证据；真实 Agent 提问直达用户入口，答复在恢复后实际改变相应判断，主动补充也被消费，过程中无需 Delivery LLM 转交；未回复与局部回复不被扩大为全范围确认。增加一种可恢复结果或修改一个重入点时，改动集中在对应流程／合同，不要求连带修改整个运行栈。机制测试与真实 Agent 采用分别报告。

局部分数平均较高，均不能证明该业务链成立。例子用于说明方法，不引入平台专用业务规则。

#### 功能要求

- **F1 — 启用范围与兼容。** 任务可显式启用过程评价并选择观察点；未设置时保持关闭，
  不静默修改既有 run／checkpoint。研发任务模板可显式开启，但开关不授予收费调用、
  新建模或追加预算权限。本期支持任务配置及 Host 命令入口，不要求新增管理 UI。
  关闭时不产生专用阶段抓取、评分调用或评价等待依赖，原业务记录和必要验收保持。
- **F2 — 三类观察点与语义范围。** 首期覆盖 CQ 成果、切片方案、跨切片整合，具体准则
  见下表。一个评价对象可以包含零个尚未分派的工作单元、一个单元或多个相关单元，
  以实际业务范围和产物引用确定，不按 Agent、LangGraph 节点或 Ontology 数量决定。
  CQ／切片评价检查计划与候选；首期跨切片整合评价检查已应用的实际组合及其治理读取。
  计划中预期的连接与实际成立的连接必须区分；未应用时保留未到达／待评价，不冒充实际整合。
- **F3 — 显式提交与最小抓取。** 在现有工作空间／产物提交边界，由生产方或获准 Host
  明确声明某范围的某版成果可评价，并给出目标、来源、产物及版本引用。程序核对可定位性，
  不从聊天措辞、工具成功、原生回合结束或图节点完成自动推断业务阶段通过。不规定固定
  阶段顺序、切片数量或生产调用次数；仅保存本次评价所需获准内容及引用，缺产物准确登记。
  失败前已提交的可评产物仍可诊断；未声明完成的阶段在汇总中显示未观察到，不倒造快照。
- **F4 — 固定输入、去重与变化。** 每次评价绑定任务／run、观察点、业务范围、相关单元
  集合、来源及产物版本／摘要、评分准则版本、实际评价配置；实际整合再绑定本体修订。
  同一绑定重复提交、事件重放或进程恢复复用原记录及已完成结果，不新增重复调用；未知
  在途执行沿原身份对账。只有新一版显式提交、标准／配置变化或显式复评才创建新评价。
  旧结果保留原范围与时点；后续相关版本变化后标明已被替代／不再适用于当前目标。
- **F5 — 异步读取与证据边界。** 固定输入后可异步评价，生产推进不依赖结果返回。
  原材料和阶段产物按绑定版本读取；涉及实际模型时必须取得该修订的受治理读取。
  已保存的合法只读证据可以用于历史诊断，但必须明确其读取范围和时点，不冒称当前
  在线消费验证。默认观察快照仅保留引用、各组件并非原子读取；缺少历史正文／数据时
  显示目标变化或证据不足，不用当前模型补成过去结果，不为本期建设完整历史回放系统。
- **F6 — 独立性与权限。** 阶段评价使用与产物生产分离的原生上下文和只读工具范围，
  只能读取获准业务来源、绑定产物及必要实际模型，不能创建、继续或修复生产 run，
  不能写业务模型、生产记忆或生产完成状态。允许写自身报告和执行证据。报告默认只对
  获准用户／Host 复盘侧可见，不自动进入生产提示、共享记忆或正式验收输入；不读取或
  转交正式验收的隐藏题、答案及私有诊断。未来用户显式采用反馈时需留下实际介入记录，
  不能把受反馈影响的运行当作无干预对照。原生产自查不因改名变成独立评价。
- **F7 — 预期与评分。** 复用版本化通用阶段准则，任务具体目标来自获准原材料及业务
  确认，不要求每次新增一套人工标准答案。准则及绑定由 Host 沿获准配置确定，生产者和
  评价者不能根据待评成果倒改标准；业务预期不明则保留缺口。每个适用维度给出 0—4 分
  或“未验证”，附预期、实际发现、原文／字段／关系依据、差距、影响和优先级。程序核对
  身份、范围、实际读取和格式，语义由 Agent 判断；材料读回、标签或节点数不自动得分。
  CQ 质量、答案依据就绪及模型可回答性分开；生成的问题和答案不能互证完整覆盖。
  CQ／切片方案不因尚未应用模型或缺少执行回执而扣计划质量分；必要材料未绑定只表示
  相应判断未验证，不等于生产缺少内容。公开能力目标可带预期说明，是否要求题面隐藏
  答案取决于声明用途，不将所有目标强制当盲测题。
- **F8 — 组合评价与覆盖。** 组合评价联合检查相关单元的对外结果、共享身份、条件／
  例外、单位／时间口径及来源中的整体规则，包含至少能区分正确与错误组合的情境。
  同时检查父级未分派范围和本应存在却尚未建出的关联；不能只遍历已有依赖或累加
  子级分数。按有依据的关联组有界读取，不默认全部切片两两比较或一个上下文通读全项目。
  各范围的未检查部分、缺失依据与合理不适用分别可见，不为消除游离点强行加业务关系。
- **F9 — 开关变化、暂停与失败。** Host 可运行中手动停用或启用，持久记录变更及生效
  截止点；停用后不再准入新评价，尚未启动的队列项取消，已开始的原生回合自然结束并
  计量，不自动开下一纠错回合。再启用仅观察后续事件，历史补评须显式选择。Task 的
  pause／stop／预算控制优先；进程恢复不撤销停用状态或静默复活取消项。评价失败只影响
  该诊断记录，返回具体错误并允许沿原绑定纠正；不自动阻断或重启生产，不因评分低重跑。
- **F10 — 资源与成本。** 复用现有执行、任务控制与资源收尾机制，过程评价作为独立
  用途登记，并计入所有在途角色核对。托管调用含失败／纠错计入原任务预算并单列；
  不重置预算，不把评价算作新的建模轮次／semantic start。外部 Host 用量单列、未知
  用量不补零，另行授权的离线复盘独立记账。非阻塞只表示评分不是生产依赖，不豁免
  共享预算控制或在途凭据清理条件。无调用授权或准入条件不足时记录未执行原因。
- **F11 — 运行汇总。** 生产结束、失败或用户收口时，程序从已有记录生成 JSON 原件及
  可读 Markdown，默认不再调用总结 Agent。展示各阶段的范围／版本、逐项得分、关键
  缺口、未评部分、首次与修订后变化、评价用量／耗时及正式验收引用；首次可为截至当时
  的暂定汇总，晚到合法结果形成新的汇总版本，不覆盖旧件。暂停只形成进度快照，不冒称
  运行完成。主线完成、评价执行完成、阶段满意和正式验收通过为不同状态；没有评分的
  阶段仍保留在覆盖分母及状态中，不当作零分、通过或被平均掉。
- **F12 — 有界验证与交付范围。** 先用有固定产物和来源的样本校准，再在获准真实任务
  验证自动打点和整体报告。分别报告工程合同、评分有效性、流程优化效果；不能用新 Agent
  数量、分数上涨或局部 token 下降证明质量提升或净降耗。本期不增加自动修模、评分放行、
  常驻监督链、统一加权总分、多 Judge 投票、完整历史回放或第三方评价平台依赖。

#### 阶段准则与满意度

| 观察点 | 必需检查维度 | 关键输入与边界 |
| --- | --- | --- |
| CQ 成果 | 业务目标覆盖；问题清晰与可判定；条件／例外及跨单元问题；来源忠实与未知保留 | 目标、来源、整组 CQ 与确认口径；不能以题量、近义重复或自生答案代替覆盖，未确定答案不等于问题没有价值 |
| 切片方案 | 范围去向；完整规则与切分合理性；共享概念／身份复用；依赖、对外结果与整合责任 | 范围、来源／命题去向、工作树及未分派内容；不强制一个切片对应一个 Ontology，也不把所有细节前置为开工门 |
| 跨切片整合 | 共享定义相容；上下游条件与例外衔接；来源中的整体约束；组合情境与实际表达对应 | 相关单元、原规则、相容的实际修订及治理读取；有路径不等于业务成立，候选／摘要不补成实际模型证据 |

| 分数／结果 | 统一锚点 |
| --- | --- |
| 0 | 有明确证据表明核心目标未满足或与依据冲突 |
| 1 | 存在重大缺口，不能支持本阶段主要用途 |
| 2 | 部分满足，仍有影响使用的已知缺口 |
| 3 | 在声明范围和证据内满足约定要求 |
| 4 | 满足要求，关键边界、例外及适用组合反例均有充分验证 |
| 未验证 | 必需证据不足、读取未完成、目标变化或判断依据未确定；不猜分 |
| 不适用 | 确实不适用且有可核对的范围理由；与漏评、未完成、已停用区别保留 |

**满意度汇总规则**：适用必需维度均有充分证据且不低于 3、没有关键缺口，才可标记该
绑定范围“满足预期”；任一已证实缺口使相应范围标记“有差距”，未验证维度同时保留。
没有已证实缺口但仍缺必需证据时为“未验证”；整阶段不适用须有业务范围依据。
工程报告以每维 `status`、`score`、`priority` 表达上述判断：任一已证实缺口须落入相应
维度并标注非 `none` 优先级，无缺口用 `none`。`gap`／`key_gaps` 为解释性正文，不能
仅因“无缺口”或边界注记等说明非空而标记缺口；无缺口按合同使用空字符串／空列表，
正常适用边界放 `boundary_notes`，`unexamined` 仅含声明范围内本阶段必需未检查项。
评价自身的重试／解析反馈必须标明仅属评价侧，不能当作被评生产或答案失败的证据。
4 分不奖励节点／切片数量、长文或超范围建模。初期不生成全任务加权总分；关键缺口
与覆盖不足不能被其他高分抵消，“满足预期”不是正式语义验收 PASS。

**执行状态另列**：未观察到阶段、待评价、评价中、已完成、评价失败、已停用／取消及其
原因独立于分数。任何部分结果只对已核对维度成立；范围删减、标准／来源变化或不同
评价配置均须披露，只有可比范围才展示分数差值。记录“最早可观察缺口”，没有反事实
或对照证据时不宣称根因已证实；最终失败仍沿既有四类归因。

#### 复用与相邻分工

源码核对基线为 `68cc310`。现有版本化工作空间、工作树、Host 观察快照和只读执行可
作为基础；`cli.evaluate` 仍要求 `handoff_ready`，`check-unit` 是原生产者自查，尚无
三类阶段诊断及其开关。新增阶段用途必须保持上述正式验收与自查含义，不通过放宽
最终入口资格实现复用。具体事件／字段命名在实施交接中确定，不在此预设新表、新服务
或新编排框架。证据与入口见[可行性评估 §2、§6](../research/2026-11-02-modeling-process-evaluation-feasibility.md)。

001 提供自然回合控制、执行身份与观察点；002 提供内容版本与引用；003 仍承担完整
建模和跨单元整合；004 提供实际应用与治理读回；006 继续拥有正式独立语义验收；
007 提供运行可观察性与完整成本比较；010 提供 CQ 内容和版本。011 只观察这些成果，
不降低它们的完成标准，不把诊断结论写回成业务事实。

**问题与目标**：具有动态委派工具不等于默认团队已经分工。本轮 Demo 的 work-plan.units
为空，CQ 来源于旧公开种子，切片/建模/整合由同一根职责承担；多次执行和独立评分不能
证明专职协同。新任务应实际使用 Coordinator、Competency Question、Modeling 的独立
生产职责与执行上下文，并在复杂场景按业务范围扩展 Modeler 和父级协调；不要求一个视角、
表或 Ontology 对应一个 Agent。

例如模型目录与凭证额度两个切片：Coordinator 确定范围、共享模型身份及整合责任；CQ
专职检查全景、切片和跨切片公开问题；Modeler 分别提出模型表达，发现“回放是否重新扣额”
与共享额度的冲突时回到责任方和必要的业务澄清。Coordinator 不能替缺席的 CQ/Modeler
偷偷完成其成果，评分 Agent 也不能充作生产 CQ。

#### 功能要求

- **F1 — 新任务默认专职分工。** 本需求交付后的正常新 v5 建模任务使用版本化专职团队
  合同；Coordinator 负责目标/范围、切片、共享协调及整合，CQ 负责问题制作与维护，
  Modeling 负责来源理解、语义表达及本责任范围读回自查。三类职责有各自可核对的作者、
  模型绑定、提示/工具、原生执行和成果；小任务可各使用一个实例，已有 CQ 可由专职 CQ
  复核/复用，不为人数重复制题。不得自动降级为根 Agent 包办。独立评价不计作生产分工。
- **F2 — 身份与专业合同。** 分清 role、actor、工作单元、业务切片、原生执行和平台资源。
  工作树可继续递归；CQ 工作覆盖全景/多个切片，不被伪装成一个业务切片。不同角色可选
  同一模型，仍须具有独立上下文及最小必要工具；缺模型绑定/角色包给可修正配置反馈，
  不静默沿用 modeling 配置，也不将旧完整包中不适用的 Runner/Delivery 指令直接挂载。
- **F3 — 范围及切片由 Coordinator 实际负责。** 依据原文和目标维护有版本的范围/分派
  方案、共享定义责任、依赖、未分配部分及整合义务；允许暂定、并行补充与局部 HITL。
  Coordinator 不以已有 CQ、现有图或子级数量限定完整业务范围，不替业务负责人确认未知。
  平台只执行显式计划和依赖，不按文件/表数裁定业务切片或 Ontology 拓扑。
- **F4 — CQ 制作、消费与评价分离。** CQ 专职复用 v4 的全景→按实际切片补充/跨切片
  覆盖、来源支撑、确认口径及版本维护职责；承接 R5.0-010 用户题库与可选答案。
  产出任务可消费的公开 CQ 版本，记录已有题的复用/修订、新增、未知和覆盖缺口，不把
  公开 draft 标准当业务事实，也不以题量或自生答案自证完整。公开 CQ 制作、CQ 过程
  评分、私有验收标准准备及独立 Judge 是不同用途。需要隐藏题时沿获准私有准备/审核/
  冻结入口及独立上下文；生产 CQ 不读隐藏题/答案/评分，不因沿用同一角色名而混用会话。
- **F5 — 真实交接与渐进推进。** 角色提交类型化成果和精确对象版本/摘要，由程序沿原
  工作单元投递并记录读取/消费；普通回复、已读、业务依赖满足、已应用和已验收分开。
  初步范围足以分派时即可让 CQ 与 Modeler 并行；公共 CQ 未完成不妨碍有界来源分析。
  安全应用只依赖其真正需要的当前业务决定、输入与执行合同，不恢复“所有 CQ/切片都
  完成才允许任何推进”的机械门。正式验收沿原冻结目标；新增公开题不暗改隐藏分母。
- **F6 — 语义作者与整合责任。** 每份 Modeler 候选/显式变更具有责任单元、来源、公共
  CQ/共享定义依赖及实际模型基线。Coordinator 负责选择、共同身份、关系衔接、未分配
  范围和整体约束；可提出有依据的语义决定，但不得在整合时无记录地重写成员业务正文。
  新/改语义交原责任 Modeler（共享内容交明确维护者）修订。程序按精确引用组合并保留
  各项作者，再使用现有统一图/显式变更、编译、单次原子 apply；不恢复 Protocol LLM
  翻译、技术审批或模型 dry-run。根级统一调度应用，实际写入由 Host 执行。
- **F7 — 共享定义与跨候选引用。** 委派前/后可明确共享维护者及使用方，不能以同名自动
  合并或为冲突另造同义副本。跨成果稳定定位与逻辑 item/change ID 分开；同一原生身份
  的冲突修改必须协调，不能 last-write-wins。候选内 ID 碰撞、共享引用、分批回执及显式
  Ontology 放置由确定性适配保持可追踪，技术原生 ID 只取实际读取/回执，不猜 IRI 后缀。
  未解决冲突只挡受影响的不安全内容，独立安全范围可继续。
- **F8 — 版本与局部重入。** 来源、范围、CQ、共享定义或实际模型变化时，标明旧成果基线
  和影响候选，Agent 判断语义影响；受影响原责任单元/祖先重入，未变兄弟内容复用。
  busy 回合自然结束后再消费变化；过期成果保留，不能覆盖新版本或释放已撤回批准。
  尚未分派、待回复、局部草案与真实缺口均不冒充已完成。进度变化不自动触发全团队返工。
- **F9 — 自查及整体交接。** 应用回执按原贡献定位回 Modeler，安排其责任范围的实际治理
  读回；CQ 专职更新公开问题支撑与未知，Coordinator 检查整体范围和跨单元约束。
  复用同基线有效检查；模型修订改变时按责任范围有界复核，保留未变候选，不强迫每名
  成员重复通读全模型。原单元 self-check、Coordinator 整合检查及独立语义验收分开。
  最终 handoff 绑定被消费的角色成果、未决项和实际修订，不以所有子级 ready 代替整体判断。
- **F10 — 确定性调度与可恢复失败。** 复用工作树、消息/版本材料、HITL、原生执行登记、
  检查点与 Host。程序根据工作类型/角色合同路由任务，不依赖根 Agent 自愿先 delegate
  才激活必需职责；同一对象有确定责任人。角色格式错、依赖缺失、陈旧结果、临时调用失败
  给准确反馈，保留当前目标和可重试身份；不以固定角色数量/轮数制造不可恢复 run 拒绝。
  依赖环和成员不可用暴露责任和待补决定，不能无限互等或由 Coordinator 冒名补产物。
- **F11 — 自然控制、恢复与成本。** 所有生产/私有准备/独立活动沿真实授权及同一预算，
  计量保留实际 role/actor/purpose/model；未知不补零。暂停/停止/额度关闭等待当前原生
  回合自然结束，所有在途活动停稳才声明生效；恢复复用已完成结果，未知执行/写入先对账，
  不用更换角色/线程/run 重置额度或重放 apply。首次真实 Modeler 来源分析须遵守授权后
  20 分钟启动要求：prepare 即登记并优先准入获准原始范围的 Modeler intake，不依赖
  Coordinator/CQ 首个结果；单并发槽也优先满足该真实启动。intake 提取原文业务命题/
  未知，不预设切片或申请 apply，后续按 Coordinator 确切范围版本接续并复用。仅创建
  会话、技术 preflight 或空调用不算真实语义开始。Host 外部用量仍单列。
- **F12 — 兼容与入口一致性。** 新默认入口、Task/模型配置、冻结角色包、工具、CLI、工作树/
  进度和文档必须一起接线；仅新增提示不算交付。新专职合同显式版本化，旧 run 按原绑定
  接续，不用新角色接管旧 native context，不自动重写旧 Task/检查点/报告。只有用户显式
  选择其他模式时才可用于新任务，状态须披露；本需求不启动或迁移任何 run。
- **F13 — 原则与范围。** 专业职责分离是本次新默认的目标调整，优先于旧设计允许同一
  Agent 合并这些生产职责的表述；工作单元/视角/Ontology/Agent 不一一对应、按需有界
  推理和工作空间权威仍保留。程序不替代语义裁决，不增常驻 Delivery、通用角色插件框架、
  新业务 API/领域特例、全局事务、多机调度、自动低分修模或额外的固定角色链完成门。
