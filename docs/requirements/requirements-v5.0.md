## 目标与边界

例如，安装与返修共同使用“验收”定义，返修的年度口径需要用户澄清。系统应让安装继续推进，将未决项及影响保存在共同业务记录中；答复后只重审适用部分。若模型应用时发生超时，按原提交身份对账。更换 Agent 或重启工作进程后，能从记录恢复；最终仍由独立侧读取冻结的实际模型评价。

重写范围包括 Team 的流程组织、Agent 执行入口、业务工作状态、角色／工具交接、必要的任务控制与观察，以及新方法的实际采用。允许重划现有模块边界；客户业务概念继续是本体数据，不能为参考场景加入专有平台逻辑。

现有 FastAPI／MCP、PostgreSQL／RDF、模型表示、确定性应用与治理检索按实际适配需要复用。v5 不以重写整个语义平台、通用工作流产品、可视化拖拽编辑器、多机调度、旧原生会话热迁、SHACL／OWL 推理或通用规则引擎为默认目标。

方法中的 S0—S9、Q、R、C1、C2 为活动与导航，不是固定角色数、模型调用数或不可跳过的机械阶段。控制流程必须允许有依据的合并、回退、局部等待和重入。

### R5.0-001 可控编排与有界 Agent 执行

**目标**：将流程控制变为可检查、可测试的程序行为；Agent 在有界目标和权限下作语义判断。

- **F1** 明确执行位置、正在处理的工作单元、下一项依赖、首阻塞与所需输入；程序负责已确定的路由、等待、结果归属和恢复，Agent 提供需要推理的判断及理由。
- **F2** 在 LangGraph 编排下选择有界 Agent 执行层；可复用 Codex／DSH，或采用 OpenAI Agents SDK、Deep Agents、`create_agent` 等库，不要求继承旧适配器。输入、工具与输出有明确合同，执行器内部会话与外层业务流程职责分开。实际 provider、模型、effort、工具行为及用量必须核对，不因 SDK 默认值静默改变配置。
- **F3** 每个有长等待需求的工作单元可独立暂停与接续；无关工作继续。程序不因普通心跳、日志增长或计时到期无条件唤醒模型。
- **F4** 保留用户输入、暂停／停止、预算变化与真实关键错误的及时响应。框架暂停与云端请求是否结束分别记录；已在途结果和不确定写入不得丢失。
- **F5** 执行控制与业务状态分离；错误、字段缺失、暂时等待和技术运行上限允许准确修正及继续，不因角色数量或固定尝试数永久终止目标。
- **F6** 不保留常驻 Delivery LLM 作为机械推进的必需条件；用户沟通和确需判断的协调仍可由有界助手承担。该项是 v5 对旧职责合同的目标调整，实施时同步活跃提示与工具入口。

**验收**：局部等待不阻塞无关单元；进程恢复、用户控制及预算行为有真实状态证据；增加一种可恢复结果或修改一个重入点时，改动集中在对应流程／合同，不要求连带修改整个运行栈。机制测试与真实 Agent 采用分别报告。

<a id="r5-0-002"></a>

### R5.0-002 持续语义工作空间

**目标**：业务理解独立于聊天、原生会话和 run 存续；跨 Agent 的协作依据是可定位内容。

- **F1** 覆盖方法 §4 的最小对象：材料单元及修订、完整业务命题、解释与决定、语义定义／变更、业务工作单元、派生主题与摘要引用。CQ、支撑、依赖、复用和模型对应保持各自含义。
- **F2** 对象具有稳定身份、内容版本与更新基线；并发冲突返回实际差异，支持重读及语义合并，不能最后写入覆盖或永久终止 run。
- **F3** 材料审阅、业务认知、表达覆盖、实际应用、工作、验收与当前适用性分别记录。已知未表达、未审阅、无法读取和业务未知不得相互冒充。
- **F4** 工作空间只保存候选改变与实际模型引用，不另维护可随意编辑的完整已应用本体。已应用以平台事实为准，独立验收以绑定报告为准。
- **F5** 原材料定位尽量由工具保留；Agent 维护命题、解释和表达的对应及处置。不恢复逐字段 Evidence 包或整套旧 Lineage 服务。
- **F6** 跨会话按本层目标、直接子单元返回、相关定义和未决项接续；按权限读取，必要时下钻原文，不强制加载全项目历史。

**验收**：同一含义的多轮修订和冲突可定位；换会话不丢判断及实际结果；来源记录、候选、应用和验收不会互相升级状态。工作空间写入与流程 checkpoint 不同先后失败时均不倒写旧业务内容。

<a id="r5-0-003"></a>

### R5.0-003 递归工作单元与完整建模循环

**目标**：实际采用方法设计 §5—9、§17—18，而不是仅更新角色提示。

- **F1** 从业务目标向下拆解，并从原材料向上补充；工作单元不等于文件、表、Ontology、Agent 或权限边界。父级保留未分配范围，承担直接子级组合与本层约束。
- **F2** 保留每项命题有意义的条件、例外、否定、量词、时间、模态与上下文；分开观察和解释，但不强制两轮调用。范围内材料有审阅记录，每项有业务意义的命题有可追踪去向。
- **F3** 按身份连续性、区分性情境、上下文和引用需求判断复用、局部限制、新含义、共享修改、未知或冲突；名字和相似度不决定等价。
- **F4** 子单元有明确对外说明与实际引用；父级按需读取并主动核对整体规则。局部通过、图连通或子任务全部完成不证明组合成立或项目完整。
- **F5** 共享修改及澄清有明确责任；同一待定含义复用共同未决项，答复只解决其实际适用范围。依赖遍历给出影响候选，语义影响由 Agent 判断。
- **F6** 新增、修订、撤回资料或决定通过 S9 回到准确步骤，复用未变化的有效成果；材料撤回不自动证明业务事实为假。局部推进可先开始，但未审阅／已知未交付内容不得记为完整收口。

**验收**：至少两个相互依赖单元、共享定义、范围内低频例外、一次局部澄清和一次资料变化；另验证递归父级责任及跨单元合计约束。具体语义以获准材料为准，不由测试代码发明业务答案。

<a id="r5-0-004"></a>

### R5.0-004 应用、对账与受治理读取接续

**目标**：新编排复用已有应用能力，并保持执行结果与语义判断边界。

- **F1** 沿 R4.3-024／025 接收明确变更意图，由程序编译、绑定执行字段、应用并返回可定位结果；不恢复独立模型 dry-run 或 Protocol 翻译审批。
- **F2** 维持真实资源身份、授权、租约／修订与现有原子边界。跨 Batch／Ontology／存储不声称全局事务；相关变更无法安全分组时保留准确缺口。
- **F3** 区分未写入、已应用及结果未知；执行重试和框架恢复复用原操作身份与回执。应用已成功而 checkpoint 未保存时不重复成功应用；未知结果先 R 对账。
- **F4** S7 与独立验收通过真实受治理接口读取实际模型，分别定位捕获、理解、表达和检索问题。工作笔记、候选或摘要不能补成模型实际读不到的答案。
- **F5** 实际模型被其他客户端修改时，刷新受影响读取与候选基线；缺少业务理由保留待核对，不能编造确认历史。

**验收**：覆盖成功回执丢失、结果未知、跨批部分成功、基线漂移与召回不完整；成功效果不重复，失败层不混淆。仅确定性回归不替代真实平台和独立语义证据。

<a id="r5-0-005"></a>

### R5.0-005 分层总览与增量认知维护

**目标**：提供从整体到局部的业务认知入口，支持续接、定位变化与消费。

- **F1** 总览按业务结构组织，保留共享与跨主题引用、原定义／原材料入口；社区发现仅为可重建辅助视图，不决定业务分类、身份或授权。
- **F2** 关键未知、冲突、例外和未完成范围可展开到实际内容；不因低频、摘要长度或未进社区而遗漏。父级不拼接全部下层分析。
- **F3** 在获准范围内生成摘要，区分生产、用户、消费者和验收视图；消费者不把未应用候选当作实际模型，生产不得读取隐藏验收材料。
- **F4** 相关材料、决定、模型、工作、验收和权限变化影响摘要适用性；按需合并刷新。各自截止点和未刷新范围可见，生成期间变化的结果不冒称当前。
- **F5** 摘要用于导航，精确判断仍读取实际依据；摘要不能写回形成自证事实。摘要不可用时允许安全建模和直接模型消费继续，但不能宣称包含总览的完整交付已完成。

**验收**：共享定义跨主题变化、来源撤回、孤立内容、生成中输入变化和权限变化均有准确反映；摘要辅助消费与模型直接消费分开评价。

<a id="r5-0-006"></a>

### R5.0-006 独立语义验收与冻结交接

**目标**：新流程不降低生产与评价的独立性，并支持大型业务分层评价。

- **F1** 生产前沿既有规则完成独立题集准备／冻结；生产只获得公开投影。正式验收绑定确切模型、范围、题集、依据、读取条件和时点。
- **F2** 独立侧使用自己的输入、凭据／工具范围和运行上下文，不能创建、继续或修复被验收的 run；生产状态、摘要和共享聊天不能成为隐藏答案通道。
- **F3** 大型业务按单元有界评价，父级核对覆盖、实际对外定义与跨单元整体规则；不只汇总局部分数，也不强制单个评价上下文通读全部材料。
- **F4** 同范围遗漏覆盖由独立侧根据原始依据追加题集并在执行前冻结，保留原题集／报告；新失败或未验证范围不能被旧 PASS 遮盖。
- **F5** 修复仅使用获准公开反馈及真实业务依据，沿原授权推进，产生新的实际验收目标。捕获／解释／表达定位与四类最终失败分类保持区别。

**验收**：隐藏材料不流回生产；评价无修改能力；旧报告、追加报告和新模型结论绑定准确；模型直接消费与摘要辅助消费分别报告，不能互相代替。

<a id="r5-0-007"></a>

### R5.0-007 迁移、可观察性与效果验证

**目标**：将 v5 作为新的清晰执行路径交付，同时保留业务连续性和可核对证据。

- **F1** 新旧入口切换有明确边界。旧模型、候选、地图和决定只按可核对的实际对应导入；缺历史依据时明确披露，不伪造命题。旧 run／原验收原件保持。
- **F2** 不将旧 Codex／DSH 原生会话伪装成可在新 SDK 中无缝恢复；新流程继承获准业务结果及未完成工作，不借新运行身份重置预算或重复已确认应用。
- **F3** 地图、卡片和摘要逐步变成工作空间的引用／投影；主写入口切换后避免长期双写。对挂起任务保留其流程和状态版本，处理不相容升级。
- **F4** 当前单元、方法活动、等待对象、首阻塞、实际结果、依据引用和授权边界可观察。采用既有四类失败归因；工程状态不升级为模型质量结论。
- **F5** 沿既有任务账本累计生产、评价、失败、恢复及获准辅助调用；外部 Host 原始用量单列，不计入任务金额成本或预算扣减。缺失用量不补零，研发／复盘另列。
- **F6** 在同业务范围、材料、模型配置和评价条件下比较模型往返、上下文、用量、墙钟、宿主介入与质量，记录成本转移；用实际修改演练评价维护性，不以节点数、缓存率或总代码行数作为收益证明。

**验收**：当前入口切换和历史读取成立；依赖版本可复现；暂停／恢复及证据边界通过；净成本、语义质量和维护性各自有证据，缺一项按对应范围保留未验证。
