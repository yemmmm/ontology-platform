## 实际缺口与窄修复

失败层均为 `platform-contract`／prompt-contract，不据此判模型质量失败。

1. **真实治理返回被误拒绝。** v5 MCP 读取工具返回成功 REST 正文，含 scope／修订，
   不含合成 `ok` 字段；新框架却要求 `ok=true`。保留真实成功工具、无错误和准确修订
   核对，去除不存在的成功标记要求；显式失败 envelope 仍被拒绝。T0 复核：实际读取及
   绑定保护有必要，特定 envelope 标记不构成独立不变量；原工具状态与修订校验已覆盖风险。
2. **后续变更缺少可消费引用。** Host 保存了实际资源和回执位置，但 snapshot 没有提供
   现有绑定解析器接受的 artifact/path。增加 `resource_refs`，由 Host 返回精确引用，
   沿原编译器解析；不让 Agent 猜路径、UUID 或重建已应用定义。
3. **暂停覆盖首阻塞。** 返回格式错误后，下一回合准入因暂停退出，会把原纠正反馈替换成
   暂停错误。暂停／停止保留已有 issue，状态和控制视图仍显示停稳情况。
4. **重试自查的快照身份冲突。** 真实 resume 时，新快照投影与旧 `target:0` 内容不同，
   固定身份配 expected_revision=0 导致版本冲突。快照身份加入内容摘要，复用相同内容，
   不同内容保留不同引用；不覆盖历史目标或既有自查依据。
5. **旧资源处置标签误报任务失败。** 原收尾已确认会话终态、无在途 Attempt、保留非空
   模型并撤销临时权限，但旧 `PlatformScope` 从旧 Runner 的 `terminal_results` 推导
   `failed-written-retained`；v5 的生产／评价结论另存。v5 返回中改为中性
   `written-retained`，保留 `legacy_scope_disposition`，不改旧共享清理器、资源动作或
   失败／语义裁决。原现场收尾回执完整保留；标签修正由真实 backend 环境工程测试验证，
   不冒称为新代码重新执行过整段在线清理。
