# v4.3 建模效率增量设计

权威范围：[v4.3](../../requirements/requirements-v4.3.md)。基线 `157c8be`，工作树干净。
本设计覆盖 R4.3-001–007，保留完整 27 题范围、原评分、未知与公开／隐藏隔离。
用户授权设计、审阅、开发与测试；既有真实建模暂停指令保持，不消耗剩余四次额度。
开发和独立功能测试可以关闭工程交付，120 分钟真实完整 PASS 仍单独待证。

## 当前问题与最小变更

1. **R4.3-001：同一轮计时。** 复用 R4.0-021 的运行记录。记录输入就绪且获准开始的
   UTC 时点、资料／题池／配置／代码身份，以及完整独立 PASS 和收尾时点。
   修模、重验及 fresh start 不重置该轮起点。记录阶段区间、平台故障及人工等待；区间按
   墙钟并集计算，只有有证据阻断关键路径的故障可以另报扣除值，正常推理／调度不扣除。
   缺少结束 PASS、清理或活动证据时保持未知／未完成，不伪造效率达标。采用本地运行
   记录与最小确定性汇总工具，不增加逐工具打点或超时硬门。
2. **R4.3-002／003：按已批准计划连续执行。** 复用 unified materialization plan、
   `plan_ref`、projection digest、现有批准及 staged batch forwarder。提供 Protocol 可调用
   的按引用入口：Runner 读取本轮完整不可变计划，生成已有格式的请求并走现有审核、
   dry-run、apply、实际读回路径。每批在前批完成后的当前 workspace version 上 dry-run。
   已批准多个依赖计划可以连续执行，成功回执不要求 Coordinator 再批准同一内容。
   计划或候选变化必须重新绑定批准；错误／漂移停止受影响依赖并返回可修正定位。
   已成功提交不重放，未知写入先对账；不新增跨批事务或自行推断业务依赖。
   批量按现有部署上限、命令体积及真实依赖形成，不设置固定批次数。
   一批对应一份已批准 `plan_ref`；执行工具不从已批准 projection 中再切子批，避免改变
   当前严格批准内容。Protocol 在批准前依据真实上限形成依赖有序的计划列表。
   当前 `get_modeling_context` 只证明版本／数量，连续执行回执明确资源读回尚待完成；
   Protocol 继续既有受治理完整分页读取及引用关联检查，之后才能报告实际业务链读回。
3. **R4.3-003：关联扫描引用。** 在当前 Protocol mechanics 路径接受本轮保留读取引用，
   由 Runner／工具解析受治理响应并传给现有 `inspect_model_associations`，不让 Agent 转录
   全部 bindings。保留页面、定位、摘要、模型绑定；缺页维持 PARTIAL，篡改／失效引用
   给出可操作反馈。仅允许本轮已观察且获准的读取，不把任意文件路径作为读取权限。
4. **R4.3-004：完整小链及早期反馈。** 在 Modeling、Coordinator、Protocol 角色和方法
   中明确按候选身份对账定义、关系、共享身份、跨 Ontology 目标、依赖与明确不落地项。
   工具可核对确定性候选／计划覆盖，业务意义由 Agent 判定。已完整小链可以先执行，
   首条安全读回小链通过现有公开反馈入口取得少量问题的真实反馈；隐藏题不进入生产。
   终态前核对实际完成与缺口，不以候选数或成功回执代替模型质量。
5. **R4.3-005：按需唤醒。** `delivery.py` 继续程序观察与保存原始状态，比较有意义的
   决策投影：运行／操作生命周期、第一失败层、待办内容及版本、交付／审核／冻结／交接
   成果、未完成请求和修复结果。心跳、字节数、日志游标及无关计数变化不进入唤醒身份。
   不能只用顶层 status 过滤；新问题同数量或内容版本变化也必须送达。用户输入保持现有
   steer／中断通道。条件满足后由 Delivery 在已有授权内及时冻结或交接，不自动代作
   尚未授权的业务决定。记录观察与实际唤醒分别计数，不新增事件总线。
6. **R4.3-006：冻结业务原文读取。** 初始 Judge packet 改为资料引用清单，包含本轮
   批次／freeze 身份、来源、定位、content digest、review version 及每题关联。
   Runner 从既有冻结获准业务依据构造只读内容注册表（复用已有冻结副本，不读取当前
   已变化源文件）；原文从初始 prompt 移出，但完整副本仍保留在 Host。
   Judge 子进程仅新增受限原文读取工具，按内容身份读取该注册表；无文件系统、在线
   数据库或平台能力。读过的内容可复用、可重读、可按定位读取；不同版本不可混淆。
   校验同步覆盖 packet、内容摘要、读取 receipts 与 Judge 报告：PASS 必须引用该题
   实际读到的相关资料，读取不足不能只凭 manifest 通过。工具失败可修正且未完成明确。
   旧 packet 仍可按其内嵌合同验证，新的引用合同明确版本，不仅删去 `content` 字段。
7. **R4.3-007：提前去重和分组。** 已有 `_v3_judge_lossless_transport` 对每份 Judge
   输入主动编码，正文按内容身份一次保留，逐题实际响应 metadata／完整性／引用保持。
   复用 `_cq_judge_input_packets` 按实际序列化体积提前分组，软目标低于原生硬上限；
   单题超软目标可以完整单组，超硬限明确未完成。各组有序覆盖冻结完整分母并披露组数、
   原始／去重／分组字节量。业务资料与平台响应分别统计；不新增在线平台读取能力。
   本阶段不实施并行／流水，不改变同源续接锁。

## 代码与权限边界

- 生产引用与执行：`runner.py`、`staged_decisions.py`、`protocol_retrieval_mcp.py`、
  `protocol_mechanics.py` 及相关原生能力 schema／mount；所有写入走既有 gate。
- Delivery：`delivery.py`、当前 Host 状态合同及 Delivery 提示／Skill。
- Judge：`competency_questions.py`、`acceptance_runtime.py`、`__main__.py`、
  `runtimes/codex.py`、只读原文 facade、Judge 提示／Skill。
- 不修改业务平台 API、RDF 存储、前端、数据库 schema 或评分规则；代码发现必要接口
  增量须同步相关工具合同。GitNexus 当前索引落后 246 提交，以当前调用点检查代替。

## 验证与交付

[共享测试计划](../test-plans/2026-10-09-v4-3-modeling-efficiency-test-plan.md) 分开记录
设计审阅、开发测试、独立功能验收和真实性能验收。先独立设计审阅再实施。
工程测试使用本地受限 MCP／原生运行 fixture 与必要真实依赖，禁止启动生产建模。
若修改 backend／frontend 则执行仓库全套及 systemd 重启／健康检查；仅 Team runtime
变更运行 Team 回归，当前 application 不因文档／提示或隔离工具变化而重启。
真实性能测试待恢复授权后按完整范围运行；本轮绝不将工程 PASS 改写为 120 分钟达标。

## 实现与验证结果

2026-10-09 设计独立审阅 Round 1 PASS；工程独立功能验收 Round 2 PASS，首轮三项
失败及修复保留在同一共享测试计划。全 Team 2580 passed、11 skipped、316 subtests
passed（198.92 秒）；独立 native／边界复验 31 passed、12 subtests passed。
本阶段采用既有 Runner capability／Report Sink，未增加平台 API、数据库 schema 或
并行验收框架。建模 context 只证明版本及计数，真实资源读回仍由 Protocol 沿既有治理
分页读取完成；确定性覆盖和计时工具不作语义判定。

真实生产／只读验收／修复运行仍暂停，未消耗剩余四次启动额度。完整 27 题语义 PASS
与端到端 ≤120 分钟未执行，v4.3 总体验收保持 PARTIAL；R007 并行／流水属于后续方向。
