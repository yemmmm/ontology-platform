# v4.1 项目建模工作台设计

权威范围：[v4.1 全部条目](../../requirements/requirements-v4.1.md)。本设计细化其网页交付，
不重定义 v4 模型质量与独立验收结论。用户已授权实现；不另设产品设计批准门。

## 目标、布局与边界

项目为主工作空间，Ontology 为可选模型筛选。左侧按总览、建模工作、语义模型、检索与验证、
项目管理组织导航；首页项目列表可直接进入工作区，无 Ontology 也可读 Brief、CQ、地图和运行。
模型浏览为列表/选中详情/关联图，七视角为同一身份的筛选和阅读入口。保留 Class、Entity、
GraphSet 的次级技术入口；旧 rules 路由迁往业务规则语义阅读，search 迁往 Context Query。

视觉沿用仓库组件、字体和样式变量：密度适中的表格、清晰的标签、克制的强调色；
来源/时点/范围放在摘要旁，技术信息用详情展开。桌面采用列表与详情分栏，小屏上下排列。
按钮有可见 focus，表单有 label；加载、错误、未接入、缺少内容、禁止访问分别表达。
面向用户的主要文案为简洁中文，遵循现有语言切换机制。

不增加执行引擎、脚本执行、API 调试、业务行存储、连接管理、自动 SQL 改写、调度/恢复平台。
业务角色、权限角色、Agent 角色分开；普通用户仍使用 Key，网页沿用管理员登录。

## 最小 API 与文件接入

新增项目级固定只读入口（建议 `/projects/{project_id}/workbench` 与其 run 详情子资源），
由薄路由、专用读取服务实现。响应封套包括项目/run/产物身份、版本或内容摘要、源路径标识、
源记录时点、observed_at、范围、limitations、availability；不存在/无数据/失败/未接入分别表达。
只读服务不得实例化 Runner、创建 run、发 FIFO、恢复、清理、写文件、改 CQ 或执行模型调用。

固定根为本仓库 `workspaces/modeling-runs`，服务端配置/实现决定；请求只能选已绑定 run ID，
不能提供文件路径或根路径。按 state.platform_binding、历史 state.cleanup.scope、
production handoff.scope_binding 里的显式 project_id 匹配，
缺失或冲突则不挂到项目，不能从任务名、目录名或“最近运行”猜项目。枚举有上界并明确完整性；
历史 run 可选，不自动把旧 run 作为当前。未知项目/无权 run 不泄露跨项目身份。

当前 Runner 未在生产交接前持久公开项目绑定，需要一处最小补充：在现有 state.json 的
写入中附 platform_binding，仅由已准备 PlatformScope 的 project_id/ontology_ids 生成，
不含 Key、地址、源资料或其他私有配置；prepare 完成后下一次实际状态（含 RUNNING）即有绑定。
create 模式也必须使用平台实际返回身份，不能使用尚未准备的请求值猜测。
不改状态机、启动依赖、额度、恢复合同或已有保留 run；无绑定旧 run 标为无法关联。
所有可用显式绑定有冲突时返回绑定问题而非任取一项。增加尚无 handoff/cleanup 的 RUNNING 测试。

协同产物首版仅组织/相应项目管理员读取，普通 read/model Key 拒绝此管理投影。
这是复用现有主体权限的网页管理接入，不扩展普通生产 Agent 权限。模型检索仍用现有语义授权。
生产可见内容仅读取 Coordinator 地图、已发布候选/计划/回执、CQ public projection、公开反馈、
宿主已记录摘要/计时/授权、公开验收结果和隐藏分组的获准聚合状态。私有 CQ、冻结题正文、
隐藏回答/答案点/诊断、源材料及凭据均不在此端点返回；隐藏详情不另建网页权限绕过。

逐种产物使用明确 schema 字段投影，不递归透传任意 JSON。文件名只来自固定类型目录，
不跟随符号链接到私有或外部文件。字段有来源才显示；原始 JSON、缓存、导出均不能绕过投影。
必要文件安全限制只保护实际外部文件边界，不给建模引入新硬门。
已有 `modeling_team.host_ops.get_run_status` 可复用只读事实提取，必须再筛掉 host-private 内容；
原函数不作为安全投影。backend 运行 cwd 为 backend，引用 repo 路径须据源码定位，不依赖 cwd。

报告保留原 verdict，另列适用性（已核实当前/历史/绑定未知/失效）。只有实际冻结、模型状态、
报告版本绑定均有证据才可称最新有效验收；缺失时不能降格假装已验证。未实现专项保持未验。
不能把 stale 报告拼成总体 PASS，也不把单题多个诊断重复计为多题失败。

检索复用 `/semantic/context:query` 的 project_id/scope_mode/ontology_ids、resource_types、
semantic_roles、match_cursor/context_cursor；权限过滤由服务端执行，关联上下文不被角色过滤。
详情与列表同一授权范围，错误和结果不泄露隐藏资源数量/桥接节点。
R4.0-005 业务规则是普通 instance + semantic_roles=rule，而旧 resource_type=rule 原专属
退役的 RuleDefinition 资源。规则视角使用语义角色，不新造或复用旧平台 kind；
Context Query 表单与 REST/MCP 类型枚举同步去除旧类型，旧请求准确报不支持，不能静默忽略。

## 旧规则联动退役

R4.0-022 在 v4.1-009 实施时一同交付必要退役范围：检查 REST 规则专用路由、MCP 注册、
canonical command/protocol 规则写路径、FactAudit Generate/Run rules、图层/统计和运行服务调用。
删除旧执行专用逻辑或显式不可用入口，不能仅关按钮；历史模型/数据库记录不删除。
保留 `rule_definition` 语义注解、新业务规则实体、普通数据集加载/查询、SHACL 和 OWL。
正常产品、目录、提示与当前接口文档同步，历史交付记录不改写。测试从旧 PASS 迁到退役合同，
共享测试保留；不能将仍可执行的旧规则作为允许的残留。

## 交付、评审与验证

独立 plan_reviewer 对本设计/测试计划核对实际仓库，只有证据支持的 Critical/High 才阻止开发。
开发分前端和最小后端接入/退役，文件归属独立；稳定后 requirement_tester 独立验收，
有失败由开发修复后再验，不改低验收口径。主 Agent 维护交付记录与最终逐条证据矩阵。
运行 frontend build、全 Playwright；backend 行为变更补测试并跑全 pytest。
稳定后重启 ontology-platform.service，核对 active、health 和前端，再验证受影响接口。
记录浏览器桌面/小屏视觉和真实 REST 证据；模型质量仍以原 v4 验收为准。
不启动新的 semantic start；fixture 为确定性功能测试，不宣称新的 L1/L2/L3。
