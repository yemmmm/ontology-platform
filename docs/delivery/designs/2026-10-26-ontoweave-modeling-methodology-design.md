## 1. 设计结论与目标

推荐以持续存在的**语义工作空间**组织建模。工作空间记录业务范围、从材料获得的命题、对命题作出的解释与决定、待解决问题，以及这些内容与实际模型的对应。人和 Agent 围绕同一份可定位的业务认知协作。

主线是：

> 界定业务目标 → 双向拆解业务与材料 → 捕获完整命题 → 解释并对齐语义 → 组装局部业务链与共享定义 → 应用和验证 → 根据新信息持续修订。

这是一组可交错的分析活动。分层总览在过程中持续形成，为理解全局、选择下一步和恢复工作提供入口。领域分析、模型表达、应用结果、验收结果分别有明确依据。

本轮目标：

| 编号 | 目标与可观察结果 |
| --- | --- |
| F1 | 大型业务有可解释的递归分解结构，每层责任、切分依据、对外含义、跨单元依赖和未处理范围可见。 |
| F2 | 范围内每项有业务意义的命题及其条件、例外、否定、时间与口径都有交付去向；能识别发生在捕获之前和表达之后的遗漏。 |
| F3 | 用业务可区分性控制粒度，准确处理同义、异义、局部限制、分类与实例。 |
| F4 | 多轮、多 Agent 对同一业务判断的修改可定位，已确认与未确认含义、目标表达与实际应用不会相互冒充。 |
| F5 | 局部结果能在全局业务链上衔接，跨单元整体规则有整合责任；条件、状态、身份和指标的跨边界差异及组合结论得到核对。 |
| F6 | 用户和获准 Agent 能从分层总览逐步深入实际内容，关键未知和跨主题影响不会被摘要掩盖。 |
| F7 | 新增、修订、撤回材料或业务决定后，能够定位并重审受影响内容，复用未变化的有效工作。 |
| F8 | 模型通过真实受治理读取及独立语义检验；捕获、理解、表达、检索、验收、运行故障可区分。 |

实现 effort 不参与本轮方案排序。仍评价语义损失、认知负担、重复状态、运行耗时和长期维护的可理解性；它们属于架构质量。有限输入和开放世界下无法证明绝对零遗漏，因此目标是明确覆盖边界、发现反例、定位损失并允许修正。

## 3. 总体结构与权威边界

~~~mermaid

    B --> C["双向分解与命题捕获"]
    C --> D["解释、身份对齐、粒度判断"]
    D --> E["局部业务链与共享语义整合"]
    E --> F["显式模型变更与确定性应用"]
    F --> G["当前实际语义模型"]
    G --> H["受治理读取与业务验证"]

    G --> I
    H --> I
    I -->|"导航到原记录；不构成业务依据"| C
    J["独立冻结验收"] --> K["绑定范围与时点的验收结论"]
~~~

所有箭头表示明确授权范围内的读取或结果引用，不表示自动授予跨角色访问。独立验收数据只向获准用户视图提供允许的结论；隐藏内容不沿总览回流生产。

采用模块化边界，不预设微服务、通用工作流 DSL 或某个 Agent 框架：

| 边界 | 负责内容 | 明确不负责 |
| --- | --- | --- |
| 材料与范围 | 原始材料修订、获准范围、材料性质、已审阅范围 | 从 Schema 或样本自动确认客户规则。 |
| 语义工作空间 | 命题、解释、业务决定、工作单元、未决问题与对应关系 | 把意图当作已经写入的事实。 |
| 语义建模方法 | 分解、语义身份、粒度、规则与关系、跨单元解释 | 由确定性校验器代替业务判断。 |
| 模型应用与受治理读取 | 验证明确变更、实际应用、资源身份、当前模型查询 | 自动补造业务条件或用摘要改写模型。 |
| 分层认知投影 | 主题组织、范围内摘要、来源导航与新鲜度 | 决定业务真伪、建模完成或验收结果。 |
| 独立验收 | 基于冻结依据、实际读取与独立题目作语义裁决 | 生产、修复或修改被验收的模型。 |

### 3.1 单一含义对应明确状态，而不是多份“当前真相”

权威来源按问题分开：

- “材料说过什么”：不可变材料修订及其定位。
- “我们如何解释、谁确认”：业务解释和决定记录。
- “本次准备表达什么”：同一语义身份下的明确变更候选。
- “当前实际表达了什么”：受治理读取到的已应用模型。
- “验收证明了什么”：绑定模型、范围及题集的独立报告。

工作空间不另维护一份可任意编辑的完整已应用本体。未修改定义引用当前模型；修改部分保存基线引用、目标内容和决定。应用后的实际身份及回执回填引用。摘要和场景地图都是这些记录的视图，不再各自编辑一套定义或完成结论。

外部对模型的修改也作为实际变更被工作空间识别：刷新相关读取、比较受影响决定和候选。无法还原业务理由时标注“实际表达已变化，依据待核对”，不替其编造确认历史。

### 3.2 正交状态

| 维度 | 示例 | 权威维护者／依据 |
| --- | --- | --- |
| 范围与材料审阅 | 范围内、已确认排除；已审阅、未审阅、无法读取 | 业务范围决定；实际材料审阅记录。 |
| 业务认知 | 提议、已确认、明确未知、冲突、已否决／被替代 | 有依据的解释与业务决定；必要时业务负责人。 |
| 表达覆盖 | 未表达、部分表达、已表达及仍缺内容 | Modeling 对具体命题和候选／模型的核对。 |
| 应用 | 未提交、已应用、明确失败、结果待对账 | 平台应用记录；不是 Agent 自述。 |
| 工作 | 可继续、等待某项输入、需要重审、当前范围收口 | 工作依赖与承担者判断；不改变业务真伪。 |
| 验证与验收 | 未验证、自查发现、独立通过／不通过／待复核 | 分别引用自查与独立报告，不能相互升级。 |
| 当前适用性 | 当前、历史、待刷新、范围不完整 | 所引用材料、模型、工作记录与权限的实际变化。 |

一个未知可以被正确表达并通过“应保留未知”的验收，但该业务问题仍未知。一个已确认规则可能尚未表达。已应用也不意味着独立验收通过。这里的示例是状态维度，不要求把所有对象塞入同一个枚举或流程状态机。

## 4. 工作空间中的最小内容对象

对象独立于 Agent 会话和 run 存续；任务、run、应用与验收只引用它们。每个对象具有稳定身份，内容修订与原记录可定位，更新指出所基于的内容。一次简单工作可以同时形成多个对象，不要求多次模型调用或逐项审批。

| 内容对象 | 最少表达的含义 | 为什么需要 |
| --- | --- | --- |
| 材料单元 | 获准材料、修订、相关片段／段落／声明的定位、材料性质与可读范围 | 区分原文与模型改写，能检查未审阅范围及来源变化。 |
| 业务命题 | 材料中一个可独立判断的完整陈述、关联材料、必要上下文及限定条件 | 避免在直接挑选图节点时丢失知识。 |
| 解释与决定 | 命题可能含义、适用范围、选择或未决结论、依据、决定者、替代关系 | 区分材料陈述与认可的业务语义，保持多轮认知连续。 |
| 语义定义／变更 | 概念、关系、行为、规则等的业务含义；身份、范围、引用和目标表达 | 将业务判断准确连接到候选和实际模型，避免副本漂移。 |
| 业务工作单元 | 局部目标、父子责任、包含的命题和定义、对外使用说明、依赖、剩余问题、收口依据 | 形成可推进的大业务分解，使上层按需整合而不依赖完整下层聊天。 |
| 总览主题与摘要 | 主题成员、跨主题连接、可展开引用、当前内容与未决项的派生表达 | 支持从全局到局部的导航和共同理解。 |

CQ、材料支撑、工作依赖、概念复用、规则适用和模型对应使用不同关系含义，不混成一个泛化“related-to”。所有业务术语仍是客户模型的数据；这些对象只定义通用建模工作的组织方式。

来源支撑由工具保留已有材料定位，Agent 维护范围内命题与解释／表达的对应及处置；允许多个命题复用同一定义或支撑引用，不要求重新摘录全文、每个字段独立生成证据包、增加证据 Agent。该设计对当前仅在 handoff/map note 留定位的做法作明确目标扩展，见第 14 节；不恢复旧 Evidence/Lineage 整套产品合同。

## 5. 流程一：界定目标并双向拆解

### 5.1 从业务问题形成第一版结构

开始时明确本轮获准业务范围、材料、期望支持的使用方式和已有模型。允许存在未知，不把形成完整地图、完整原子命题集或完整层级摘要设为开始语义分析的前置门。

对大型业务按需要递归分析：

> 业务目标／结果 → 端到端场景 → 事件、状态变化与决策点 → 对象、角色、条件、规则、指标 → 必要的数据和接口映射。

这是提问顺序，不是强制固定树或七阶段。一个规则可以跨流程，一个概念可以被多个工作单元引用。初始公开 CQ 帮助定位问题，但不定义完整知识全集；独立隐藏题仍保持隔离。

每个工作单元写清：想解释什么、输入／触发与结果、相关主体和条件、与外部单元的连接、尚未明确的部分。对外使用说明至少提供所引用的稳定身份、输入与结果的含义、必要条件、适用范围与时间、例外作用域和未知，并指向可核对的定义；候选与已应用内容分别标明。使用方先读取这份说明与所需实际定义，不必先理解全部内部细节。它复用工作单元和语义定义引用，不另维护一份本体副本。

无法合理拆开的紧耦合规则共同分析；工作单元不等于一个 Ontology、文件、Agent 或权限边界。单元的划分与对外说明可以在推进中完善，不要求全项目所有说明齐备才开始局部分析。

### 5.2 从材料反向补充结构

按原始材料的可定位单元审阅，捕获获准范围内有业务意义的陈述，再映射到工作单元。无法归入现有结构的命题必须得到处置：补充既有单元、提出新单元、识别重复、保留疑问，或按实际授权确认其不在范围内。

不能因为当前 CQ 不问、图中无节点或主题聚类未收录，就排除某项范围内知识。材料目录与已审阅范围覆盖无命题区域，避免只检查已抽出的内容而漏掉从未进入候选的段落。材料单元分别说明“已审阅且有相关命题”“已审阅且无相关业务内容”“未审阅”“无法读取”或“有授权依据的范围外内容”；“未审阅”和“无法读取”不能充当无命题的结论。

范围内每项有业务意义的命题均须有可追踪去向：已表达、由已有定义覆盖、作为重复支持关联到同一含义、明确未知／冲突，或仍未交付的已知内容。分析过程中尚未判断的内容保留待分析状态。已有定义覆盖或重复支持须指向足以承载该命题限定条件的表达；不能只写“已有”就跳过核对。明确未知须确属业务含义未定，未读、未解释或已知未表达不能改记为未知。

重要性只影响处理顺序和验证深度，不决定知识是否保留；低频例外同样需要去向。不要求每句话生成节点，多个命题可以由同一完整定义或规则覆盖。覆盖按单元和材料分批核对，父级汇合子级覆盖引用与缺口，不要求同一上下文容纳全部项目知识。记录去向用于暴露交付缺口，不能把“已知未表达”或未获准保留的未决项自动升级为完整交付。

工作单元边界可以修订。若大量解释都需同时反复读取两个单元，优先检查切分是否割裂了一项完整业务判断；若一个单元内部存在互不依赖的决策，可以进一步分解。调整保留原有内容和引用，不重置已经有效的分析。

### 5.3 递归推进与有界协调责任

父单元负责本层目标、直接子单元之间的衔接、本层约束及未分配范围；子单元负责自身内部的分析与表达。子单元仍过大时按同一原则继续分解。每层都有明确的整合责任，但责任层级不规定 Agent 数量或 Ontology 数量；同一 Agent 可以分时承担多层职责。

| 时点 | 父单元与子单元交换的内容 | 判断边界 |
| --- | --- | --- |
| 分派与启动 | 父单元给出子单元目标、获准范围、相关材料、已有定义、上层适用约束和需要提供的对外结果。 | 只传本次工作所需内容；材料未分配部分仍留在父级范围记录中。 |
| 局部推进 | 子单元在内部运行 S1—S7；局部解释、表达和技术纠错在所属单元处理。 | 不要求每个局部决定逐级审批，不向上搬运所有分析过程。 |
| 返回与整合 | 子单元返回对外使用说明、业务结果与模型引用、材料／命题覆盖及缺口、依赖与未决项、实际应用和验证范围、本次变化。 | 父单元据此核对直接子单元组合和本层约束；完成数量或摘要不能代替实际依据。 |
| 问题升级 | 改变对外含义、共享定义或跨单元约束的问题，连同差异、影响和来源，交给能覆盖受影响范围的最低共同父级或已指定的共享维护方。 | 接收方组织整合与必要的业务澄清，不因协调职责获得业务确认权或额外读写权限。 |
| 下钻与接续 | 对外说明不足、出现冲突、约束影响或需要核对证据时，读取被指出的定义、命题和原始片段；新会话从本层目标、直接子单元返回和未决项继续。 | 若经常需要通读全部子单元细节，回 S1 检查切分和对外说明；必要的依据读取仍允许进行。 |

跨部分问题可以横向协作，但须定位整合责任和引用关系，不能在多个父单元各维护一份独立结论。父级语义收口按第 8.1 节检查覆盖与组合，实际交付再核对应用和独立验收；分层总览仅帮助定位这些内容。

## 6. 流程二：捕获完整命题，分开观察与解释

### 6.1 原子性按判断边界定义

业务命题是“在相关上下文中能够独立判断的一项陈述”。它可以包含多个实体、合取／析取条件、量词、例外或跨句引用；不等于一个句子或一个三元组。

例如，以下是示意材料，不是当前项目事实：

> 普通工单验收通过后可关闭；返修工单还须填写关闭原因。紧急处置可暂缓原因补录，但不能豁免验收。签收不代表验收。

捕获时分别识别普通关闭规则、返修附加限制、紧急例外的准确作用范围、签收与验收的区别，并保留它们的共同上下文。不能把紧急例外扩大为豁免全部条件，也不能把“签收不代表验收”删成无关说明。

命题内容保留有意义的主体、参与角色、行为／关系、适用范围、条件、否定、数量、时间、指标口径和例外。还须区分陈述性质与模态：定义、状态／已发生事件、规则、意图、计划、预测或建议，以及其中的许可、义务、禁止和可能性。关联谁作出陈述、依据何种材料；引用某人提出的建议不等于该建议已被业务采纳。

例如“经理可以批准退款”不等于“退款只能由经理批准”，“预计周五发货”不等于“周五已发货”，“系统必须保留记录”不证明系统已经执行。对“只有、全部、不得、从不”等表述保留适用总体和时间，不能从几个样本或未出现记录推导全称／否定结论。模态与业务有效时间分别保留，未来计划不会仅因到达日期而自动变为已发生事实。

缺少某个维度并不要求补值；保持未给出的部分。复杂逻辑保留可核对的自然语言和分组，不强制转成可执行规则 DSL。

### 6.2 两次不同目的的审阅

第一次关注材料表达了什么，允许开放术语、重叠表述和未解指代。第二次关注这些命题共同意味着什么，才决定概念身份、关系方向、共享定义和表达结构。

这两种关注可在一次有界分析中完成，也可随复杂度分开；不要求所有材料先抽完、固定两个 Agent 或两轮模型调用。对指代或上下文不完整的命题回读关联原文，不能用上层摘要补造缺失条件。

材料陈述、抽取解释、业务确认分开记录。明确获准作为业务依据的材料可按任务既有规则支持直接陈述，无需逐条请用户重新批准；确认记录标明实际依据和确认方式。模型自己提出的解释不能因为写入工作空间就变成业务确认。数据库主外键、CHECK、样本和 API 字段是相应技术结构的证据，不自动成为业务规则；外部业务行继续留在源系统。

## 7. 流程三：解释、身份对齐与粒度控制

### 7.1 按含义对齐

先从已有模型和工作空间检索相关定义，核对完整含义与周边引用。对开放表达写出必要的自然语言定义，再比较身份、角色、方向、范围、条件、时间和单位。

选择只有六类语义结果：复用同一含义、在既有含义上增加局部限制、建立不同含义并关联、提出共享含义修改、明确未知、保留冲突。不得仅按名称、连接度或向量相似度归并；没有合适候选时允许新建有依据的定义。

### 7.2 粒度的操作准则

| 提问 | 对表达的影响 |
| --- | --- |
| 差异是同一对象在连续生命周期中的状态、参与角色或上下文限制吗？ | 先核对身份连续性，优先表达状态／角色／局部规则；订单草稿与已批准、同一客户作为付款方与收货方，不因此成为不同实体。 |
| 能否找到一个业务情境，A 与 B 会导致不同答案、规则或结果？ | 若成立，应表达区别；例如签收成功且验收失败。此判断决定需要区分含义，不直接决定拆分身份或建立子类。 |
| 它是否有独立身份、独立事件的发生、参与关系或被其他规则单独引用的必要？ | 结合已有身份连续性决定对象、事件、角色或关系的表达；责任或所有者变化本身不证明对象身份改变。 |
| 拆开后是否破坏条件组合、量词作用域或事件参与关系？ | 用完整规则／关联结构保留组合作用，不机械展开为孤立边。 |
| 共性是否在多个真实用途中稳定成立，而且有材料依据？ | 才考虑共享抽象；字段相同或反复出现不构成分类依据。 |
| 继续细化是否增加范围内的业务区分能力或保真度？ | 若没有，停止细化；仍保留完整定义和必要限定内容。 |

规则、指标和复杂关系同样执行此判断。一个指标名称相同但时间窗、分母或排除项不同，必须保留口径区别；不因名称相同复用一个计算定义。

不强制从实例归纳类，也不从类定义虚构具名实例。模型可以表达概念、规则、行为和明确未知，而无需把每个命题都变成独立 RDF 节点。

### 7.3 业务澄清

只有缺失信息会改变当前业务结论时才提出澄清，说明一个具体区别情境、受影响的判断和已有依据。复用已确认答案。未回复不是确认，材料相互冲突时不自动按最新消息获胜。

发起前也检索尚未回答的同一判断。确认指向同一待定含义或共享规则、可由同一实际决定者回答时，保留一个未决项，各单元引用它并说明各自适用场景、受影响结论和返回步骤；可向同一决定者合并呈现相关问题。不同合同、业务范围或时点须核对是否确属该共享判断，不能只凭措辞合并。答复记录回到共同未决项，再逐个核对引用方的适用性；只回答一个场景时，仅解决该场景，其余引用继续未决。权限不同的引用方只取得各自获准内容。

提问不冻结无关工作。未知应缩到具体业务含义；“已知但尚未表达”“工具不支持”“尚未读取”分别作为表达或工作缺口，不改名为业务未知。

## 8. 流程四：局部闭合与全局整合

### 8.1 局部语义闭合

一个工作单元当前可收口，意味着：

1. 当前单元声明范围内的材料已审阅，每项有业务意义的命题均有第 5.2 节所述去向；范围外材料有实际范围依据，不能由 Agent 为收口自行排除。
2. 范围内已知含义及其身份、路径、条件、例外和结果由候选或复用模型完整承载；仍未表达的已知内容是收口缺口，不能因为标为低优先级而省略。
3. 对相邻单元所依赖的定义和条件、本层负责的整体规则已核对；未决连接及未知／冲突仅在当前交付范围明确允许保留时可随范围收口，其他未决项仍是缺口。
4. 正常、条件不满足、相关例外及有区分作用的临界情境能得到符合材料的解释；自查结论带有本次覆盖边界。

未审阅或无法读取的相关材料存在时，可以交付有价值的局部成果，但该单元的材料覆盖仍为不完整，不能记作范围闭合；下一步仍指向准确的审阅缺口。此要求不阻止开始或应用已安全确认的局部语义，也不要求每次局部推进前通读整个项目。

闭合不等于业务事实全部已知、模型已应用或独立验收已通过。没有材料的部分不能借“闭合”被排除。材料已经审阅但业务本身未给出答案时，保留的是业务未知；材料尚未审阅时，保留的是工作缺口。授权范围仍未处理时项目继续保留剩余工作。

父级收口递归检查直接子单元的覆盖与缺口、父级尚未分配的材料／命题、本层跨单元规则及获准保留的未知／冲突。子单元全部报告完成也不能替代这些检查；任何范围内已知未交付内容仍使对应范围不完整。实际交付还须绑定相容的模型内容与各自应用、读取和验收证据，不能把不同版本的局部通过相加为当前项目通过。

### 8.2 全局整合关注连接语义

局部推进后即检查相关连接，不等待所有单元结束：

- 上游“完成”能否满足下游“允许开始”的条件。
- 两个流程引用的主体是不是同一身份，或者只是同一个角色名称。
- 共享动作的必要条件、失败效果、单位和时间是否一致。
- 某项例外是本地限制还是修改了共享规则。
- 某个指标的输入、去重、空值和计算范围能否跨单元衔接。

父单元须从本层目标、合同／政策等原始材料及子单元对外结果中主动识别组合约束，不只等待子单元报告相邻连接问题。每项已识别的跨单元规则明确适用范围、整合责任、业务依据、参与单元及验证情境；组合检查由能覆盖其范围的最低共同父级组织，已有共享维护方继续维护规则含义与引用，相关子单元引用同一含义。父单元负责检查组合后的业务结论，子单元负责提供该规则所需的局部含义与结果。

例如安装、返修、配件补偿各自符合局部规则，但同一合同年度的三类合计仍须满足有材料依据的额度上限。整合方读取额度规则及三个单元对金额、计入时点、合同与期间的定义，检查合计；无需向三个建模上下文复制全项目规则。没有整体规则的来源不能凭常识新增限制，已有规则的归属也不能因不属于单个切片而遗漏。

组合规则明确哪些条件同时满足、哪些是备选路径、例外仅豁免哪个条件，以及同时适用规则的关系。优先、替代或豁免必须有业务依据；不能默认“特殊规则覆盖通用规则”或“新资料优先”。无法同时满足且材料未给出处理关系时，保留冲突并进入 Q。共享规则变化时，由维护方重审组合及其消费问题，参与单元分别核对自己的引用，不能只重查发生修改的局部规则。

如“安装完成”是否足以允许结算，应按材料核对验收、签收等额外条件。图上存在一条路径不等于这条业务链可成立。

遇到冲突先比较两个完整解释及适用上下文，再决定共享、局部化、区分或澄清。缺陷回到相应命题或决定修正，不通过增加同义节点或模糊摘要消除冲突。

### 8.3 持续推进与停止

下一项工作由实际剩余问题和依赖选择，优先解决影响多个单元的歧义、阻断关键业务链的缺口，以及能形成完整验证样例的单元。优先级由建模负责人作可解释判断，不要求算法评分或固定次数。

当继续拆解不能改变范围内的业务理解、已审阅材料有处置、跨单元连接有依据、剩余未知已明确且满足约定交付条件时停止细化。范围或授权改变才扩展目标；不能为了“更完美”无限补充外围知识。

## 9. 共享业务认知如何精确维护

### 9.1 修改的对象是明确判断

每次有实质新信息，指出：涉及哪个稳定语义身份／命题、当前判断、拟改变的部分、新依据、适用范围与时间、影响的使用者和未决问题。聊天可以解释决定，但共同状态从决定记录读取。

| 新信息性质 | 处理方法 |
| --- | --- |
| 重复支持 | 关联新增支撑；含义没有变化就复用已有判断和表达。 |
| 新增局部条件 | 修改该上下文的规则或用途，核对是否影响共享定义。 |
| 对旧解释的纠正 | 保留原判断和纠正依据；重审由旧解释推导的内容。 |
| 真实业务规则变化 | 记录实际生效范围与时间，区分历史仍成立的规则。 |
| 同时有效且相互冲突 | 保留冲突两方、影响与待确认项；不能自动选较新文本。 |
| 来源修订／撤回 | 检查其他支撑与独立确认；失去支撑标记待重审，撤回材料本身不证明业务事实为假。 |

业务生效时间只在材料或业务决定支持时填写。记录时间表示平台何时得知，不能代替业务时间。普通文字修正不制造业务规则变化；规则后来被纠正也不改写旧验收当时采用的依据。

### 9.2 共享维护与并行协作

共享定义有一个负责协调含义的维护方，其他单元提出明确差异。维护方不自动获得业务确认权或平台权限，也不要求一个专职 Agent。

跨单元整体规则按第 8.2 节指定整合责任并复用同一决定；变更通知包含对外含义和组合结论的变化，而非仅通知节点已修改。同一待确认判断按第 7.3 节共同维护未决项，答复与后续修订均检查各引用方的适用范围。

更新指明所基于的定义内容。另一项已确认变化使基线失效时，返回具体差异供重读和合并判断；不采用最后写入覆盖，不永久终止任务。不同单元的独立工作继续推进。

一次决定同时说明需要重审的引用，维护方与引用方分别给出保持、修改、未知或冲突结论。依赖遍历只是候选影响集；语义影响是否传递由含义判断，不能把图上可达的所有节点全部强制返工，也不能仅检查直接边就声称无间接影响。

### 9.3 增量进入同一方法

新任务先查看当前获准总览与实际相关模型，定位变化涉及的工作单元，再进入第 5—8 节的局部循环。不重新理解全部项目，不盲信旧摘要，也不把换 run 视为业务认知清零。

影响链为：材料／决定变化 → 命题与定义 → 使用它们的业务单元及关系 → 受影响验证 → 相关主题摘要。共享定义的跨主题使用同时进入影响集；没有完整依赖记录时主动检索并标注核对边界。

## 10. 分层总览作为共同认知入口

### 10.1 一份内容，多粒度阅读

总览在建模开始后即可逐步生成，既包括当前模型，也包括明确标识的候选、未处理范围和业务疑问。可以从项目进入业务领域／流程，再进入专题和具体定义；层数随内容调整，不要求固定四层。

主组织结构沿已确认的业务范围与解释建立，允许多父引用和跨主题连接。社区算法形成另一种可重建的发现视图，用来提示紧密主题与跨范围联系。发现视图不自动改写业务结构、Ontology 拓扑、共享身份或授权。

例如，“关闭工单”可以同时出现在安装、返修和结算视图中，引用相同的适用定义与不同局部规则。摘要中明确哪些内容共享、哪些条件只在某个上下文成立，不复制三份独立“当前定义”。

父层总览优先组织本层目标与约束、直接子单元的对外结果、覆盖缺口和升级问题，并提供向实际定义和原材料下钻的入口。它不拼接全部下层分析；摘要层级也不自动决定责任归属，责任以第 5.3 节的工作单元约定为准。

### 10.2 每层应呈现什么

| 内容 | 组织方式 |
| --- | --- |
| 业务主线 | 本主题解释什么，主要对象、行为、条件和结果如何连接。 |
| 当前认知 | 已确认判断；重要未知、冲突和适用范围。 |
| 表达与交付 | 已有模型表达、候选修改和待交付内容；应用及验收结论分别引用。 |
| 横向关联 | 共享定义、上下游条件、跨主题依赖与影响。 |
| 深入入口 | 可展开的子主题、具体定义、原始材料或工作记录，在当前读者获准范围内提供。 |
| 当前适用性 | 所依据的内容时点、覆盖范围及待刷新部分。 |

关键未知、冲突和决定结果的例外，必须以可展开条目传播到相关上层；条目过多时可分组分页，但不能因摘要篇幅截断而显示“没有问题”。重要性不能只用出现频次或图连接度决定。

### 10.3 如何生成，如何防止摘要逐层失真

每层输入包含：所覆盖成员的当前内容、可复用的下层摘要、关键未决条目、跨主题连接和相关限定条件。状态值及适用范围来自原记录，LLM 组织叙述；程序不能验证语义忠实度，仍需要对关键条件、结论和反例作内容核对。

上层摘要引用下层摘要用于压缩和导航，同时保留追到原定义或原记录的链。不能把一段无来源的“摘要的摘要”当作确认依据，也不能从摘要重新抽取出“新事实”后写回模型，形成自我证明循环。

摘要不声称完整替代细节。涉及业务修改、条件判断或精确回答时，Agent 必须沿入口读取相关实际内容；仅了解全局和定位工作时可以停留在摘要层。

### 10.4 谁能看到什么

- 用户视图：按用户获准业务和管理范围，组合语义、工作和允许展示的验收结论。
- 生产视图：获准材料、当前模型、公开问题、可见决定及工作状态，不包含隐藏题、答案和私有验收诊断。
- 消费者视图：以获准已应用模型为依据的业务导航；不将内部候选或待确认计划伪装为当前模型内容。
- 独立验收视图：基准验收直接使用冻结模型、获准依据和题目。若要验收“摘要辅助消费”，单列模式，摘要只由冻结获准模型生成，并验证引用；不混入生产工作记录或隐藏答案。

授权范围在摘要生成前确定。不能先对更大范围生成摘要，再尝试删掉敏感名词；权限变化影响已有摘要的可读资格，旧摘要不得越权复用。摘要必须说明可见范围的限制，不能把不可见解释为不存在。

### 10.5 更新与成本

材料、定义、范围、决定、应用、验收或权限发生相关变化时，标记受影响主题及其上层、横向关联摘要需要更新。按需读取或有价值的阶段完成时刷新，合并连续小改动；无变化复用当前结果，不为每个工具调用重生成全树。

语义内容、工作进度与验收状态引用不同截止点，不能只用一个模型修订号冒充全部一致。生成期间输入变化时，新结果可保留为历史，不能标为当前。仅修改工作状态时可复用未变的业务内容摘要。

跨主题结构明显变化时重算相关发现结构，再更新成员与祖先摘要；覆盖检查包括孤立资源和未进入聚类的内容。内部依赖无法确定时，宁可扩大必要刷新范围或披露过期，也不声称已精确增量。

运行成本须记录，收益用实际阅读、续接和判断效果检验。层级更深、摘要更多不自动代表更好，展示可选择最能帮助当前问题的层次。

## 11. 模型表达、应用与验证

### 11.1 表达与执行

Modeling 明确业务含义及变更意图，确定性程序补足执行字段并应用。沿用现有编译器和可恢复应用方法，不恢复独立模型 dry-run、Protocol 翻译审批或专用规则引擎作为默认门。

所需业务语义必须出现在实际模型可读取的定义和关系中，不能只停留在工作空间或摘要。原文支撑、决策历史与模型表达分别定位；表达合同不足时保留已知缺口并修正合同，不把已知内容假称未知。

应用边界要保护共享语义一致性。可在一个原子应用中完成的相关变更成组应用；跨现有原子边界时，采用含义明确的兼容新增及安全引用迁移，或暂缓无法保持一致的变更组。不得假设 PostgreSQL 与 RDF、多个 Ontology 或多个 Batch 天然构成全局事务。

成功回执证明确定性应用结果，相关业务自查通过真实受治理读取核对含义。无需每次成功写入后重复全量读回；在完整业务单元形成、关键共享含义变化及最终验收时进行有价值的读取。

### 11.2 四个不同的质量问题

| 检查 | 要发现什么 | 不能替代什么 |
| --- | --- | --- |
| 材料覆盖 | 相关段落／声明是否被审阅，范围内有业务意义的命题是否遗漏、是否都有交付去向，未审阅及已知未表达范围是否公开。 | 已提取命题自己检查不出未捕获信息；材料已读或已有处置记录不等于完整交付。 |
| 解释与表达保真 | 条件、否定、量词、例外、时间、身份和口径是否被正确理解并表达。 | 解析成功、字段齐全不能证明语义正确。 |
| 跨单元一致性 | 定义复用、业务状态衔接、条件组合和共享影响是否成立。 | 存在图路径或局部自查通过不能证明全链成立。 |
| 实际消费与独立验收 | 在获准模型中能否得到完整且正确的业务答案。 | 生产者自述、内部工作笔记、摘要或结构检查不能代替。 |

命题到表达的核对至少双向进行：范围内每项有业务意义的命题在哪里表达、由何处覆盖或为何未交付；模型中的各项业务断言依据什么。重复支持可以共用对应，明确未知须核对其性质及允许保留范围。另从原始材料审阅范围查漏，防止双向核对的两端共同遗漏同一内容。核对强度可以按风险安排，但不能用“只核对关键项”代替全范围去向。

规则验证包括正常成立、必要条件不满足、适用例外、容易混淆的概念及跨单元组合。涉及金额、数量、比例、时间窗或生效时点时，选择能区分解释的边界值本身及必要的两侧情境；核对包含／不包含边界、起算点、单位和适用版本。例如明确“含第 30 天”的规则须检查第 30 天，不能只用第 10 天和第 40 天验证。原文边界不明时先记录歧义并进入 Q，不能由测试预期代替业务决定。

验证情境按真实规则与风险选择，不要求所有规则套用固定矩阵，也不恢复可执行规则引擎。自查问题可以随理解深化而补充，独立冻结题目及其裁决标准不能由生产方为求通过而修改。

### 11.3 独立验收与修复

独立题目与评分依据先由独立侧根据获准业务范围和原始依据准备，正式生产前完成既有要求的题集冻结，生产侧只接收公开投影。过程中可新增公开自查情境；真实业务范围或依据变化时，由独立侧明确维护对应题集及变化记录，不按候选模型的答案倒改评分标准。

原冻结题集与报告保持不可改写；后续区分两种情况：

| 情况 | 独立侧的处理 | 结论边界 |
| --- | --- | --- |
| 业务范围或原始依据变化 | 按获准变化准备新版本题集与判定依据，记录变化范围；用于新一轮生产的基准仍在该轮生产前冻结。 | 旧报告仅覆盖原绑定范围及依据，不自动适用于新业务含义。 |
| 范围与依据不变，但发现原题集遗漏情境 | 独立侧通过原始材料及覆盖复核定位遗漏命题，记录补充原因和依据，形成追加题集版本并在执行补充验证前冻结。不得因候选答案而调整业务判定标准、删掉失败题或选择更容易通过的替代题。 | 原题集和原报告保留；追加报告单列新增验证范围与结果，不把新增题伪装成原来已验收。 |

追加验证仍绑定确切的题集版本、模型、读取条件、依据、范围和时点。原冻结模型可用且读取条件适用时，可对同一目标补充验证；若模型或条件已变，报告绑定新目标，旧结果不能直接并入新版本结论。发现覆盖遗漏后，当前完整性结论标明待补充的范围；补充发现失败则如实形成当前未满足结论，历史报告保留原样，不继续用旧 PASS 掩盖缺口。补充覆盖本身不启动生产修模或新增资源授权。

正式验收再绑定实际模型、允许依据、题集和读取条件；已有报告只在其绑定仍适用时用于当前结论。生产不在验收冻结目标上继续修改。

大型业务的独立验收按获准业务范围有界分工：局部评价核对所属单元的实际模型与原始依据，父级评价核对覆盖缺口、对外定义及跨单元整体规则，需要时下钻相关证据。父级不能仅汇总子级分数宣称全项目通过，也不默认由一个评价 Agent 通读全部切片。整条评价链保持生产独立性，原题与追加题的隐藏内容、答案和私有诊断均不流回生产。

验收发现问题后，按获准公开程度反馈缺口，回到原始材料、解释、模型表达或检索的准确失败层。隐藏题正文、答案和私有理由不进入生产工作空间；如需要真实业务澄清，通过另有依据的业务渠道提出。修复形成新的实际目标后另行验收，旧报告不覆盖。

内容分析中使用捕获、解释、表达、查询等定位；最终失败分类仍沿 modeling-quality、platform-contract、collaboration/routing、runtime/infrastructure。前者帮助定位语义损失，后者避免把平台问题当作模型质量失败。

## 12. 职责与运行组织

方法中的职责包括业务确认、范围与整合、语义分析／表达、确定性执行、独立评价，以及用户沟通。职责可以由少量 Agent 承担，也可以在复杂业务下按工作单元并行；独立评价与生产保持隔离。

单一 Modeling Agent 可以在一个单元内完成捕获、解释、建模和自查。复杂业务的并行单元通过稳定定义、命题及决定协作；不按每一种视角或每一步方法固定设置 Agent。

协调责任按第 5.3 节递归分配：每层负责本层目标、直接子单元衔接及本层约束，局部问题在所属单元解决，对外含义和跨层影响才升级。程序负责有明确合同的等待、执行、投影和恢复。会话结束后从本层记录、子单元对外结果、未决项及实际应用继续，不要求重载全项目细节。可修正的格式、缺字段、摘要过期或协作问题不成为 run 永久死亡条件。

分层总览帮助定位下一项工作，但不自动派单或扩大授权。决定使用哪份资料、写入哪个模型、启动哪次修模以及消耗预算，仍在同一获准任务边界内；换工作单元、Agent 或 run 不重置资源授权。

## 13. 贯穿示例：工单关闭规则的理解与维护

以下均为设计示意，用于暴露方法差异，不写入真实模型。

| 环节 | 处理结果 |
| --- | --- |
| 目标 | 理解普通工单与返修工单何时允许关闭，以及关闭是否足以触发结算。 |
| 双向分解 | 形成关闭判断、验收、返修附加要求、结算条件等关联单元；材料中的紧急例外必须有归属。 |
| 命题捕获 | 保留验收必要性、返修原因要求、紧急仅豁免补录时点、签收不代表验收。 |
| 粒度判断 | 用“签收成功但验收失败”区分两个事件；返修要求先作为局部规则，不能直接修改所有工单。 |
| 共享整合 | 关闭与结算分别保留条件；缺少“关闭足以结算”的依据就明确未知，不因图上相邻而建立因果。 |
| 表达与读取 | 模型中能读到准确条件及未知，工作笔记里存在不算已经表达。 |
| 总览 | 项目层提示“关闭条件已有表达，关闭与结算的充分关系待确认”；返修专题展开原因要求和紧急例外。 |
| 新信息 | “11 月起普通工单也须关闭原因”先核对来源和适用时间，判断是政策变化还是对旧解释的纠正。 |
| 影响维护 | 重审普通关闭规则及相关消费问题；返修既有要求未变化部分复用，更新涉及主题及上层摘要。 |
| 独立检验 | 验证条件不满足时不会答成可关闭，紧急例外不扩散到验收，未知结算条件不会被补造。 |

| R4.2-002：介绍、一句话进度、CQ 与验收结果 | 目标扩展为分层业务总览；用户继续能看懂范围、成果和未决内容，技术字段留在展开的依据层。 | [概览页面](../../../frontend/src/pages/OverviewPage.tsx)。 |
| R4.4-001：工作卡、协作请求及历史 | 用作工作活动记录并引用业务工作单元；工作卡不再独立重述完整共享含义。 | [现行需求](../../requirements/requirements-v4.4.md#r4-4-001)。 |
| R4.3-030：当前 Delivery 降耗优先 | 本轮目标设计依最新用户要求不受实现 effort 限制；运行成本仍如实测量，现有任务预算不变。 | [现行需求](../../requirements/requirements-v4.3.md#r4-3-030)。 |
| 独立语义验收与权限隔离 | 保留；目标明确分层评价和独立追加遗漏覆盖，原冻结基准与报告不改写；增加摘要辅助消费的独立评价模式，不能用它代替模型直接消费基准。 | [验收方法](../../../modeling_team/skills/acceptance/SKILL.md)、[受治理访问](../../../backend/app/services/semantic_access.py)。 |

迁移按内容连续性组织：先识别现有模型、候选、地图和决定的真实来源；能明确对应的内容导入工作空间，不能追溯的标为已有模型／依据待核对，不要求为历史对象伪造命题。新工作按新方法进行，旧 run 和原验收证据保持。地图或旧摘要在交接前可供读取，主写入口切换后只生成派生视图，避免长期双写。

数据库、Agent runtime 和外部框架选择不由本方法论预设。现有 FastAPI/MCP、PostgreSQL/RDF 和原子执行边界可继续承担职责；任何替换都应解决已明确的内容或一致性问题。无需先更换整个运行框架才能验证方法。

## 15. 实质决策表

以下均为按本轮设计授权采用的推荐方案，除标明沿用者外，不冒称用户逐项确认。

| 编号 | 决策 | 取舍与理由 |
| --- | --- | --- |
| D1 | 以持续语义工作空间和业务工作单元组织流程，各层承担有界的父子整合责任。 | 内容与决定独立于 Agent 会话，支持局部推进和跨轮接续；不以固定角色链作架构中心，也不要求上层通读全部细节。 |
| D2 | 业务目标向下分解与材料命题向上补充双向进行，范围内每项业务命题都有去向。 | 避免只围绕已知 CQ 建模、按文档切块误定边界，或以不关键为由省略已捕获知识。 |
| D3 | 捕获完整命题与确定语义表达分开思考，但不固定调用次数。 | 保留限定条件，避免增加无意义阶段交接。 |
| D4 | 以区分性情境、身份、上下文和引用需求决定粒度。 | 能说明为什么拆、为什么合，不靠固定节点数或相似度阈值。 |
| D5 | 语义解释、业务决定、目标表达、实际应用和验收各有依据。 | 避免多份当前真相和一个状态冒充全部结果。 |
| D6 | 共享更新先判断重复、限制、纠正、业务变化或冲突。 | 保护局部用途与历史含义，源撤回先检查剩余支撑。 |
| D7 | 局部闭合与跨单元整合交替，对外含义和整体规则有明确维护责任，按真实影响重审。 | 既避免全局前置等待，也避免把各切片通过误当作组合结论正确；无依据的优先关系保留冲突。 |
| D8 | 分层总览是持续派生认知层；业务组织与社区发现分工。 | 同时支持整体理解和细节读取，保留关键未知与横向关系。 |
| D9 | 摘要按授权范围生成、随相关变化失效，不作为语义自证。 | 摘要压缩不能泄露隔离内容、遗忘关键例外或形成循环依据。 |
| D10 | 明确扩展最小命题支撑及变化维护；保留直接应用、未知表达和独立验收，遗漏情境由独立侧追加验证。 | 为保真和持续维护提供必要输入；保留原题集与原报告，不倒改标准，不恢复旧证据、规则引擎或 dry-run 流水线。 |

不宣称存在无权衡的“完美架构”。本提案选择可解释的业务分解、明确的权威边界与可修正的循环，并用下面的反例检查其质量。不存在需要替用户确定的客户业务事实；具体建模任务中的未知仍由获准业务材料和负责人解决。

## 16. 验证设计与效果边界

本轮仅完成设计与审阅。下列验证未执行，不记作功能或真实语义 PASS。

| 编号 | 反例／场景 | 预期与证据 |
| --- | --- | --- |
| A1 | 材料含当前 CQ 未涉及的范围内例外；80 页政策仅阅读了 10 页 | 未读材料阻止“范围已闭合”的结论但不阻止局部推进；完整审阅后例外进入正确单元及表达或明确缺口，不被问题集排除。 |
| A2 | 规则含否定、合取条件、例外及跨句指代 | 捕获、解释、模型和读取保持作用域；正常／失败／例外情境能区分。 |
| A3 | 签收与验收同现，订单有多个状态，同一客户同时担任两个角色 | 区分性情境支持正确表达；不虚构实例、不误归一，也不把状态／角色差异误拆成不同实体。 |
| A4 | 两个业务单元都使用“客户”或“完成” | 比较身份与条件，复用或区分有依据；图连通不冒充业务可衔接。 |
| A5 | 已确认但未表达、已表达未知、已应用未验收同时存在 | 各状态在工作空间、总览及消费结果中保持区别，任何一个不会自动提升其他维度。 |
| A6 | 两个 Agent 基于不同旧定义提出共享修改 | 第二次修改识别基线变化；受影响引用重审，无静默覆盖，无关工作可继续。 |
| A7 | 新资料只新增支持、增加局部限制或改变生效日期 | 三种变化导致不同处置；不会每次重建全模型或把局部规则变成全局规则。 |
| A8 | 唯一来源撤回、多个来源中一个撤回、历史政策仍有效 | 检查剩余支撑和业务确认；不将删除文档直接等同删除真实事实。 |
| A9 | 高频主线正常，低频例外决定能否操作 | 上层总览保留关键例外／待决入口；按频次摘要不会吞掉它。 |
| A10 | 一个共享定义被多个主题使用，有孤立资源 | 修改使所有相关主题和上层待刷新；未进社区的内容仍可定位，不被遗漏。 |
| A11 | 摘要生成期间模型／工作决定变化，或读者权限变化 | 旧结果保留正确时点和资格；不作为当前、完整或越权内容返回。 |
| A12 | 摘要出现推断、候选尚未应用、隐藏诊断存在 | 推断不写回为事实，消费者不误读候选，生产摘要不包含隐藏内容。 |
| A13 | Agent 会话退出后由新 Agent 接续 | 不读完整聊天即可定位业务范围、当前判断、实际应用、剩余工作及必要原材料；不重复已确认应用。 |
| A14 | 外部客户端修改模型，或多 Batch 修改中途失败 | 以实际模型和回执恢复状态；不靠工作空间意图或摘要声称全部成功。 |
| A15 | 模型正确但召回不完整，或运行／平台失败 | 分层定位后沿原失败分类报告，不能推导模型错误或通过。 |
| A16 | 某范围自查通过，独立验收失败或仅覆盖部分 | 保留各自范围、输入与结论；不把局部通过写成项目完成。 |
| A17 | 许可与义务、计划与已发生事件、建议与正式政策并存 | 命题、模型和摘要保留陈述性质、模态、陈述主体及适用范围；不因到达预计日期或出现在建议文件中而升级成事实。 |
| A18 | 四个部分各有 30 个切片，父层或局部会话中断后接续 | 每层按目标、直接子单元对外结果、缺口和本层约束推进；下钻有具体原因，生产和独立评价均不把全部细节默认集中给一个 Agent。 |
| A19 | 安装、返修、配件补偿分别合规，但合计超过合同年度额度，随后共享口径变化 | 整合责任方从原始规则发现并验证三方组合，参与方核对引用；合取／析取、例外和优先关系均有依据，变化触发受影响组合重审。 |
| A20 | 材料全部已读，低频例外已捕获但未表达；全部子单元报完成仍有父级未分配命题 | 每项命题可追到实际表达、复用、重复支持、明确未知或未交付状态；已知未表达和未分配范围仍使对应范围不完整。 |
| A21 | 十个切片等待同一年度口径答复，答复只适用于其中一类合同 | 复用同一未决项和受影响引用；限定适用的答复只解决匹配范围，其余继续未决，无关工作继续。 |
| A22 | 时间、金额、比例或生效时点恰落边界；原文另有含混边界 | 按真实规则验证边界本身及必要两侧；含混时先澄清，不用测试答案定义业务规则。 |
| A23 | 原材料与范围未变，独立侧发现冻结题集遗漏情境 | 原题集及报告保留，追加覆盖有原材料依据并在执行前冻结；报告绑定确切模型和读取条件，新增未通过或待验证范围不能被旧 PASS 遮盖。 |

实际方法验证应选用包含至少两个相互依赖业务单元、共享定义、条件／例外和一次资料变化的完整场景。先验证模型直接消费，再独立评价分层总览辅助理解；比较范围、材料与难度一致，保留非盲或盲测条件。衡量：遗漏与无依据断言、粒度错误、跨单元衔接、未知保留、接续准确率、修改影响遗漏，以及全过程耗时和用量；不以图大小、摘要字数或缓存率代替效果。

设计审阅记录：[独立审阅与文档检查](../records/2026-10-26-ontoweave-modeling-methodology-design-review.md)。

## 17. 各步骤的输入、输出、注意事项与跳转

本节将前文方法展开为一个工作单元的操作流程，并按第 5.3 节递归用于父子单元。父单元在 S1 划分并交接有界目标，在 S5／S7 核对直接子单元组合和本层约束；子单元返回对外结果与缺口，不逐级重放全部分析。S0—S9 是导航编号，Q、R 是按需进入的处理分支，C1、C2 是持续维护的共同状态与总览。编号不代表固定 Agent 数量、强制模型调用次数或平台新增的硬状态机；下文输出可以是同一工作空间中的条目与引用，无需每步生成独立文件。

正常新增路径：S0 → S1 → S2 → S3 → S4 → S5 → S6 → S7 → S8。其中 S1—S5 可以在不同工作单元之间交错推进；S8 的最终结论绑定声明的完整验收范围。已有成果仍有效时复用它们，进入本次变化实际影响的步骤。S9 负责变化分流；C1、C2 在有相关变化时更新。摘要暂时不可用不阻止安全建模或模型直接消费验收；若本轮交付明确包含当前总览或摘要辅助消费，相关内容未完成仍须作为未交付项，不能宣称全目标完成。

### 17.2 S0：明确目标、范围与已有基线

| 项目 | 说明 |
| --- | --- |
| 谁负责 | 用户／业务负责人提供目标和实质授权；Delivery／协调者整理范围与现有记录；独立侧准备评价依据。 |
| 输入 | 用户要解决的业务问题；获准材料及版本；可读写模型范围；已有模型、工作空间和有效结果；当前任务授权与资源边界。首次建模时已有模型可为空。 |
| 处理 | 区分从零建模、局部补充和含义修订；明确本轮业务范围、排除项、期望消费方式；盘点材料及未读区域；核对既有实际应用和重要未决项。按既有要求在正式生产前完成独立题集准备与冻结，生产只取得公开投影；后续同范围遗漏覆盖由独立侧按第 11.3 节追加，不改写原冻结基准。 |
| 输出 | 建模目标说明；范围与材料目录；本轮已有模型基线和可复用成果引用；成功判据及公开 CQ；独立侧保管的冻结题集与评价依据。 |
| 可进入下一步的条件 | 能说明本轮允许处理什么、依据什么、期望交付什么；不要求已经解决所有业务未知、通读全部材料或生成完整地图。 |
| 注意 | 当前模型未记录某内容不证明业务不存在；历史验收结果须核对适用范围。目标、权限、预算和业务确认相互独立。 |
| 下一步 | 新项目／需要重新划分范围 → S1；增量任务已有稳定范围 → S9；目标或授权不明 → Q，受影响操作等待；发现旧写入结果不明 → R，先对账再决定后续写入。 |

### 17.3 S1：双向拆解业务，形成工作单元

| 项目 | 说明 |
| --- | --- |
| 谁负责 | 本层业务分析／整合职责维护直接子单元结构及本层约束；子单元负责内部拆解与推进，不要求新增专职角色。 |
| 输入 | S0 的目标、公开 CQ、材料目录；已有业务结构和模型概览；S2 发现但尚无归属的命题。 |
| 处理 | 从目标拆到端到端场景、事件与决策点；识别对象、角色、规则、指标及必要映射；同时把材料中的业务主题挂回结构。选择能形成完整判断的局部单元，向子单元交接目标、材料、相关定义及上层约束；明确本层负责的组合规则和问题升级位置。 |
| 输出 | 工作单元目标／范围、父子整合责任及关联材料；含稳定身份、输入与结果、条件、范围、例外和未知的对外使用说明；共享定义、跨单元连接、未分配／待分析范围及下一批可推进单元。说明随局部分析完善并引用实际定义。 |
| 可进入下一步的条件 | 选中单元有明确边界、输入和解释目标，能开始审阅相关材料；其他单元可以仍待分析。 |
| 注意 | 文档章节、数据库表、Ontology 和 Agent 不是天然业务边界。触发／结果等内容按业务性质提供，不为静态概念任务虚构流程。无法合理分开的条件共同分析。 |
| 下一步 | 选定单元 → S2；单元过大或边界割裂关键判断 → 在 S1 调整；发现范围外的新需求 → S0，不能自行扩大授权；业务范围有实质歧义 → Q。 |

### 17.4 S2：读取材料并捕获完整业务命题

| 项目 | 说明 |
| --- | --- |
| 谁负责 | 建模职责；工具保留已获准材料定位和实际读取范围。 |
| 输入 | 一个工作单元及其获准原始材料；必要的上下文和交叉引用；已有命题；材料的新旧差异。 |
| 处理 | 按材料单元读取，识别完整陈述；保留条件、例外、否定、量词、时间、单位、口径、陈述主体和许可／义务等模态。遇到跨句指代回读上下文；识别重复但保留支撑关联。同步登记材料已读、未读、不可读或有依据的范围外状态。 |
| 输出 | 可定位的业务命题集；每条命题的原材料关联、限定条件、归属单元或未分配状态；未解指代、缺失上下文或相互冲突的原始表述；材料覆盖记录及待分析去向。输出尚不意味着这些陈述都被业务确认。 |
| 可进入下一步的条件 | 某组命题已具备足够上下文，可以进行有界解释；不必等待整个项目材料全部抽取完毕。单元材料未读完时仍保留覆盖缺口。 |
| 注意 | 原子命题不是最短三元组。预计发货不等于已发货，许可不等于义务，源表样本不等于业务总体规则。不可读与未读属于工作缺口，不能伪装成已确认的业务未知。 |
| 下一步 | 上下文充分的命题 → S3；上下文可从现有材料补齐 → 留在 S2 补读；发现遗漏单元 → S1；材料缺失或真实业务歧义需外部输入 → Q。不受影响的命题继续推进。 |

### 17.5 S3：解释业务含义，判断身份与粒度

| 项目 | 说明 |
| --- | --- |
| 谁负责 | 建模职责作语义判断；必要时由业务负责人澄清；共享定义维护方参与相关判断。 |
| 输入 | S2 命题及原始上下文；已确认业务决定；检索得到并核对完整内容的既有定义、关系和使用场景；当前材料与模型基线。 |
| 处理 | 区分材料陈述与推导解释；比较同义、异义、局部限制及适用时间。先判断身份连续性，再用业务情境辨别需要表达的差异。确定对象、事件、角色、规则、关系和指标含义；为重要选择说明采用／排除理由。 |
| 输出 | 明确的语义定义或修订建议；复用／新增／局部限制／共享修改决定；对应命题与依据；具体未知或冲突及共同未决项引用；正常、条件失败、例外、易混概念，以及涉及数值／时间时有区分作用的临界验证情境。 |
| 可进入下一步的条件 | 已有足够依据决定当前要表达的含义，或者能够准确表达获准保留的未知。仍需业务确认的推测不能作为事实断言推进。 |
| 注意 | 定义状态不由命名、相似度或模型置信分数决定。草稿订单与已批准订单、同一人的两个角色，通常仍保留同一身份。直接获准材料支持的陈述不要求逐条重复询问用户。 |
| 下一步 | 需要新增或修改表达 → S4；已有定义完全满足且当前有效 → S5 核对使用场景后复用；发现原文理解不全 → S2；关键含义未决 → Q。可准确表达的未知与其他已确认部分可以继续 S4。 |

### 17.10 S8：独立验收并形成交付结论

| 项目 | 说明 |
| --- | --- |
| 谁负责 | 独立 Consumer／Judge 或指定评价职责按单元有界分工；父级评价负责覆盖和整体语义，不以子级分数汇总代替组合判断。Delivery 负责合法交接和向用户说明结果。 |

| 处理 | 在只读条件下通过实际模型作答并独立对照业务依据判定；局部评价聚焦所属范围，父级核对对外定义、覆盖缺口和跨单元整体规则，按需下钻。发现同范围遗漏时按第 11.3 节追加验证并单列结果。基准与摘要辅助消费分别标明对象；生产不能修改冻结目标。 |

| 可结束本轮的条件 | 满足当前声明交付范围的全部完成门，或如实交付部分／未完成结论并说明剩余项；后者不记作目标已完成。已正确表达并获准保留的业务未知仍作为未知保留。 |
| 注意 | 不从局部 PASS 推导项目 PASS。验收者不修模，不把隐藏题、答案或私有理由改写成生产提示。修复不能覆盖原模型绑定和旧报告。 |
| 下一步 | 当前目标完成 → 保留结果，结束该目标的生产推进；有新的获准变化 → S9；需修复且已有授权 → 由 S9 根据获准可见问题分流到 S2／S3／S4／S5／S7，形成新目标内容后重新 S8；授权不足 → 等待原授权方，不能自行新增轮次或预算。 |

| 下一步 | 用户／Agent 通过总览定位，进入相应 S1—S9 并按需读取原内容；发现潜在语义问题先提问并回 S3／S5 核对，不能直接改模型；刷新失败则明确过期或直接读取原记录，主流程继续按其真实条件推进。 |

### 17.14 Q：业务澄清与等待分支

输入是一项会改变业务结论的具体歧义，携带获准上下文、不同解释导致的实际差异、受影响单元和原步骤。先利用已有材料与确认记录，并检查同一判断是否已有未决项。确认属于同一待定含义／共享规则且决定者相同时，追加本单元场景引用及影响，不重复提问；不同范围不因措辞相似而强行合并。仍需外部决定时，按实际决定者适度合并，通过已有沟通入口询问。

输出为共同未决项上的可定位确认、补充材料、明确未决或范围决定，保留答复主体、依据和适用范围；逐个检查引用单元，局部答复只解决匹配部分。未答复不选择默认含义。只暂停依赖该答案的断言或修改，其他工作继续。

收到新材料回 S2；收到能解决含义的业务决定回 S3；范围／授权变更回 S0；已确认解释只缺表达时回原 S4／S5。若无法获得答案，按原任务允许的未知表达继续 S4，或保留明确未完成部分；不能用记录一个未知代替本可完成的材料审阅。

### 17.15 R：写入结果不确定时的对账分支

输入为原提交身份、实际请求、Batch／Attempt 和已知回执。先读取既有写入与恢复记录，确认实际效果，不能因为超时新建同义内容或换身份重试。

确认已应用的部分更新 C1，并进入 S7；确认无效果且符合重试合同的部分，沿原身份恢复 S6；多批次中已成功的部分保留，只处理尚未完成的部分。仍无法确认时暂停相关写入，保留现场并经获准技术路径解决，独立只读工作可以继续。

### 17.16 每次交接应能回答的六个问题

1. 当前处理的是哪个业务工作单元，以及哪一步？
2. 本轮依据哪些具体材料、已有定义和当前内容？
3. 新增或改变了哪项业务判断／模型表达？
4. 哪些内容已实际应用或验证，哪些仍是候选、未知或未完成？
5. 当前需要什么输入，影响哪些其他工作？
6. 下一步进入哪个 S 步骤、Q 或 R，原因是什么？

这些信息复用工作空间条目与引用，不要求重复贴原文或所有历史。简单任务可一次完成多步并给出一份交接；复杂任务可在任意有意义的边界交接。

示意交接：当前单元为“返修工单关闭”，位于 S3；原材料支持“验收必须通过、原因允许紧急暂缓补录”，已复用验收定义，决定将暂缓作为返修局部例外。尚未应用，无需业务确认。下一步进入 S4，输出含完整条件和例外的候选；与结算的充分关系仍未知，送 S5 核对该连接，不能把它当成关闭规则本身未知。

### 17.17 流程说明核对场景

| 场景 | 预期路径与检查 |
| --- | --- |
| 从零理解一条完整业务链 | S0 → S1 → S2 → S3 → S4 → S5 → S6 → S7 → S8；C1／C2随实际内容变化更新。 |
| 所有含义与当前模型均可复用 | S0／S9 → 有界核对 → S3 → S5 → S7；需要当前目标独立结论时进入 S8，不制造写入。 |
| 80 页材料只读了 10 页 | 已理解的局部可以推进；S7 不能因此认定完整范围已具备最终验收条件，回 S2 处理剩余材料。 |
| 关闭原因要求存在业务歧义 | S3 → Q；无关单元继续；答复后回 S2／S3，再推进受影响内容。 |
| 实际写入超时但可能成功 | S6 → R；已应用则 S7，明确无效果才恢复 S6；不复制节点或重复成功应用。 |
| 模型正确但自然语言检索不完整 | S7 定位检索层并修正，随后重查 S7；不回 S4 随意修改业务含义。 |
| 独立验收发现公开可定位的表达缺陷 | S8 → S9 → S4 → S5 → S6 → S7 → 新绑定的 S8；旧报告保留。 |
| 来源撤回但还有其他独立支撑 | S9 检查支撑 → C1／C2，必要时 S3 重审；不能自动删除真实模型事实。 |
| 用户仅查看总览，或摘要暂时过期 | C2 返回适用的摘要／过期说明和原记录入口；不因此启动建模、写入或新授权。 |

## 18. 大型业务的递归推进与覆盖推演

本节是针对 H1—H3、M2／M3／M4 的设计桌面推演，不是真实运行或独立验收证据。假设一个获准售后项目分为 A 合同权益、B 安装交付、C 返修、D 配件补偿，每部分有 30 个切片。这个数量用于检验责任与上下文边界，不规定业务必须这样分，也不代表需要 125 个 Agent 或 Ontology。

示意材料规定：同一年度内，安装、返修和配件补偿共用 10 万元额度；核验本次申请时，计入该年度既有占用和本次拟批准金额，合计不得超过上限。年度的起算口径尚待业务确认。项目整合方负责跨 B／C／D 的组合约束，A 维护合同与年度定义；各部分负责自己的 30 个切片及内部组合。

| 推进环节 | 谁需要读取什么 | 操作与可交接输出 |
| --- | --- | --- |
| 根单元分解 | 项目整合方读取整体目标、获准材料目录、合同额度条款及 A—D 的范围说明。 | 给四个直接子单元分派目标、材料和适用约束；保留未分配材料／命题。此时不预读 120 个切片细节。 |
| 部分内推进 | C 的整合方读取本部分目标、直接切片的范围／依赖及当前缺口；选中 C07 后，由局部建模者读取其原始材料、所需定义和相关上层约束。 | C07 运行 S2—S7；局部原因字段问题在 C07 解决，影响年度占用含义的问题交给 C 整合方及额度维护责任方。其他部分继续。 |
| 合并待确认判断 | B04、C07、D09 及其他切片读取同一年度口径未决项，只补充自身适用场景及影响。 | 由合适的业务负责人答复一次；若仅确认甲类合同自生效日起按周年划分合同年度，则解决匹配引用，其他合同口径仍未决，不能扩散答案。 |
| 子单元返回 | C 整合方取得 C07 的对外定义、占用口径、覆盖去向、缺口、真实模型／应用引用及自查范围。 | 核对本部分内部组合，再把 C 的对外结果和未决影响返回根单元；不拼接全部局部分析。未完成或候选内容保留原状态。 |
| 跨三方核对 | 年度口径已确认后，根整合方读取额度原文、A 的年度定义，以及 B／C／D 的合同、期间、金额口径和本次情境。 | 同一合同年度安装已占 3 万、返修已占 4 万、拟批准补偿 5 万，合计 12 万；即使各单元局部条件成立，整体额度条件仍不满足。结果回到有关单元及共享规则记录。 |
| 规则组合与临界验证 | 整合方读取同一额度定义及有依据的例外，而非假定例外能豁免全部约束。 | 按“不超过 10 万元”检查合计 10 万本身及必要两侧；额度条件满足不代替其他局部条件。若材料只写“额度以内”且边界有歧义，先 Q，不靠测试定含义。 |
| 共享规则后来变化 | 原始材料或业务决定明确上限、计入口径或有效时间变化；维护方读取变化内容及已知 B／C／D 引用。 | 经 S9 选择重入步骤，重审受影响组合、引用与验证；未变局部定义复用，旧适用范围和原报告保留，不让全部切片无差别重做。 |
| 跨会话续接 | 新的根协调会话读取项目目标、四个部分的对外返回、本层额度规则与未决项；新的 C07 会话读取自身记录和所需引用。 | 分别恢复本层未完成判断及准确 S 步骤。因对外说明不足、具体冲突、约束影响或证据核对而下钻对应内容，不默认重载 120 个切片。 |
| 逐层收口 | C 整合方核对 30 个切片覆盖及本层未分配范围；根整合方核对四部分返回、根级未分配范围和跨部分规则。 | 若 C29 仍有已捕获但未表达的低频例外，C 不能报完整；即便 120 个切片均报完成，根级遗漏的合同命题或未验证组合仍阻止项目完整交付。获准保留的业务未知单列，不冒充已知答案。 |
| 独立评价 | 独立局部评价读取所属冻结模型和获准原始依据；独立父级评价读取适用局部报告、对外实际定义、全范围缺口及额度等整体规则。 | 对相容的目标绑定形成分层结论并验证组合；父级不只加总通过数量，也不由一个评价上下文默认承载所有细节。隐藏题与私有诊断仍与生产隔离。 |

若独立侧后来发现原题集未检验“合计恰好 10 万元”，而范围及材料未变，则按第 11.3 节保留原题集与报告，以原“不超过”条款形成追加题集，执行前冻结。追加报告说明新增边界覆盖及其模型／读取条件；同目标可单列补测，目标已变化则绑定新目标，不能把旧结果直接加总为新目标全通过。补测尚未执行或失败时，当前结论如实保留待验证或未满足范围。

上述推演只核对本轮六项修订能否给出责任、所需内容和下一步，不引入长尾推进安排、同输入重复分析一致性验证、固定角色数量或新的实现机制。
