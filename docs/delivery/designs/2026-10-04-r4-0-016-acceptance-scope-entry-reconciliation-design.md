# R4.0-016 建模启动时的完整验收范围与执行入口核对设计

## 1. 设计状态、依据与边界

本文是 [R4.0-016](../../requirements/requirements-v4.0.md#r40-016-建模启动时的完整验收范围与执行入口核对) 的详细设计，复用 R4.0-009 的验收目标、R4.0-014 的进度交接、R4.0-015 的公开反馈边界以及 R3.0-011／R3.0-015 的题池冻结与检查点恢复合同。本文解决“获准范围、题集可见性和实际入口在末端才对账”的流程缺口；不建设新的覆盖管理平台、不固定题数、不增加 semantic start 门槛。

设计 PASS 只代表入口与范围记录方案可审阅。未执行的题集、专项能力和真实语义质量仍须保留 PARTIAL／PENDING；启动台账不能替代 Examiner、Judge 或真实业务资料证据。

## 2. 当前问题与目标

本次真实运行中，隐藏题主要覆盖切片，公开题还承担全景、跨切片和静态映射消费。隐藏集通过后才发现公开集没有独立执行，原入口也只选择隐藏题，之后才补公开选择和缓存隔离。根因不是题数不足，而是启动时没有把覆盖维度、可见性、题集、入口和收口证据放在同一个可定位记录中。

目标是让宿主在启动或接续时用最小检查回答：

- 当前授权究竟要覆盖哪些维度和专项；
- 哪些公开／隐藏题集负责这些维度，实际身份和版本是什么；
- 每个题集通过什么命令／入口执行，预期报告和题目分母是什么；
- 什么时候可以把某段标为已执行、部分、通过或待办；
- 哪些缺口是未授权、未冻结、入口未就绪或尚未执行，而不是默认为不适用。

## 3. 核心模型：范围、可见性和执行入口分开

### 3.1 覆盖维度

宿主按当前适用需求和授权记录目标维度，例如全景、切片、跨切片、治理、映射、完整推理或外部执行。维度是业务／能力范围，不等于一个 Ontology、一个题目或一个 Agent。

### 3.2 题集与可见性

题集记录实际冻结后的 `question_id`、content version／digest、公开／隐藏 visibility、对应维度、是否已曝光和是否仍具备盲测资格。公开／隐藏是生产可见性属性，不强制映射到全景／切片；同一维度可以有公开和隐藏问题。公开投影可在获准范围内指导生产；隐藏题从生产首次输入起隔离。

题目或答案一旦进入生产修模，后续结果只按非盲回归记录；不能在台账中把曝光题重新计入隐藏盲测。题目冻结前只记录目标覆盖和预期入口，冻结后再绑定实际题集；不为启动预先补造全量题。

### 3.3 执行入口与完成依据

每个范围项记录实际入口，例如 `cq-acceptance`、`checkpoint resume --mode acceptance` 或已有专项验证命令，以及 visibility／question selection、输出报告路径、预期 attempt／denominator、完成所需的状态和报告证据。角色存在、命令可解析、公开题已提供给生产或另一题集 PASS 都不能算对应项已执行。

## 4. 启动台账与对账内容

不先设计新数据库或通用 Schema。优先在现有 host run record／handoff／checkpoint resume 记录中增加以下可读区块；若当前记录没有位置，再使用当前 run `evidence/` 下的 append-only 文本／JSON artifact，并沿已有 digest、报告和事件引用方式保存。

### 4.1 启动前最小记录

1. **目标与授权**：需求版本／条目、授权范围、semantic start 或 acceptance-only resume、获准材料、当前代码／Task／Profile、生产或验收模式。
2. **范围矩阵**：每个覆盖维度、题集或专项、是否已冻结／已曝光、当前状态（planned／ready／running／partial／pass／pending）和明确 out-of-scope。
3. **入口绑定**：入口命令／参数、visibility、选择器、预期报告目录、attempt、题目分母或专项完成证据；不写死 11／10 等本次题量。
4. **安全前置**：如果是生产，记录现有写入／回读和授权状态；如果是验收续跑，记录 handoff／checkpoint、源 run、冻结摘要和只读绑定。只做安全启动所需检查。
5. **未覆盖项**：列出尚未冻结、入口未就绪、未授权、尚未执行或不能由当前阶段证明的项目，并标明下一动作。

### 4.2 执行和收口记录

执行中按题集／专项追加开始时间、实际选择、报告／attempt 路径、有效分母、已执行／有效裁决／通过／待复核／未完成数、第一失败层和状态绑定。收口时逐项对账“目标—入口—实际报告—完成证据”，将未执行和缺口保留为 pending／partial。

完整 PASS 仍由现有 `batch_report_is_full_pass`、冻结／model binding、无 skipped／drift／未完成和相应专项证据决定；台账只负责让分母和缺项可见，不放宽任何通过门。

### 4.3 恢复与状态变化

检查点验收-only 恢复读取原 run 的 scope／identity／冻结摘要和当前题集；新输出 run 只记录新的 attempt／report／收口，不覆盖原件。模型或题集状态变化时，将受影响项标为 superseded／需重验，禁止拼接前后报告。未知写入、source_active、scope drift 等沿既有类型化拒绝与恢复合同处理。

## 5. 执行流程

1. 读取当前适用需求、run record、Task／Profile 和用户授权；列出本次目标维度及不在范围内的能力。
2. 复核题池当前状态。题池未冻结时只登记预期覆盖；冻结后读取公开／隐藏 projection／pool 的实际身份、版本和 digest，检查可见性隔离。
3. 为每个范围项绑定现有执行入口和报告／attempt 位置，确认入口的 visibility／selector 真正会选择该题集；不以默认参数猜测。
4. 做最小安全检查后立即进入获准真实 semantic start 或现有 acceptance-only resume。遵守授权后 20 分钟内开始首次真实建模，不因对账台账前置全面审计、mock run 或全套验收。
5. 运行和收口时对照台账，分别记录 public／hidden、各维度和专项结果。题集漏执行时直接留下待办，不缩小分母、不把未授权能力记为不适用。
6. 交接时把 scope ledger、报告路径、模型／冻结绑定和未覆盖项交给下一责任者；正式独立验收沿既有交接和收口流程执行。

## 6. 现有实现触点与最小变更

| 触点 | 计划核对／变更 | 边界 |
| --- | --- | --- |
| `skills/modeling-dev-loop/references/team-runbook.md` | 增加启动范围、题集／visibility／入口、收口对账示例 | 不把台账变为全量预检或固定题量硬门 |
| `modeling_team/__main__.py` | 核对 `--question-visibility`、`cq-acceptance` 和 checkpoint resume 的 selector／报告分母；仅在入口无法选择已登记题集时修薄包装 | 不改变 Judge、冻结或 semantic start 计数 |
| `modeling_team/host_ops.py`、checkpoint／handoff 记录 | 绑定 source run、attempt、报告目录和 read-only 状态；仅在现有记录缺少可定位字段时增加 host-owned 记录 | 不写平台业务资源，不修改原 checkpoint／旧报告 |
| `modeling_team/competency_questions.py`、`runner.py` | 复用 pool／projection digest 和 visibility 校验 | 不添加平台域的题集管理或固定维度字段 |

优先文档和宿主记录改动；实施前必须证明实际入口缺口。若已有命令和记录足够，只补 runbook 与交付记录，不引入第二套状态机。

## 7. 验收标准与反例

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| A1 | 获准范围含公开和隐藏题集，启动／接续任务 | 可定位每个维度对应题集、visibility、入口、报告和完成依据；局部通过不吞掉其余待办 |
| A2 | 隐藏题已通过，公开题未执行 | 隐藏结果保持原义；公开仍 pending；沿同源只读入口实际执行公开集，不复用隐藏 PASS |
| A3 | 全景题需多个切片完成 | 获批公开投影可提前指导切片／关联建模；内容完成后对相应题集独立验证；隐藏内容不进入生产 |
| A4 | 入口缺口不会造成不安全写入 | 记录缺口并准备既有路径，仍及时开始真实建模；缺口未闭合不宣称对应验收完成 |
| A5 | 分段通过但外部执行、完整推理或其他能力未覆盖 | 台账和交付报告保留具体缺口；不据局部 CQ 或静态映射通过标记全 v4、L2 或 L3 PASS |

特别反例包括：默认入口只取 hidden；公开题已由生产使用却仍计入 blind；题集实际未运行但报告被复制；按本次 10／11 固定分母；角色存在或命令启动成功被当作语义完成；前后状态报告被拼接。

## 8. 设计审阅、验证分层与结论边界

独立设计审阅检查维度／visibility 正交性、隐藏隔离、启动及时性、分母保留、恢复只读边界、旧件不可变和是否引入新的硬门。开发阶段验证 entry selector、projection／pool digest、报告绑定和台账往返；独立功能验收用独立题集与故障 fixture 检查遗漏分母和错误入口；后续获准真实运行才提供 A1—A5 的真实语义与范围证据。

机械文档检查、开发回归、独立验收和真实语义结果必须在记录中分开。本文没有启动真实 run，不消耗建模额度；实现或功能 PASS 不等于全部需求范围或模型质量 PASS。
