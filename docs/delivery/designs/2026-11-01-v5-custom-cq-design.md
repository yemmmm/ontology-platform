# v5 项目自定义 CQ 设计

日期：2026-11-01。归属：[R5.0-010](../../requirements/requirements-v5.0.md#r5-0-010)。
状态：推荐设计稿与示例种子已形成；尚未实施、独立评审或取得本功能的真实运行证据。

## 1. 用户看到的能力

用户在项目总览的“能力问题”区域点击“添加问题”，写下“每个凭证授权了多少模型、成功
调用了多少次？”即可保存。用户可以补充“没有调用的凭证也要保留”等业务口径，不必
填写答案、SQL、Ontology 或切片。用户可以在后续建模时选用这些问题，并查看逐题验证
结果及缺少的资料。保存在题库里不触发收费调用或模型修改。

最小表单：必填“问题”；可展开“预期口径／参考答案”“资料依据”“业务主题”，均可空。
列表支持编辑、停用、选择用于后续任务。用户提交即表示将题干作为目标；系统自动起草
的业务答案仍是待核对内容，不能冒充用户确认。资料中已有清晰口径的部分无需重复访谈，
新增实质含义和冲突沿已有 HITL／审核通道处理。

当前产品的“CQ 通过”容易同时被理解为语义忠实、能够生成 SQL、SQL 已运行，展示必须
拆开。例如 Q8 应显示“未满足：没有拒绝／回放事件来源；忠实性检查识别出该缺口；SQL
未生成／未执行”，不能只显示一个绿色通过。

## 2. 当前实现与最小复用

本次以提交 `1e9776b` 为代码基线，只读取相关合同；未修改产品代码。
具体核对路径及证据见[现状记录](../../research/2026-11-01-custom-cq-design-baseline.md)。

| 已有入口 | 当前能力 | 本功能所需增量 |
| --- | --- | --- |
| `backend/app/api/interview.py`、`schemas.py` | 项目 CQ 列表、创建、更新、状态、验证接口 | 项目级自定义题允许不绑定 Ontology，公开输入与私有判分资料分离 |
| `CompetencyQuestionModel`、`services/interview.py` | 持久记录、来源、排序、停用；编辑使旧结果失效 | 自定义题的可选标准、内容版本及执行引用；保持旧题兼容 |
| `run_question_validation` | 实体／关系／SPARQL 计数 | 保留；不能用这些计数宣称问数语义或 SQL 验证通过 |
| `frontend/src/pages/OverviewPage.tsx` | 展示旧 run 冻结题与结果 | 增加项目题库编辑入口，区分活跃题与某次运行题集 |
| v5 `TaskBinding.prepare`、`SourceRevisions` | 固定材料 manifest、摘要与自然边界增量接续 | 把选定公开 CQ 作为独立类型的目标材料；题目变化沿现有机制交接 |
| v5 `evaluate`、`validate_report` | 独立只读上下文、冻结摘要、实际修订与完整编号检查 | 固定 CQ ID 对照、四态逐题结论和 SQL 支撑状态，不另建运行框架 |

取舍：只把问题写进 task 文件不足以跨任务维护；独立建设另一套题库和执行器又会重复
现有平台与 v5。采用扩展平台现有 CQ 记录，并向 v5 导出固定版本投影的方案。
“复用”不等于已打通：当前 v5 不会自动消费平台 CQ，旧页面也不是现成的 v5 题库入口。

## 3. 三个主要设计问题

### 3.1 什么阶段可以添加

| 阶段 | 用户动作与生效方式 |
| --- | --- |
| 项目准备／首次建模前 | 随时添加；未有模型和答案也能保存，选定版本进入下一次建模目标 |
| 访谈／建模中 | 立即保存；排队到原生 turn 完成后交付，Agent 判断是否补材料、重审或继续 |
| 验证准备 | 选题、明确标准、冻结版本；缺依据问题保留待复核，不阻断其他题取证 |
| 验证已开始 | 可以继续维护题库；本批仍使用原快照，新题或新标准进入后续追加批次 |
| 已交付／已有模型 | 可先做获准的只读检查；需要修模时按原任务／预算授权另行推进 |

保存与执行是两件事。添加问题不自动扩大业务范围，不中断在途执行、不复活 stopped
run，也不自动追加预算。若题目只是检查现有模型，允许 `no_change` 后照常读取与验证。

### 3.2 是否需要用户提供答案

不需要。分开保存“问题目标”“参考答案”“判定标准／依据”“实际结果”。

- 只有题干：先进入建模目标与澄清队列；Agent 从获准材料整理必要概念、口径和未知。
- 材料充分：形成可核对答案要点与来源，沿现有审核使用；不要求用户自己写 SQL。
- 材料不足／相互冲突：指出需要补哪条业务事实；该题可继续检索取证，但没有就绪标准
  就不能给确定语义通过结论。不得根据待验模型自身补造参考答案。
- 用户提供答案：记录作者、适用范围和依据；与原材料冲突时进入待复核，不能把用户
  随手给出的样例数值变成所有时点的业务真值。

问数题的标准通常是“成功新调用粒度、历史实际扣额、零调用保留、避免连接放大”，
不是固定返回某个数字。数值答案只有绑定业务数据快照、时间范围、时区及必要参数后
才可比对。参数未知时分别列出，不能用现在的样本反向补足模型语义。

### 3.3 是否分公共 CQ／切片 CQ

用户无需选择切片。统一是项目业务问题，可选业务主题标签。

内部保留 `coverage.unit_ids` 多值引用及理由，一题可以跨多个工作单元；未分派时由
父级保留，拆分后补充对应。父级负责检查跨单元的组合规则；子级不能只验证局部后就
宣布整题通过。工作树变化不改变问题身份，不把一个跨单元问题复制成多条独立题。

“公共”需要消除歧义：若指项目共同问题，就是项目整体覆盖；若指生产可见，就是
公开／隐藏维度。两者独立。第一版自定义题默认供建模和回归验证使用，不新增可见性
选择控件；隐藏题仍放在既有私有冻结包。第一版不建设跨项目通用题库。

## 4. 内容与执行合同

### 4.1 活跃问题与确定版本

复用平台 CQ 表，推荐最小增量为允许 `ontology_id=null`、增加 `content_revision` 及
独立 JSON 定义字段 `cq_definition`；后者不复用已有 SPARQL `query_definition`。
旧记录默认沿原验证方式，自定义题使用 `cq_definition.kind=custom`。

自定义定义至少包含目标用途、可选参考答案／判定要点、固定来源引用及其就绪状态、
可选业务主题；内部覆盖引用是可修订的工作分派，不是新增 Ontology 或授权范围。
正文、标准、来源或用途发生实质变化时增加内容版本。更新携带当前版本，冲突返回
最新版本和可重试反馈；不使用最后写入静默覆盖。

种子导入使用定义中的可选 `external_id`，在同一 Project 内唯一；同一外部键的创建在
事务内处理，重复导入返回现有身份，内容有差异则交用户合并。普通手工添加没有外部键
也能成立；题干相同不自动证明是同一道题。

活跃表只维护当前内容；每次执行保留完整使用快照，不为未执行的每次草稿保存建立
通用版本库。题集至少保存 `cq_id + content_revision + content_digest`、题干、用途、
就绪标准、依据引用、可见性／已曝光状态、选题与停用状态，以及 `index→cq_id` 对照。
运行另外绑定实际目标模型版本、来源版本与执行时间／参数。旧快照与旧报告保持不变。

平台通用读取只返回获准公开内容。隐藏题和私有判分资料不进入这个活跃表的公开字段、
生产 manifest 或通用检索；私有包沿已有权限边界保存。示例种子中的九题均已公开，
其答案要点也属于公开回归口径，不承诺隐藏测试。

### 4.2 进入建模和验证

1. Host 根据用户选择读取项目 CQ，固定内容版本，导出目标材料及 `index→cq_id` 对照。
2. 生产包只含可见题干和明确发布的业务口径；材料类型标明是目标，不是业务事实。
   Agent 仍须读业务来源，形成／更新内部覆盖与未决项。
3. 本期复用完整 manifest 及 `source-revise`；有新题时生成下一完整投影，不让 Agent
   在运行中读取持续变化的项目题库。使用已有来源变化重审路径处理旧候选。
4. 验证前从选定版本生成 `frozen-questions` 与现有 freeze ID／摘要／题数；缺标准的
   题保留在覆盖清单并标记待复核，不能通过排除它们得到全选题通过。
5. 模型交接后复用 `evaluate` 及真实治理读取，在报告中保留每题稳定身份和精确模型
   版本。单题不满足继续其他题，平台错误只拒绝当前不安全操作并允许纠正后重试。
6. 题库变化产生新投影／批次。公开自查或反馈可以指导获准修模；私有判分依据不得
   通过反馈泄漏，反馈后曝光的题只再提供回归证据。

当前 v5 独立评价是一名只读评价者读取来源／冻结标准／模型；独立性指未参与生产。
它不等同于旧 v3 Examiner 与 Judge 分离的答案盲测，第一版不为自定义题重建那套角色。
不改 R5.0-006 已有隐藏题隔离要求，也不声称上述已知九题能测未见问题泛化。

### 4.3 判定与旧协议兼容

旧 v5 case 只有 `passed: bool`，不能完整表达出题问题或未运行。自定义 CQ 批次增加
逐题 `outcome`：`pass`、`model-recall-insufficient`、`question-answer-review`、
`platform-runtime-incomplete`；原 `passed` 继续作为兼容投影，不能单凭 false 归因模型。
旧报告按旧合同读取，不给缺失的新字段编造值。缺少就绪标准的题必须保持待复核；
整批只有所有选定题有有效通过结论才能 PASS，含待复核／未完成时为 PARTIAL，明确
模型／召回不满足保留 REVISE。已确认模型不满足与未完成并存时总状态为 REVISE，
同时披露未完成覆盖；不能用总状态遮盖逐题状态和数量。

另外记录 `answerability`（supported／conditional／unsupported／unverified）、
`sql_readiness`（同四态）、`sql_execution`（pass／fail／not_run／blocked）与证据引用。
用户目标未实现与“正确识别出不足”分别说明。没有适用 SQL 或未获准执行时记录
not_run；SQL 成功并不自动证明业务口径正确，结果比对须单独有证据。

来源根本没有所问事件、或问题超出当前获准能力时，记录来源能力缺口并进入题目待复核，
不能直接判为建模质量失败。来源明确足够、但实际模型或召回缺少必要信息时，才使用
模型／召回不满足。来源缺口是业务限制说明，不是新增第五种运行失败分类。
对于 Q8／Q9 这类统计目标，诚实指出缺口不能把 `answerability=unsupported` 改成支持，
也不能据此给“所需统计能力已实现”的结论。

自定义 CQ 不走旧 `/validate` 的计数路径；无 Ontology 的题也不能调用该路径。
既有计数题继续原合同。最终汇总保留所有选定题的分母及待复核／未执行数量，旧批次
不能因后来停用题目变成通过。

## 5. 固定上述九题

仓库种子：[competency-questions.json](../../../examples/llm-access-lab/competency-questions.json)。
这是待导入的数据设计，当前产品／v5 尚不直接识别该文件；没有把它冒称为已入库 CQ。
以 `llm-access.analytics.Q1`—`Q9` 作为稳定外部键，首次导入关联实际平台 ID；重复导入
同一版本复用原记录，已有用户编辑时返回差异，不能覆盖。换任务保留同一项目问题身份。

| 题 | 长期判定重点 | 上次 revision 4 的观察，仅作历史对照 |
| --- | --- | --- |
| Q1 | 成功新调用粒度；历史实际扣额；零调用模型与平均值空值 | 支持 |
| Q2 | 授权与调用分别预聚合；含零调用凭证；余额独立 | 支持；直接连接发生重复计数 |
| Q3 | 凭证状态、授权、模型状态、余额四条件及具体编码 | 条件支持，缺凭证 enabled 编码 |
| Q4 | 正余额但小于当前费用；启用与授权条件完整 | 条件支持，同上 |
| Q5 | 历史扣额与当前配置分开，不重算历史 | 支持 |
| Q6 | 请求标识在凭证内去重，检查跨凭证重复 | 支持 |
| Q7 | 明确 UTC 边界与物理时间表示 | 条件支持，缺时间语义 |
| Q8 | 拒绝／回放的事件来源及“今天”的日期、时区 | 不支持，缺事件映射；不能返回零 |
| Q9 | 调价历史事件、前后值、操作时间与操作者来源 | 不支持，不能由成功记录还原 |

Q8 的“今天”保留原题，执行时须显式解析日期和时区；没有确认时不能静默按服务器时区
处理。Q7 的固定日期保持为回归案例，后续可复制为带时间参数的新题，不改旧版本题意。
历史六条 SQL 及返回数字不作为题库答案注入生产；相关[实际取证报告](../../research/2026-11-01-demo-model-to-sql-readiness.md)
保留独立历史身份。将来模型补齐缺口后，应按同一能力目标重新判定，不能要求它继续“不支持”。

## 6. 决策与取舍

下列为本轮推荐设计，未经独立评审；判断把握均明确超过 85%，是设计判断而非测试概率。
用户明确要求的九题长期复用及无需感知切片，按本次指令落实到设计；未把推荐写成逐项获批。

| 决策 | 推荐方案与理由 | 来源／状态 |
| --- | --- | --- |
| D1 添加阶段 | 全阶段可保存；固定执行版本、自然回合边界生效，兼顾追加与可核对结果 | 推荐；继承 v5 输入边界 |
| D2 答案 | 用户可不提供；Agent 据来源整理标准，缺依据待复核，避免题目门槛和自证 | 推荐；继承源忠实度 |
| D3 归属 | 项目统一入口、可选业务主题；内部多工作单元覆盖，不要求切片选择 | 用户期望＋推荐实现 |
| D4 可见性 | 自定义题默认建模与回归；隐藏题沿原私有包，已曝光不再算隐藏 | 推荐；继承独立验收边界 |
| D5 版本 | 活跃记录可改，执行快照不可改；新题进新批，停用保留旧分母 | 推荐；继承冻结与接续合同 |
| D6 结果 | 就绪、可回答性、SQL 条件和实际执行分开；缺失数据不等于零 | 推荐；依据九题实测缺口 |
| D7 集成 | 扩展现有平台 CQ 与 v5 投影／冻结，不另建题库或 SQL 执行器 | 推荐；现有代码能复用 |
| D8 Demo 基线 | 保存九题和稳定标准；历史缺口／数字不固化成永远正确的答案 | 用户要求＋推荐实现 |

## 7. 实施与验证交接

最小实施顺序：平台记录及迁移／来源与版本校验 → 项目总览编辑和选题 → v5 固定投影、
输入变化和冻结包接线 → 稳定 CQ ID 与逐题结果投影。接口行为变化须同步现有接口文档。
实现前对实际修改符号进行影响分析，不因本设计做全面重建索引或重写旧 CQ 流程。

至少验证以下行为，当前均为计划，未执行：

- 无 Ontology／答案创建；中文及多行内容往返；来源和版本错误可修复；旧计数题不回归。
- 同题跨任务复用、九题重复导入、用户已改题的冲突保护；项目权限和私有包边界。
- 忙碌时追加只入队，实际后续回合消费；旧候选按新目标核对；停止状态不被保存操作撤销。
- 跨单元 Q2 由父级整合，一题只统计一次；冻结后编辑／停用不改原报告和分母。
- 无标准返回待复核，检索无结果与模型确认缺失分开，Q8／Q9 不制造事件或零值。
- Q3／Q4 条件不足和 Q7 时间未知保留；补充获准来源后的新版本能够更新判定而不覆写旧结果。

开发阶段运行后端相关用例、v5 受影响合同及 UI 构建／交互测试；后端／前端代码变更
按仓库规则测试后重启并查健康。真实有界验证再用独立只读上下文与确切模型版本取证，
不以开发自测代替该证据。本设计不授权新建模预算、启动或恢复已封口运行。
