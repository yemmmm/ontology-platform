## 共享记忆

第一版是当前建模任务内的共享业务记录，复用现有 PostgreSQL 对象和版本仓储。

| 内容 | 最小表达 |
| --- | --- |
| 身份 | entry_id，由 Agent 选择稳定名称；存储自动绑定当前 task |
| 分类 | kind，建议 judgment／decision／open_item，不做严格分类枚举 |
| 正文 | title、body；条件、例外、否定和未决内容由 Agent 自行表达 |
| 依据 | source_refs，原文或实际模型等已有引用，不重复复制整个项目 |
| 维护信息 | 程序记录最后作者、更新时间和 revision，旧版本保留 |

提供 `write_memory`、`read_memory`、`search_memory`。已知身份直接读；未知位置按文字及
可选 kind 查找有界预览，再读完整记录。更新沿现有 expected_revision 比较；冲突返回
实际内容供 Agent 合并，不额外强制重读、审批或接单步骤。相同正文不重复生成版本。

记忆是有来源的业务理解，不是已应用模型或新的人工确认。实际应用和独立检查继续读取
真实模型与获准原文。生产成员共享本 task 记录，独立验收不挂载记忆写入工具；首版不做
跨项目共享、跨 run 项目迁移、向量库、自动抽取或完整摘要系统。

已有[共享记忆 P0](../test-docs/2026-10-28-v5-shared-memory-validation.md)的读写／冲突／
新会话消费证据复用；本批补正式入口接线及未知位置查找。

## 检查点快照

由 Host CLI 按需保存命名快照，文件保存在原 run 的 snapshots 目录。保存时记录：

- Task／run 绑定和保存时源码摘要；LangGraph checkpoint 身份、当前值及下一节点。
- 业务记录和版本的冻结正文，包括共享记忆、工作卡、问题及队列；原执行保留引用。
- 实际模型上下文／版本及对应工作记录引用。读取不可用时明确保留读取错误与原引用。

提供 `snapshot-save`、`snapshot-list`、`snapshot-show`、`snapshot-diff`。名称不作为
文件路径，实际文件用程序生成的 ID；保存不覆盖旧快照。对比显示对象增删／版本与字段
变化、流程和模型版本变化。此能力不调用模型、不要求 Agent 停稳，也不新增运行硬门。

快照是带各自版本的观察记录，不声称 PostgreSQL、LangGraph 和 RDF 的全局事务；
当前保存和查看／对比，不回滚当前任务或复制已应用模型。旧平台数据 capture／fork
已有[专门设计](2026-09-18-r3-0-017-checkpoint-data-fork-design.md)与接口，若后续需要
保存完整平台数据／分叉重跑，应复用那条路径，不在本批重建恢复框架。

## 验证

先在已提交通信代码上复跑冷启动，保留无宿主修补的结果；再启动共享记忆最小任务：
A 读原文并保存决定，B 通过查询找到未知身份记录、读取并修订，换新执行后 A 读取当前
版本继续实际应用与治理自查。中途按自然回合暂停、重建 CLI 并接续；保存前后快照并
核对旧正文不变、差异可见及实际应用不重复，最后做独立公开工程检查。

按本次 v5 研发 `usage_only` 授权保存原始用量，不将普通金额控制或完整 P2 调度前置。
本批工程与实际采用分开记录，不用记忆条数、快照数量或已有 P0 PASS 代替新入口实证。
