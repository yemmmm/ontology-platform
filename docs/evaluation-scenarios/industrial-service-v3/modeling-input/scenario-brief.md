# 工业设备售后服务运营（建模输入摘要）

一家工业设备制造商为客户现场提供售后服务。业务资料涉及服务区域、客户、现场、设备型号、安装资产、
服务合同、SLA 目标、故障事件、工单、工程师、延迟记录、备件、仓库、库存、申请和发运。

本资料用于一次完整场景的业务访谈和关系型语义建模。后续建模应把场景拆成相互依赖的逻辑切片，
保留项目级共享视图，但不要根据表数量预先决定一个还是多个 Ontology。Ontology 只保存确认后的业务
语义、关系、指标和到数据库表/列/连接的映射；数据库中的业务行仍由 PostgreSQL 保存。

输入的样例行是帮助发现结构的有限证据，不代表完整业务真相。请先询问并记录以下尚未确认的内容：

- 合同、资产覆盖和暂停状态的生效边界；
- 严重度、工单状态、故障码和库存/发运状态的正式含义；
- 响应、到场、恢复、解决的计时起点、时区、空值和分母口径；
- 延迟原因的确认责任、原因重叠规则和未知原因处理；
- 重复故障窗口、一次修复和重新打开/再次分派的定义；
- 成本语义的可见角色，以及语义可见性和实际数据库数据权限的边界。

该摘要不包含固定查询答案；请把不确定内容标为待访谈，而不是从列名或样例分布推断为业务规则。
