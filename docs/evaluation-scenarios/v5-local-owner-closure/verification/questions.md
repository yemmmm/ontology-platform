# 原生生产开始前冻结：原单元闭环

这是公开有界参考任务，不是客户盲测。来源沿复用的组合场景和署名年度补充；实际模型必须真实治理读取，生产笔记与候选不能补成缺失模型事实。

1. 最终模型是否忠实表达三类金额含义、同合同／已确认年度共享合计及包含边界、甲乙不同年度、父级正式完成与低频许可和真实未知？不得造实例、审批标准或各类独立额度，不要求固定 Class／Ontology 数。
2. 初次实际应用后，是否由建模 Agent 声明需要的原责任单元读回，而由既有程序安排执行；费用／组合中间单元按其声明的直接子级检查结果完成本层自查，再交根级整体判断？证明绑定实际模型，不是把提案改名完成。
3. 依赖检查是否有界：原单元检查自己的实际含义，中间层保留三类组合，根级保留父级未分配命题与整体条件；不能只加子级 ready 数代替整体结论，也不从责任层级制造业务实体。
4. 受控外部反例出现后，是否由原责任单元实际读回发现 revise，并沿原单元及祖先重入；Host 仅发一次整体重查请求，没有指定叶子 check-unit／reopen 或代写语义修订？初次格式纠正可保留，不伪装未知执行。
5. 修订是否复用真实资源身份，保留无关兄弟的有效含义和代次；最终原责任检查、中间层与根级自查有相容的实际目标和读取引用？新模型通过不覆盖原故障与检查记录。
6. 最终判断是否来自实际治理模型、获准原文和署名补充；自查、应用、工作状态与独立验收分开，过程缺口保留，不把 Host 控制的故障 fixture 或生产 ready 当成独立语义通过？
